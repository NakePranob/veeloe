# สิ่งที่ต้องลองด้วยมือ

ไฟล์นี้จดสิ่งที่ agent ลองเองไม่ได้ ตอนนี้ยังไม่มีโค้ดของกุญแจ ทุกข้อด้านล่างจึงเริ่มลองได้หลังทำขั้นที่ระบุเสร็จแล้วเท่านั้น

repo นี้เป็น public เมื่อรายงานผล ให้ระบุแค่เครื่อง รุ่น OS ข้อที่ลอง และผลที่ได้ และอย่าใส่ข้อมูลส่วนตัวหรือความลับ

## 1. iPhone จริง: Face ID

**ลองได้เมื่อ:** หน้าสร้างกุญแจและหน้าล็อกเสร็จ

**เหตุผล:** ตามเอกสารของ Expo, Simulator ไม่บังคับ biometric

**ต้องเตรียม:** iPhone ที่เปิด Developer Mode และบัญชี Apple สำหรับเซ็นแอปใน Xcode แล้วรันใน `controller/`:

```bash
bunx expo run:ios --device
```

ลองตามลำดับนี้ เพราะข้อ 1.6 ทำให้กุญแจใช้ไม่ได้

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 1.1 | เปิดแอปครั้งแรก | หน้าสร้างกุญแจ และยังไม่ถาม Face ID จนกว่าจะกด |
| 1.2 | กดสร้างกุญแจ | iOS ถาม Face ID หนึ่งครั้ง แล้วเข้าหน้าแรก |
| 1.3 | ปิดแอปแล้วเปิดใหม่ และกดยกเลิก Face ID | อยู่ที่หน้าล็อก เข้าไม่ได้ และกดลองใหม่ได้ |
| 1.4 | ทิ้งแอปไว้หน้าจอเกิน 5 นาทีโดยไม่แตะ ต้องปิด Auto-Lock ก่อน | กลับไปหน้าล็อก |
| 1.5 | ส่งแอปไปพื้นหลังเกิน 5 นาทีแล้วกลับมา | เห็นหน้าล็อกก่อน ไม่เห็นเนื้อหาแวบขึ้นมา |
| 1.6 | เพิ่ม Alternate Appearance ใน Face ID แล้วปลดล็อก | หน้าที่บอกว่ากุญแจเดิมใช้ไม่ได้ และไม่ใช่หน้าสร้างกุญแจตามปกติ |
| 1.7 | ใช้เครื่องที่ไม่ได้ตั้ง Face ID แล้วกดสร้างกุญแจ | แอปไม่สร้างกุญแจ และบอกให้ตั้ง biometric หรือใช้เว็บ |

**ข้อควรระวัง:**
- ข้อ 1.6 เปลี่ยน Face ID ของเครื่องจริง แอปอื่นที่ผูกกับ Face ID เช่นแอปธนาคาร อาจขอให้ login ใหม่ และ Alternate Appearance ถอดออกทีละอย่างไม่ได้ ต้อง Reset Face ID ทั้งหมด ถ้ามีเครื่องสำรองให้ใช้เครื่องนั้น
- ข้อ 1.7 ถ้าไม่มีเครื่องสำรอง ให้ข้ามได้ แต่ต้องรายงานว่าข้าม

## 2. Mac จริง: passkey บนเว็บ

**ลองได้เมื่อ:** vault บนเว็บเสร็จ

**เหตุผล:** agent จำลอง authenticator ได้ แต่สแกน Touch ID จริงไม่ได้

รันใน `controller/`:

```bash
bunx expo start --web
```

ลองใน Safari และ Chrome

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 2.1 | กดสร้างกุญแจ | เบราว์เซอร์ถาม Touch ID หรือรหัสเครื่อง แล้วเข้าหน้าแรก |
| 2.2 | reload แล้วกดปลดล็อก | ถามยืนยันตัวหลังกดปุ่มเท่านั้น แล้วเข้าได้ |
| 2.3 | reload แล้วกดยกเลิก | อยู่ที่หน้าล็อก และกดลองใหม่ได้ |

## ยังลองไม่ได้ในรอบนี้

- **Android:** แผนนี้ลองแค่ iOS และเว็บตาม ADR 0022 พฤติกรรมของ `requireAuthentication` บน Android จึงยังไม่ถูกลอง ถึงแม้จะใช้ API เดียวกันก็ตาม
- **passkey บน iPhone Safari:** ต้องใช้โดเมน HTTPS จริง ซึ่งยังไม่มี web Controller ที่ host ไว้
