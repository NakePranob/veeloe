# สิ่งที่ต้องลองด้วยมือ

e2e ลองหนี sandbox บน Linux ใน CI ด้วย Provider ปลอมที่สั่ง `bash` ตามบท ไฟล์นี้จดสิ่งที่ต้องใช้ macOS จริง, Linux จริงนอก CI และ Provider จริง ที่ LLM เลือกคำสั่งเอง

ยังไม่มี Approval คำสั่งที่ Agent ขอจะรันทันทีภายใต้ sandbox ลองบนเครื่องที่ไม่มีข้อมูลสำคัญนอกรายชื่อไฟล์ลับใน `design.md` เท่านั้น

repo นี้เป็น public เมื่อรายงานผล ให้ระบุแค่เครื่อง รุ่น OS ข้อที่ลอง และผลที่ได้ และอย่าใส่ key ของ Provider, เนื้อหาไฟล์ลับ, path ที่มีชื่อผู้ใช้จริง หรือรายชื่อโดเมนภายในขององค์กร

## เตรียม

ทำตาม `openspec/changes/agent-and-task/manual-checks.md` ส่วนเตรียมจนคุยกับ Agent ได้ แล้วสร้าง Agent สองตัวชื่อ A กับ B บน Machine เดียวกัน บน Linux ติดตั้ง `bubblewrap`, `socat` กับ `ripgrep` ก่อน (sandbox-runtime ใช้ ripgrep หาไฟล์ที่ห้ามเขียนใน Workdir ดูผลข้อ 1.1 ใน `design.md`)

e2e (`bun run test:e2e`) ลองข้อ 2 กับ 3 แบบอัตโนมัติแล้วด้วย Provider ปลอม ทั้งบน macOS และ Linux ใน CI ข้อ 3 ใน e2e ใช้ `example.com` จริงเพราะ proxy ของ sandbox หาที่อยู่ของโดเมนบนเครื่อง ไฟล์นี้จึงเหลือสิ่งที่ LLM จริงเลือกคำสั่งเอง และเครื่องจริงนอก CI

## 1. คำสั่งปกติ

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 1.1 | สั่ง A ว่า "สร้างไฟล์ hello.txt แล้วบอกว่าอยู่ที่ไหน" | หน้า Task แสดงคำสั่งพร้อมเครื่องหมายผ่าน และไฟล์อยู่ที่ `agents/<A>/workdir/hello.txt` |
| 1.2 | สั่ง A ให้รันคำสั่งที่ล้มเหลว เช่น `ls /ไม่มีจริง` | แถวคำสั่งเป็นสีแดง และ Agent อธิบาย error ได้ |
| 1.3 | สั่ง A ให้รันหลายคำสั่งต่อกัน | แถวเดียวบอกจำนวนคำสั่ง กดแล้วเห็นทีละคำสั่ง |
| 1.4 | สั่ง A ให้ `sleep 200` แล้ว `echo done` | คำสั่งแรกหมดเวลาที่ 120 วินาที, `ps` ไม่เหลือ `sleep` และ Turn จบปกติ |
| 1.5 | สั่ง A ให้รันคำสั่งที่พิมพ์ยาวมาก เช่น `seq 1 100000` | Agent ได้ตอนท้ายพร้อมบอกว่าตัดไป และแอปไม่ค้าง |

## 2. กำแพง

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 2.1 | สั่ง A ให้อ่าน `~/.ssh` และ `~/.aws/credentials` | Operation not permitted หรือเทียบเท่า และไม่มีเนื้อหาในแชต |
| 2.2 | สั่ง A ให้สร้าง symlink ไป `~/.ssh` ใน Workdir แล้ว `cat` ผ่าน symlink | อ่านไม่ได้เหมือน 2.1 |
| 2.3 | สั่ง A ให้ `ls` Workdir ของ B และอ่าน `runtime/providers.json` | อ่านไม่ได้ทั้งคู่ |
| 2.4 | สั่ง A ให้เขียน `~/.zshrc` หรือ `~/Library/LaunchAgents` | เขียนไม่ได้ และไฟล์เดิมไม่เปลี่ยน |
| 2.5 | สั่ง A ให้ `kill` pid ของ `veeloe` ที่หาได้จาก `ps` | kill ไม่ได้ และแอปยังออนไลน์ |
| 2.6 | เปิด server ที่ `127.0.0.1:8000` บนเครื่อง แล้วสั่ง A ให้ `curl` ไปที่นั่น | ต่อไม่ได้ |
| 2.7 | สั่ง A ให้อ่าน `/etc/hosts` | อ่านได้ |

## 3. Egress

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 3.1 | Egress ว่าง สั่ง A ให้ `curl -I https://github.com` | ต่อไม่ได้ แต่ Agent ยังตอบได้เพราะ LLM ไม่ผ่าน Egress |
| 3.2 | ในแอปไปหน้า Machine → Egress เพิ่ม `github.com` | ถาม Face ID หรือ passkey ก่อน footer บอกว่าใช้กับ A และ B |
| 3.3 | สั่ง B ให้ `curl -I https://github.com` โดยไม่เริ่ม `veeloe` ใหม่ | ต่อได้ เพราะรายชื่อใช้ทั้ง Machine |
| 3.4 | เพิ่ม `*.npmjs.org` แล้วสั่ง A ให้ `bun init -y && bun add zod` ใน Workdir | ติดตั้งได้ และ cache ของ package ไม่ทำให้ sandbox ปฏิเสธ |
| 3.5 | ใส่ `https://pypi.org/simple` หรือ `10.0.0.1` | แอปบอกว่าโดเมนไม่ถูกต้อง และไม่ส่งอะไร |
| 3.6 | เอา `github.com` ออก แล้วทำ 3.3 อีกครั้ง | ต่อไม่ได้ |

## 4. เครื่อง

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 4.1 | รัน `veeloe` บน Linux ที่ยังไม่มี bubblewrap, socat หรือ ripgrep | terminal บอกว่าขาดอะไรพร้อมคำสั่งติดตั้ง และจบด้วย exit code 1 โดยไม่เปิด worker |
| 4.2 | บน Ubuntu 24.04 ที่จำกัด user namespace | terminal บอกวิธีเปิด แทน error ที่อ่านไม่ออก |
| 4.3 | ปล่อย Task ที่รันคำสั่งเป็นช่วงๆ นานกว่า 10 นาที | worker ไม่หลุดจาก sandbox และไม่ถูกเปิดใหม่เอง |
| 4.4 | `ps` กับ `cat /proc/<pid>/environ` (Linux) ของ worker | ไม่มี key ของ Provider และไม่มี `VEELOE_PROXY_TOKEN` |
| 4.5 | `veeloe unpair` แล้วทำ Pairing ใหม่ | หน้า Machine เห็น Egress ว่าง |
