# สิ่งที่ต้องลองด้วยมือ

ไฟล์นี้จดสิ่งที่ agent ลองเองไม่ได้ ข้อที่ลองกับกุญแจอยู่ใน `openspec/changes/controller-device-key/manual-checks.md`

repo นี้เป็น public เมื่อรายงานผล ให้ระบุแค่เครื่อง รุ่น OS ข้อที่ลอง และผลที่ได้ และอย่าใส่ข้อมูลส่วนตัวหรือความลับ

## Safari และ Firefox จริง: ฐานข้อมูลบนเว็บ

**ลองได้แล้ว:** รันใน `controller/`:

```bash
bunx expo start --web
```

**เหตุผล:** agent ลองข้อ 1 ถึง 3 บน Chromium และ engine WebKit ของ Playwright ผ่านแล้ว แต่นั่นไม่ใช่ Safari ที่ผู้ใช้ติดตั้ง ส่วน Firefox ของ Playwright เปิดไม่ขึ้นบนเครื่องนี้ (`Could not find profile folder`) จึงยังไม่เคยลองเลย

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 1 | เปลี่ยนภาษา แล้วปิดเบราว์เซอร์และเปิดใหม่ | ยังเป็นภาษาที่เลือก |
| 2 | เปิดแท็บที่สอง | แท็บที่สองแสดงหน้า "ใช้ที่นี่" และแท็บแรกใช้ต่อได้ |
| 3 | กด "ใช้ที่นี่" | แท็บที่สองเข้าแอปได้ และแท็บแรกแสดงหน้า "ใช้ที่นี่" |
| 4 | เปิดในหน้าต่างส่วนตัวของ Safari | หน้าที่บอกให้เปิดในหน้าต่างปกติ พร้อมปุ่มลองใหม่ ไม่ใช่หน้าขาว |

## ยังลองไม่ได้ในรอบนี้

- **Android:** แผนนี้ลองแค่ iOS และเว็บตาม ADR 0022
- **Safari ลบข้อมูลหลัง 7 วัน:** รอลองจริงไม่คุ้ม ADR 0021 ถือว่าฐานข้อมูลบนเว็บเป็น cache ที่สร้างใหม่ได้

## ลองแล้ว ไม่ต้องลองซ้ำ

ลองเมื่อ 2026-11-03 จาก commit `c23ffb4` ด้วย Chromium 152 ใน browser pane ของ Claude และ `hub/cmd/testhub`

- **ผ่าน:** หน้า `http://localhost:63999` เปิด WebSocket ไปที่ `ws://127.0.0.1:<port>/connect` ซึ่งเป็นคนละ origin ได้ และได้ `hub.challenge` เป็น frame แรก ข้อนี้ปิดเรื่องที่ค้างจาก commit นั้นว่ายังไม่ได้ลองจากเบราว์เซอร์จริง
- **ไม่ผ่าน และยังไม่รู้สาเหตุ:** หน้า `https://example.com` ต่อ `ws://127.0.0.1:<port>/connect` ไม่ได้ (close 1006) โดยสายไม่ถึง Hub เลย ขณะที่ `curl` ที่ส่ง `Origin: https://example.com` ได้ 101 ปัญหาจึงอยู่ฝั่งเบราว์เซอร์หรือ pane ไม่ใช่การตรวจ Origin ของ Hub ข้อสันนิษฐานคือกฎที่กันหน้าเว็บสาธารณะไม่ให้ต่อเข้าเครื่องตัวเอง แต่ยังไม่ได้ยืนยัน
- **ยังไม่ได้ลอง:** handshake ที่เซ็นครบในเบราว์เซอร์ และการต่อ Hub ผ่าน `wss://` บนโดเมนจริง ข้อแรกอยู่ใน `machine-pairing` ส่วนข้อหลังต้องรอ Hub ที่ host ไว้
