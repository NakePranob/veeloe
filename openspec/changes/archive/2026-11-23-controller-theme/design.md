## Context

ดู proposal.md (Why) สำหรับเหตุผลของ change นี้

สภาพปัจจุบันของ `controller/src/shared/ui`:

- **`theme.ts`:** มีชุด light และ dark ใน `useColors()` และเงาใน `useShadows()` พื้นจอเป็นเทา (`background #f3f5f8`) ส่วน `Card` เป็นขาวมีเงา `radius.card` 22
- **ตัวอักษร:** น้ำหนักสูงสุด 500 และใช้ฟอนต์ระบบทุกแพลตฟอร์ม
- **ชิ้นที่มีอยู่:**
  - `Button` มีสามแบบ: `primary`, `chip`, `ghost`
  - `Row`, `Section`, `Field`, `Note`, `Empty`, `Meter`, `Bars`, `Label`, `Select`, `HeaderAction`, `QrCode`
- **การใช้สีนอก `shared/ui`:** 23 ไฟล์ใน `pages`, `widgets` และ `entities` เรียก `useColors()` เอง ส่วนใหญ่ใช้เป็นสีตัวอักษร (`secondaryLabel` 15 ครั้ง) หรือพื้น (`fill` 8, `background` 7)
- **hex นอก `theme.ts`:** อยู่ใน `pages/agent-character` และ `entities/character` เท่านั้น
- **ไฟล์ที่ต่อ `View` เองมากที่สุด:**
  - `pages/task/ui/TaskPage.tsx`: `View` 43 ตัว, `style` 29 ที่
  - `pages/agent-character`, `pages/add-machine`, `pages/link-device` และ `pages/task/ui` ส่วนอื่น

ต้นแบบหน้าตาคือกระดาน "Design system" บน canvas redesign:

- **สี:** พื้นจอขาว `#FFFFFF`, การ์ด `#F3F4F6`, หมึก `#111111`, ตัวอักษรรอง `#3A3A3A` และ `#5C5C5C`
- **สีสถานะ:** ส้ม `#FF7A2F` สำหรับรอคุณเท่านั้น, ฟ้า `#4C93CC` ทำงาน, เขียว `#2E8B57`, แดง `#D92D20` / `#B42318` และเทา `#9CA3AF` ออฟไลน์
- **มุมโค้ง:** 10, 16, 20, pill, 24
- **เงา:** เฉพาะของลอย
- **ฟอนต์:** Space Grotesk + Anuphan + JetBrains Mono

กระดานยังไม่มีชุด dark

## Goals / Non-Goals

**Goals:**

- หน้าเดิมทุกหน้าเปลี่ยนเป็นพื้นขาวกับการ์ดเทาโดยไม่ต้องแก้หน้าทีละหน้า
- ชิ้นที่ change `screens-redesign` ต้องใช้มีอยู่ใน `shared/ui` ครบก่อน
- กฎการใช้ element ถูกตรวจโดย `check:structure` ไม่ใช่แค่เขียนไว้ใน AGENTS.md

**Non-Goals:**

- ชุดสีของ Agent, ทรงกลม และ Mood failed หรือ stuck: อยู่ใน `character-look`
- ย้าย `pages/task/ui` ไปเป็น widget: อยู่ใน `task-log-widgets`
- เปลี่ยนโครง ลำดับ หรือคำของหน้าใด: อยู่ใน `screens-redesign`
- ลบหรือแก้ `controller-prototype`: เป็นของทิ้ง แค่หยุดใช้เป็นต้นแบบ

## Decisions

### 1. เปลี่ยนค่าของ token เดิม และเพิ่ม token ตามบทบาท แทนการตั้งชุดใหม่ข้างกัน

`background` กลายเป็นพื้นจอขาว และเพิ่ม `card` สำหรับพื้นการ์ดเทา ส่วน `surface` คงความหมาย "ของที่ลอย" (ขาว + เงา) สำหรับ composer, การ์ดลอย และป้ายบนพื้นการ์ด

`Section` กับ `Card` ที่ไม่ได้ `raised` ย้ายไปใช้ `card` ที่ไม่มีเงา ส่วนสีสถานะใช้ค่าจากกระดาน แล้วเพิ่ม `blue` สำหรับทำงานกับ `redText` สำหรับตัวอักษรแดงที่อ่านบนพื้นขาวได้

- **ทางที่ไม่เลือก: ตั้ง theme ชุดที่สองแล้วสลับทีละหน้า** ทำให้ระหว่างทางแอปมีสองหน้าตาปนกัน และทุกหน้าต้องถูกแตะ ซึ่งขัดกับเป้าที่ให้หน้าเดิมเปลี่ยนตาม token

### 2. Dark mode มาจากกระดาน ไม่ใช่การกลับสีอัตโนมัติ

ต้องวาดชุด dark บนกระดาน Design system ก่อนเขียนค่าใน `theme.ts` (task แรก) หลักของ dark คือ:

- พื้นจอดำเกือบสนิท
- การ์ดเทาเข้มขึ้นหนึ่งระดับ
- หมึกกลายเป็นขาว ปุ่มหลักจึงเป็นขาวตัวอักษรดำ
- เงาแทบมองไม่เห็นบนพื้นมืด ของที่ลอยจึงใช้พื้นที่สว่างกว่าการ์ดแทนเงา

- **ทางที่ไม่เลือก: คำนวณ dark จาก light ด้วยการกลับค่า** ได้สีสถานะที่ contrast ไม่พอ และส้ม "รอคุณ" เพี้ยน

### 3. ฝังฟอนต์ด้วย `expo-font` และโหลดก่อนแสดงหน้าแรก

ใช้ Space Grotesk สำหรับตัวละติน, Anuphan สำหรับตัวไทย และ JetBrains Mono สำหรับคำสั่ง ไฟล์ และ model โหลดตอนแอปเริ่มใน `RootLayout` และให้ splash ค้างไว้จนโหลดเสร็จ หน้าแรกจึงไม่กระพริบเปลี่ยนฟอนต์

เลือกเฉพาะน้ำหนักที่กระดานใช้ (400, 500, 600, 700 และ mono 400, 500) เพื่อให้แอปใหญ่ขึ้นน้อยที่สุด `Text` เลือกฟอนต์จากน้ำหนัก เพราะบน Android หนึ่ง family ต่อหนึ่งน้ำหนัก `fontWeight` อย่างเดียวจึงไม่พอ

React Native ใช้ fallback ได้แค่ family เดียว ข้อความไทยปนอังกฤษจึงต้องเลือกหนึ่ง family ต่อข้อความ:

- `Text` ใช้ Anuphan เป็นหลัก เพราะมีตัวละตินในตัวอยู่แล้ว
- ใช้ Space Grotesk เฉพาะตัวเลขกับชื่อใหญ่ที่เป็นละตินล้วน เช่น ตัวเลขใน `Stat` และชื่อ Agent

ขั้นนี้ต้องดูบนเครื่องจริงก่อนตัดสินแบบสุดท้าย (ดู Risks)

- **ทางที่ไม่เลือก: ใช้ฟอนต์ระบบต่อ** ไม่มีงานและไม่เพิ่มขนาด แต่ไม่ตรงต้นแบบที่ตกลงให้กระดานเป็นตัวตัดสิน
- **ทางที่ไม่เลือก: โหลดฟอนต์จากเน็ตตอนเปิดแอป** แอปต้องใช้ได้แม้ออฟไลน์ (ADR 0021)

### 4. ชิ้นใหม่ใน `shared/ui` มีเท่าที่กระดานใช้ซ้ำมากกว่าหนึ่งหน้า

| ชิ้น | ใช้ที่ | props |
|---|---|---|
| `Chip` | ป้ายสถานะ, model, จำนวน, ตัวเลือกหนึ่งอย่าง | `tone` (status, mono, count, choice), `selected`, `dot` |
| `Tabs` | Inbox | `items` (ชื่อ + จำนวน), `value`, `onChange` |
| `Stat` | Machine, Agent, Usage | `value`, `unit`, `label` |
| `Row` | ทุก Section | `icon` เป็นไอคอนเปล่า 20 สีหมึก ไม่มีช่องรอง ตามหน้าส่วนใหญ่บน canvas, แถวสูงอย่างน้อย 52 |
| `Button` `destructive` | ลบ Agent, ลบโดเมน | ตัวอักษรแดงบนพื้นปกติ |
| `Button` `floating` | สุ่มชิ้นส่วน | ไอคอนกลมดำมีเงา ขยับได้ หยุดเมื่อลดการเคลื่อนไหว |
| `Field` คู่ปุ่ม | Allowlist, Egress, git repo | `action` ปุ่มดำในช่องเดียวกัน |

`Meter` เพิ่มสีตามระดับ: ดำตามปกติ, ส้มเมื่อเกิน 80% และแดงเมื่อหมด

ของที่มีหน้าเดียวใช้ เช่น QR หรือช่องกล้อง ยังอยู่ในหน้านั้น

- **ทางที่ไม่เลือก: เพิ่ม layout primitive (`Stack`, `HStack`)** `View` กับ `gap` ทำได้อยู่แล้ว ปัญหาที่วัดได้คือสีและพื้นที่ตั้งเอง ไม่ใช่การจัดวาง

### 5. กฎการใช้ element ตรวจที่ `import` และ literal ไม่ตรวจ style ทุกค่า

ADR ใหม่กำหนดว่าไฟล์ใน `src/pages` และ `src/widgets`:

- ห้าม import `useColors` หรือ `useShadows`
- ห้ามมี hex สี (`#rgb`, `#rrggbb`, `#rrggbbaa`)

สีตัวอักษรให้ใช้ `Text` ผ่าน `tone` ส่วนพื้น การ์ด และป้ายให้ใช้ชิ้นใน `shared/ui`

`entities` ยังใช้สีได้ เพราะ `Character` วาดหัวหุ่นจากสีของ Agent และมีสีจอของตัวเอง

ตัวตรวจอยู่ใน `scripts/check-structure.ts` เป็นกฎใหม่ใน `.conventions/rules.json` พร้อมไฟล์ที่ต้องถูกปฏิเสธและผ่าน แล้วพิสูจน์ด้วย `prove.py` ตาม ADR 0070

- **ทางที่ไม่เลือก: ตรวจทุก `style={}` ว่ามีแค่ค่าจัดวาง** ต้อง parse JSX และแยก `gap` ออกจาก `backgroundColor` ในทุกรูปแบบการเขียน ตัวตรวจซับซ้อนกว่าปัญหา ส่วนการ import `useColors` เป็นทางเดียวที่หน้าจอจะได้สีมาตั้งเอง จึงตรวจตรงนั้นพอ
- **ทางที่ไม่เลือก: เขียนไว้ใน AGENTS.md อย่างเดียว** กฎ "Colours come from theme.ts only" เขียนไว้แล้ว แต่ `pages/agent-character` ยังมี hex อยู่

### 6. ย้ายหน้าที่ฝ่ากฎใน change นี้ ยกเว้นส่วนที่ change อื่นจะเขียนใหม่

หน้าที่เรียก `useColors()` ย้ายไปใช้ `Text tone` และชิ้นใน `shared/ui` ใน change นี้ เพื่อให้กฎเปิดได้ทันที

ข้อยกเว้นมีสองที่ ทั้งสองถูกรายชื่อไว้เป็นข้อยกเว้นชั่วคราวใน `rules.json` พร้อมชื่อ change ที่จะลบออก:

- **`pages/task/ui`:** จะย้ายไปเป็น widget ใน `task-log-widgets`
- **hex สีใน `pages/agent-character`:** จะย้ายไป `entities/character` ใน `character-look`

## Risks / Trade-offs

- **[ฟอนต์ไทยกับละตินคนละ family]** ข้อความผสมอาจมี baseline หรือความสูงไม่เท่ากัน → `Text` ใช้ Anuphan เป็นหลักซึ่งมีตัวละตินในตัว และดูบน iOS Simulator, Android และ web ทั้งสองภาษาก่อนปิด task ฟอนต์
- **[แอปใหญ่ขึ้น]** → ฝังเฉพาะน้ำหนักที่ใช้ และวัดขนาด build ก่อนกับหลังใส่ไว้ใน PR
- **[หน้าตาเปลี่ยนทั้งแอปในทีเดียว]** หน้าที่ยังไม่ได้ redesign จะดูครึ่งๆ กลางๆ (พื้นขาวแต่โครงเดิม) จนกว่า `screens-redesign` จะเสร็จ → ยอมรับได้ก่อนจบ v0.3 เพราะยังไม่มีคนนอกใช้ (ADR 0048) และดีกว่าสองหน้าตาปนกัน
- **[dark mode ยังไม่มีบนกระดาน]** ถ้าเริ่มโค้ดก่อน ค่า dark จะเป็นการเดา → task แรกคือวาด dark บนกระดาน และ task ของ `theme.ts` รอ task นั้น
- **[change ที่ค้างอยู่ชนกัน]** `agent-memory-page` และ `push-notifications` แตะหน้าที่หน้าตาจะเปลี่ยน → ปิดสองอันนั้นก่อนเริ่ม task ที่ย้ายหน้า
- **[กฎ import ถูกเลี่ยงได้]** เช่น ส่งสีผ่าน prop จาก entity → กฎนี้จับทางที่เกิดจริงในโค้ดตอนนี้ ถ้าเจอทางใหม่ค่อยเพิ่มเป็นไฟล์ที่ต้องถูกปฏิเสธ

## Migration Plan

1. **กระดาน:** วาดชุด dark บนกระดาน Design system และแก้ `controller/AGENTS.md` ให้ชี้ที่กระดาน
2. **token และฟอนต์:** ใน PR เดียว เพื่อให้ทั้งแอปเปลี่ยนพร้อมกัน
3. **ชิ้นใหม่ใน `shared/ui`:** ทีละชิ้น ยังไม่มีหน้าไหนต้องใช้ จึงไม่กระทบใคร
4. **ย้ายหน้าที่ใช้ `useColors()`:** แล้วเปิดกฎใหม่ใน `check:structure`

ถ้าต้องถอยกลับ ให้ revert commit ของ token กับฟอนต์ เพราะไม่มีข้อมูลในเครื่องหรือ Protocol เปลี่ยน
