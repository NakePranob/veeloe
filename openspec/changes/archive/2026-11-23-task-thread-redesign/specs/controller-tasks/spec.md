## MODIFIED Requirements

### Requirement: หน้า Task แสดงคำสั่งที่ Agent รัน
หน้า Task SHALL แสดงทุก tool ที่ Agent ขอใช้ตามลำดับใน log พร้อมสถานะว่ากำลังทำ ผ่าน ล้มเหลว หรือไม่เสร็จ และผลเมื่อได้แล้ว แต่ละ tool SHALL ถูกบอกด้วยคำกริยาตามชนิดของ tool กับเป้าหมายของมัน เช่น รันคำสั่ง อ่านไฟล์ แก้ไฟล์ สร้างไฟล์ ค้นหา หรือส่งไฟล์ tool ที่แอปไม่รู้จักชนิด SHALL แสดงด้วยชื่อของ tool นั้น tool ที่ใช้ติดกันหลายตัว SHALL รวมเป็นกลุ่มเดียวที่หุบไว้เป็นค่าเริ่มต้น กลุ่มที่หุบ SHALL แสดง action ล่าสุดพร้อมจำนวน tool ที่ซ่อนอยู่ ถ้ามี tool ที่กำลังทำ SHALL แสดงตัวนั้น ถ้าไม่มีและมี tool ที่ล้มเหลว SHALL แสดงตัวที่ล้มเหลวล่าสุดพร้อมบรรทัด error สุดท้าย และกลุ่มที่มี tool ล้มเหลวซึ่งไม่ใช่ตัวที่แสดง SHALL บอกว่ามีตัวที่ล้มเหลวซ่อนอยู่ การกดกลุ่ม SHALL เปิดดูทุก tool พร้อมผลทีละตัว tool ที่ Turn จบไปก่อนได้ผล SHALL แสดงว่าไม่เสร็จ แอป SHALL ใช้ข้อความทั้งภาษาไทยและอังกฤษ (ADR 0065)

#### Scenario: คำสั่งเดียว
- **WHEN** Agent รัน `ls` หนึ่งคำสั่งแล้วตอบ
- **THEN** หน้า Task แสดงว่ารัน `ls` พร้อมเครื่องหมายว่าผ่าน ก่อนคำตอบของ Agent และกดแล้วเห็นผล

#### Scenario: tool แต่ละชนิด
- **WHEN** Agent อ่าน `src/client.rs` แล้วแก้ไฟล์เดียวกัน
- **THEN** หน้า Task บอกว่าอ่าน `src/client.rs` และแก้ `src/client.rs` ไม่ใช่บรรทัดคำสั่งแบบเดียวกันทั้งคู่

#### Scenario: กำลังรัน
- **WHEN** Agent ใช้ tool ห้าตัวติดกัน และตัวที่ห้ายังไม่จบ
- **THEN** หน้า Task แสดงกลุ่มที่หุบอยู่ซึ่งบอก tool ตัวที่ห้าพร้อมสถานะกำลังทำ และบอกว่ามีอีก 4 ตัว

#### Scenario: หลายคำสั่งติดกัน
- **WHEN** Agent รันสามคำสั่งติดกันโดยคำสั่งที่สองล้มเหลว และ Turn เดินต่อ
- **THEN** กลุ่มที่หุบอยู่แสดงคำสั่งที่ล้มเหลวพร้อมบรรทัด error สุดท้าย และกดแล้วเห็นทั้งสามคำสั่ง

#### Scenario: tool ชนิดใหม่
- **WHEN** Runtime ที่ใหม่กว่าให้ Agent ใช้ tool ที่แอปไม่รู้จัก
- **THEN** หน้า Task แสดง tool นั้นด้วยชื่อของมันพร้อมสถานะ

#### Scenario: Turn จบก่อนคำสั่งได้ผล
- **WHEN** worker พังระหว่างคำสั่งรัน
- **THEN** หลัง Turn จบ คำสั่งนั้นแสดงว่าไม่เสร็จ

### Requirement: หน้า Task มี Character ของ Agent
header ของหน้า Task SHALL มี Character ของ Agent พร้อม Mood ของ Task นี้อยู่ซ้ายชื่อ Agent และมีสถานะของ Task ใต้ชื่อ ปุ่มกลับและตัวแถบ SHALL เป็นของระบบ การแตะ Character หรือชื่อ SHALL เปิดหน้า Agent เหมือนปุ่มตั้งค่า Agent ที่ header

#### Scenario: แตะ Character
- **WHEN** Owner แตะ Character ที่ header ของหน้า Task
- **THEN** หน้า Agent ซึ่งมีรายชื่อ Task และปุ่ม Task ใหม่เปิดขึ้น

#### Scenario: เลื่อน log ยาว
- **WHEN** Owner เลื่อน log ขึ้นไปดูข้อความเก่า
- **THEN** Character Mood และสถานะยังเห็นอยู่ที่ header

## ADDED Requirements

### Requirement: Turn ที่จบแล้วสรุปไฟล์ที่ Agent แก้
เมื่อ Turn จบ หน้า Task SHALL แสดงแถวสรุปจำนวนไฟล์ที่ Agent แก้หรือสร้างด้วย tool แก้ไฟล์และเขียนไฟล์ที่สำเร็จใน Turn นั้น ไฟล์เดียวกันที่ถูกแตะหลายครั้ง SHALL นับครั้งเดียว การกดแถว SHALL แสดงรายชื่อไฟล์ตามลำดับที่ถูกแตะครั้งแรก Turn ที่ไม่มีไฟล์ถูกแก้ด้วย tool เหล่านั้น SHALL ไม่มีแถวนี้ คำบนแถว SHALL บอกว่านับเฉพาะไฟล์ที่ Agent แก้ด้วย tool แก้ไฟล์ ไม่ใช่ทุกไฟล์ที่คำสั่งอื่นเปลี่ยน

#### Scenario: แก้สองไฟล์
- **WHEN** Turn หนึ่ง Agent แก้ `a.rs` สองครั้งและสร้าง `b.md` แล้ว Turn จบ
- **THEN** หน้า Task แสดงแถวว่าแก้ 2 ไฟล์ และกดแล้วเห็น `a.rs` กับ `b.md`

#### Scenario: Turn ที่แค่อ่าน
- **WHEN** Turn หนึ่ง Agent อ่านไฟล์และรันคำสั่งเท่านั้น
- **THEN** หน้า Task ไม่มีแถวสรุปไฟล์ของ Turn นั้น

#### Scenario: แก้ไฟล์ไม่สำเร็จ
- **WHEN** tool แก้ไฟล์ล้มเหลวกับ `c.rs` และไม่มีการแก้อื่นใน Turn นั้น
- **THEN** หน้า Task ไม่มีแถวสรุปไฟล์ของ Turn นั้น
