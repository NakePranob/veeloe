# สิ่งที่ต้องลองด้วยมือ

agent ที่ทำ change นี้ไม่ได้รันแอป ไม่ได้เปิด Metro หรือ iOS Simulator ตามที่เจ้าของสั่ง สิ่งที่ตรวจแล้วคือ `bun run check`, `bun run test` (test ของ `moodOf`, การสุ่มหน้าตา, `lookOf`, สถานะ `failed` บน `bun:sqlite`, `inboxRows`, `links` ที่ส่งและเก็บ `character`, vector ของ Protocol และ supervisor ที่เก็บ `character` ข้ามการเริ่มใหม่) ข้อข้างล่างทั้งหมดจึงยังต้องลองด้วยมือ ทั้งบน iOS Simulator และเว็บ สว่างและมืด ไทยและอังกฤษ

repo นี้เป็น public เมื่อรายงานผล ให้ระบุแค่เครื่อง รุ่น OS ข้อที่ลอง และผลที่ได้ และอย่าใส่ key ของ Provider ลิงก์ Pairing หรือเนื้อหาแชตที่เป็นความลับ

## เตรียม

ทำ Pairing กับเพิ่ม Provider ตาม `openspec/changes/agent-and-task/manual-checks.md` ใช้ `veeloe` ที่ build จาก commit นี้ เพราะ Runtime รุ่นเก่าไม่เก็บ `character` สำหรับข้อ 4.2 ใช้ Provider ปลอมของ `bun run test:e2e` หรือ Provider ที่ตั้ง key ผิดไว้

## 1. Character

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 1.1 | เปิดหน้าสร้าง Agent แล้วกดสุ่ม Character ใหม่สองครั้ง | Character 96 จุดเปลี่ยนหน้าตาทุกครั้ง ไม่ซ้ำกับ Agent ที่มี |
| 1.2 | สร้าง Agent | Agent ใหม่ใน Inbox รายชื่อ Agent และหน้า Agent มีหน้าตาแบบที่เห็นล่าสุดก่อนกดสร้าง |
| 1.3 | ปิดแอปแล้วเปิดใหม่ และเปิดบนเว็บอีกเครื่องที่ใช้ Workspace เดียวกัน | หน้าตาเดิมทุกที่ |
| 1.4 | ดู Agent ที่สร้างก่อน change นี้ | หน้าตาเริ่มต้นแบบเดียว (เปลือก box สีส้มอ่อน ไม่มีชิ้นส่วน) ไม่พัง |
| 1.5 | เปิด VoiceOver แล้วแตะแถวใน Inbox | อ่านชื่อ สถานะ และข้อความ ไม่อ่าน Character |
| 1.6 | เปิดลดการเคลื่อนไหวในเครื่อง แล้วส่งข้อความ | Character เปลี่ยนท่าทันที ไม่ลอย ไม่กระโดด |

## 2. Mood และสถานะ

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 2.1 | ส่งข้อความแล้วรอ Agent ตอบจบ | Character ใน Inbox และหัวของ log คิด (จุดกระพริบ) แล้วเสร็จพร้อมกระโดดหมุนหนึ่งรอบ สถานะกำลังทำงานแล้วเสร็จแล้ว |
| 2.2 | ให้ Provider ตอบ error | Character เป็นว่าง ไม่ฉลอง แถวใน Inbox และหัวหน้า Task บอกว่า Turn ล้มเหลว |
| 2.3 | ปิด `veeloe` ระหว่าง Turn | Character เป็นสีเทาวางบนพื้น สถานะออฟไลน์ และกลับเป็น Mood ตาม event เมื่อเปิด `veeloe` ใหม่ |
| 2.4 | มี Agent หลายตัวที่ทำงานพร้อมกันใน Inbox บน iPhone จริง | เลื่อนรายการได้ลื่น |

## 3. หน้า Task

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 3.1 | แตะ Character ที่หัวของ log | หน้า Agent เปิดขึ้น เหมือนปุ่มตั้งค่า Agent |
| 3.2 | ดูใต้ Character | ชื่อ Machine กับเวลาที่ Task เริ่ม หรือยังไม่ได้เริ่มใน Task ใหม่ |
| 3.3 | เลื่อน log ยาวลงจนสุด | ท้าย log จางลงเหนือช่องพิมพ์ ข้อความสุดท้ายไม่ถูกเส้นจางทับ |
| 3.4 | พิมพ์ระหว่างที่ Agent ยังตอบไม่จบ | พิมพ์ได้ ปุ่มส่งกดไม่ได้ placeholder บอกว่าส่งได้เมื่อ Turn นี้จบ |
| 3.5 | รอ Turn จบ | ข้อความที่พิมพ์ค้างยังอยู่ และกดส่งได้ทันที |
| 3.6 | ส่งจาก Controller อีกเครื่องระหว่าง Turn ที่เริ่มจากเครื่องนี้ | ยังเห็นคำของ `agent.busy` ใต้ข้อความ |

## 4. Inbox ข้าง Task

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 4.1 | เปิดเว็บในหน้าต่างกว้างกว่า 960 จุด และ iPad Simulator | การ์ด Inbox ทางซ้าย ทางขวาบอกให้เลือก Agent ทางซ้ายพร้อมไอคอน inbox |
| 4.2 | แตะ Agent สองตัวต่อกัน | Task ของตัวที่สองแทนที่ตัวแรก แถวที่เปิดอยู่ถูกเน้น หัวหน้า Task ไม่มีปุ่มย้อนกลับ |
| 4.3 | ย่อหน้าต่างให้แคบกว่า 960 จุด | แถบข้างหายไป Task เดิมยังเปิดอยู่ ย้อนกลับไป Inbox ได้ |
| 4.4 | ล็อกแอป | แถบข้างหายไปพร้อมหน้าอื่น แล้วกลับมาที่เดิมเมื่อปลดล็อก |
| 4.5 | ยังไม่มี Machine บนจอกว้าง | ทางขวาบอกให้เพิ่ม Machine แถบข้างบอกว่ายังไม่มี Agent |
