# สิ่งที่ต้องลองด้วยมือ

ฝั่งโค้ดตรวจด้วย unit test ของ `worker/adapters/files.test.ts` (path, symlink, read/write/edit/glob/grep และขีดจำกัด), `tools.test.ts` (การประกอบ runner) และ flow test ที่ worker จริงเขียนไฟล์ผ่าน tool พร้อม event `tool.result` แล้ว; sandbox e2e เดิมยังผ่าน (`e2e/sandbox.test.ts`) ยืนยันว่า `bash` ยังทำงานใน OS sandbox

repo นี้เป็น public เมื่อรายงานผล ให้ระบุแค่เครื่อง รุ่น OS ข้อที่ลอง และผลที่ได้ อย่าใส่ key ของ Provider หรือเนื้อหาไฟล์ที่เป็นความลับ

## เตรียม

ทำตาม `openspec/changes/archive/2026-11-05-agent-and-task/manual-checks.md` ให้มี Agent ที่คุยกับ Provider จริงได้ แล้วรัน `veeloe` build ใหม่

## 1. Tool พื้นฐาน

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 1.1 | ขอให้ Agent อ่านไฟล์ใน Workdir | ผลลัพธ์เป็นเนื้อหาไฟล์พร้อมเลขบรรทัด |
| 1.2 | ขอให้ Agent สร้างไฟล์ใหม่ในโฟลเดอร์ที่ยังไม่มี | ไฟล์ถูกสร้างและมีโฟลเดอร์ครบ |
| 1.3 | ขอให้ Agent แก้ข้อความหนึ่งจุดในไฟล์ | ไฟล์เปลี่ยนเฉพาะจุดนั้นและสิทธิ์ไฟล์เท่าเดิม |
| 1.4 | ขอให้ Agent หาไฟล์ `**/*.ts` | ได้ path relative เรียงลำดับ และไม่เห็น `.git`/`node_modules` |
| 1.5 | ขอให้ Agent ค้น `TODO` ในไฟล์ `.ts` | ได้ `path:line: ข้อความ` และค้นแบบไม่สนตัวพิมพ์ได้ |

## 2. ขอบเขตและความปลอดภัย

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 2.1 | สร้าง symlink ใน Workdir ชี้ไปไฟล์นอก Workdir แล้วขอให้ Agent อ่านผ่าน symlink | tool ปฏิเสธว่า path อยู่นอก Workdir |
| 2.2 | ขอให้ Agent เขียน `../escape.txt` | tool ปฏิเสธและไม่มีไฟล์ถูกสร้างนอก Workdir |
| 2.3 | ขอให้ Agent อ่านไฟล์นอก Workdir ด้วย `bash` | ยังทำได้ตามกฎ sandbox ของ ADR 0008 (ไฟล์ลับยังอ่านไม่ได้) — file tools เข้มกว่าโดยตั้งใจ |
| 2.4 | สร้าง `.git/hooks` ที่เขียนได้แล้วให้เจ้าของรัน `git` ใน Workdir เอง | เตือนในรายงานว่าโค้ดที่ Agent เขียนรันนอก sandbox ได้ถ้าเจ้าของรันเอง (ADR 0032) |

## 3. ขีดจำกัด

| ข้อ | ทำอะไร | ควรเห็น |
|---|---|---|
| 3.1 | อ่านไฟล์ 5,000 บรรทัด | ได้ 2,000 บรรทัดแรกและบอก offset ถัดไป |
| 3.2 | อ่านไฟล์ไบนารีหรือไฟล์ใหญ่กว่า 10MB | tool ปฏิเสธและแนะนำ `grep`/`bash` |
| 3.3 | เขียนเนื้อหาเกิน 2MB | tool ปฏิเสธและไม่เขียนอะไร |
| 3.4 | แก้ข้อความที่ปรากฏ 3 ครั้งโดยไม่ขอ `replace_all` | tool บอกว่าพบ 3 ครั้งและไฟล์ไม่เปลี่ยน |
