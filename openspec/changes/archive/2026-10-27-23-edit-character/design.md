## Context

แรงจูงใจอยู่ใน proposal.md (Why) และพฤติกรรมที่ต้องได้อยู่ใน `specs/controller-character` สภาพของโค้ดตอนนี้ (หลัง `31b8c71`):

- `entities/agent/ui/Character.tsx` วาดหัวหุ่นยนต์ลอยแบบ 2.5D ด้วย `react-native-svg` และขยับด้วย `Animated` รับ `agent` กับ `mood`
- `entities/task/model/state.ts` มี `moodOf` และ test แล้ว ซึ่งตรงกับ requirement "Mood comes from the Task's events"
- `entities/agent/model/agents.ts` เก็บ Agent ใน Demo เป็น array ค่าคงที่ ห้าค่าของหน้าตาวางแยกกันใน `Agent` (`color`, `shell`, `top`, `sides`, `decal`)
- Controller มีแค่สอง route คือ `index` (Inbox) กับ `tasks/[task]` และยังไม่เคยใช้ sheet
- `entities/task/model/store.ts` เป็น store ระดับ module ที่อ่านผ่าน `useSyncExternalStore` และเขียนไว้ว่าจะย้ายไป SQLite (ADR 0021) โดยใช้ hook ชื่อเดิม
- `Picker` แบบ universal ของ `@expo/ui` มีแค่แบบ `menu` กับ `wheel` ไม่มีแบบ segmented
- บนเว็บ Stack ของ Expo Router 58 แสดงแค่หน้าที่อยู่หน้าสุด หน้าอื่นถูกซ่อน ยกเว้น `transparentModal` ดังนั้น `formSheet` บนเว็บจะกลายเป็นหน้าเต็ม

## Goals / Non-Goals

**Goals:**
- หน้าแก้ตัวเดียวที่หน้า Agent และขั้นตอนสร้าง Agent ใน #11 เปิดซ้ำได้ด้วย route เดิม
- ข้อมูลหน้าตาที่ส่งข้ามระบบเป็นก้อนเดียว ตอน Hub เข้ามาจะได้แค่เพิ่ม field ไม่ต้องแก้หน้าจอ
- ทำทุกอย่างด้วย dependency ที่มีอยู่แล้ว

**Non-Goals:**
- ไม่ทำกล่องลอย (dialog) ของเราเองบนเว็บ ใช้หน้าเต็มที่ Stack ให้มา
- ไม่เก็บ Agent ลง SQLite ใน change นี้ store บนเครื่องยังอยู่ในหน่วยความจำเหมือน store ของ Task

## Decisions

### 1. หน้าตาเป็นก้อนเดียว `character` และถอยไปใช้ค่าตั้งต้นทีละช่อง

`Agent` เปลี่ยนเป็น `{ id, name, machine, character: { color, shell, top, sides, decal } }` และ Character อ่านหน้าตาผ่านฟังก์ชันเดียวที่ทำให้ค่าเป็นปกติ ถ้าเจอค่าที่ไม่รู้จักในช่องไหน ก็ใช้ `box` หรือ `none` แทนเฉพาะช่องนั้น สีที่ไม่ใช่ hex 6 หลักก็ถอยไปใช้สีแรกของชุด

- **ทำไม:** ADR 0006 ให้ Hub เก็บ Character เป็นเรื่องเดียว พอข้อมูลเป็นก้อนเดียวกัน วันที่ทำ message ของ Protocol ก็มี field เดียว ส่วนการถอยไปใช้ค่าตั้งต้นทำให้ Controller รุ่นเก่ายังแสดง Agent ได้ เมื่อรุ่นใหม่เพิ่มเปลือกหรือชิ้นส่วน ซึ่งเป็นเงื่อนไขของ ADR 0023
- **ทางเลือกที่ไม่เอา:** วางห้าค่าแยกใน `Agent` เหมือนตอนนี้ ใช้ได้ในวันนี้ แต่วันที่ Hub เข้ามาต้องแยกหยิบทีละค่าและตรวจทีละค่าซ้ำในหลายที่

### 2. store ของ Agent ตามแบบ store ของ Task

ย้าย Agent ใน Demo ไปไว้ใน store ระดับ module แบบเดียวกับ `entities/task/model/store.ts` ให้ `useAgents` กับ `useAgent` อ่านผ่าน `useSyncExternalStore` และเพิ่ม `updateCharacter(agentId, character)` ที่เปลี่ยนทั้งก้อนในครั้งเดียว

- **ทำไม:** Inbox, หัวหน้า Task และหน้าแก้ต้องเห็นค่าเดียวกันทันทีที่กดเสร็จ และวันที่ย้ายไป SQLite (ADR 0021) หน้าจอไม่ต้องแก้ เพราะชื่อ hook เดิม
- **ทางเลือกที่ไม่เอา:** เก็บใน state ของหน้า หรือ React context ซึ่ง Inbox จะไม่เห็นค่าใหม่ หรือต้องห่อทั้งแอป ส่วนการใช้ SQLite ตอนนี้ก็เร็วเกินไป เพราะ Task ยังไม่ได้ย้ายเหมือนกัน

### 3. route `agents/[agent]/character` เป็น `formSheet`

เพิ่มไฟล์ route บางๆ ที่ re-export หน้าจาก `src/pages/agent-character` และประกาศ `presentation: "formSheet"` ใน Stack ของ `RootLayout` ปุ่มยกเลิกกับเสร็จอยู่ใน header ของ sheet ซึ่งเป็นของ platform และเปิดด้วย `router.push` จากหัวหุ่นในหน้า Task

- **บนเว็บ:** Stack แสดงหน้านี้เต็มที่แทนหน้า Task และใน split view ก็แทนช่องขวาของ Inbox ปุ่มใน header ใช้ปิดได้เหมือนบน iOS และหน้านี้มี URL ของตัวเอง
- **ทางเลือกที่ไม่เอา:**
  - `BottomSheet` ของ `@expo/ui` เปิดเป็น component ในหน้า Task ไม่มี URL และหน้า Agent ในอนาคตเปิดซ้ำไม่ได้
  - ทำหน้า Agent ก่อนแล้วใส่ส่วน Character ไว้ข้างใน แต่หน้า Agent ต้องมี Workdir, Provider และ Allowlist ซึ่งยังไม่มีอะไรเลย
  - กล่องลอยของเราเองบนเว็บ เป็นงานเพิ่มที่ไม่จำเป็น และขัดกับกติกาที่ให้ใช้ navigation ของ platform

### 4. หน้าเดียวเลื่อนลง ห้าหมวด ไม่มีแท็บ

ด้านบนเป็นหัวใหญ่ราว 140pt ใต้ลงมาเป็นแถวหัวขนาด Inbox (44) ของทุก Mood แล้วตามด้วยห้าหมวดเรียงลงมา คือ เปลือก สี ด้านบน ด้านข้าง และลายบนเปลือก สีเป็นวงกลม ส่วนตัวเลือกอื่นเป็นหัวเล็กที่ใส่ชิ้นนั้นบนหน้าตาปัจจุบัน ปุ่มสุ่มอยู่ล่างสุด

- **ทำไม:** ตัวเลือกรวมมีแค่ 25 ชิ้น อยู่ในหน้าเดียวได้ และ Picker ไม่มีแบบ segmented แถว Mood ทำให้ Member เห็นทันทีว่าหน้าตาที่แต่งยังบอก Mood ได้ไหมที่ขนาดจริงใน Inbox
- **หัวเล็กในตัวเลือกต้องอยู่นิ่ง:** Character จะได้ prop ที่ปิดการขยับ เหมือนตอนผู้ใช้ปิด animation ในเครื่อง ถ้าหัว 25 ตัวลอยพร้อมกันจะรกและเปลือง มีแค่หัวใหญ่กับแถว Mood ที่ขยับ
- **ทางเลือกที่ไม่เอา:** แถบแท็บแบบหน้าแก้ Memoji ซึ่งต้องสร้าง segmented control เอง และซ่อนตัวเลือกสี่หมวดจากสายตาตลอดเวลา

### 5. แก้เป็น draft มีปุ่มยกเลิกกับเสร็จ

draft เริ่มจากหน้าตาของ Agent แตะตัวเลือกแล้วเปลี่ยนแค่ draft กดเสร็จแล้วค่อยเรียก `updateCharacter` ครั้งเดียว ส่วนการกดยกเลิกหรือปัด sheet ลงคือการทิ้ง draft ไม่ต้องถามยืนยัน เพราะเป็นแค่หน้าตา ไม่มีอะไรเสียหาย บน iOS การแตะตัวเลือกมี haptic แบบ selection

- **ทำไม:** ยกเลิกได้จริง และวันที่ส่งไป Hub การแก้หนึ่งครั้งก็เป็น message เดียว
- **ทางเลือกที่ไม่เอา:** เปลี่ยนทันทีทุกครั้งที่แตะ ซึ่งย้อนกลับไม่ได้ และวันหลังจะกลายเป็นหลาย message ต่อการแก้หนึ่งครั้ง

### 6. สุ่มแบบเลี่ยงหน้าตาที่มีคนใช้แล้ว

สุ่มทั้งห้าช่องแล้วเทียบกับหน้าตาของ Agent ตัวอื่นทั้งก้อน ถ้าซ้ำก็สุ่มใหม่ หน้าตามีทั้งหมด 2,560 แบบ ขณะที่ Workspace มี Agent ไม่กี่ตัว จึงเจอแบบที่ว่างแทบทันที ส่วนการเลือกเองยังเลือกซ้ำได้ เพราะ Member อาจตั้งใจให้หน้าเหมือนกัน

### 7. วางตาม Feature-Sliced Design

```
app/agents/[agent]/character.tsx   route บางๆ
src/pages/agent-character          หน้า sheet: header, กรณีไม่พบ Agent, จัดวาง, เก็บ draft
src/entities/agent                 Character, ทำค่าเป็นปกติ, เลือก, สุ่ม, store, updateCharacter
```

ตรรกะของ draft (`pick`) กับการสุ่ม (`shuffleLook`) เป็นฟังก์ชันล้วนใน `entities/agent/model/look.ts` ข้างการทำค่าเป็นปกติ เพื่อให้ test ด้วย `bun test` ได้เหมือน `state.ts` ของ Task เดิมวางแผนไว้ใน `features/edit-character` แต่ slice นั้นจะต้อง import entity ผ่าน index ซึ่งพา React Native เข้ามาใน test ด้วย และ Steiger ไม่ให้ข้าม index ไป และทั้งสองตัวก็เป็นเรื่องของหน้าตาล้วนๆ

### 8. Grant ระดับ Manage

v0.1 มีแค่ Owner คนเดียว ซึ่งมี Manage กับทุก Agent หน้าแก้จึงแก้ได้เสมอ วันที่มี Member คนที่สอง ปุ่มบนหัวหน้า Task ยังเปิดหน้านี้ได้ แต่คนที่ไม่มี Manage ต้องเห็นแบบดูอย่างเดียว (ADR 0010) ซึ่งไม่อยู่ใน change นี้

## Risks / Trade-offs

- **[ค่าที่แก้หายเมื่อเปิดแอปใหม่]** → store อยู่ในหน่วยความจำ เหมือน store ของ Task ใน Demo ตอนนี้ จะคงอยู่เมื่อย้ายไป SQLite ตาม ADR 0021
- **[บนเว็บหน้าแก้บังหน้า Task ทั้งหน้า]** → ปุ่มยกเลิกกับเสร็จพากลับไปหน้า Task ทันที ถ้าใช้จริงแล้วรู้สึกหลงทาง ค่อยพิจารณา `transparentModal` กับกล่องลอยบนเว็บ
- **[หัวหุ่นที่หัวหน้า Task เป็นปุ่ม คนอาจไม่รู้ว่าแตะได้]** → มีสถานะตอนกด และ label ให้ screen reader ส่วนวันที่มีหน้า Agent จะเป็นทางเข้าที่ชัดกว่า
- **[หัวหุ่นจำนวนมากในหน้าเดียว]** → หัวในตัวเลือกอยู่นิ่ง (ข้อ 4) มีแค่ 7 ตัวที่ขยับ

## Open Questions

- ตอนส่ง Character ไป Hub (#11) ต้องเซ็นหรือเปล่า ADR 0006 บอกว่าการแก้ค่า Agent ต้องเซ็นและ Runtime เป็นคนตรวจ แต่ Character ไม่ได้ไปถึง Runtime ทางที่เอนไปคือให้ Hub ตรวจ Grant ระดับ Manage เอง เพราะ Hub ที่โดนเจาะทำได้แค่เปลี่ยนหน้าตา ต้องตัดสินใน change ของ #11 และถ้าไม่เซ็น ต้องเขียนข้อยกเว้นนี้ลง ADR 0006
