## Context

ดู proposal.md (Why)

`widgets/agent-inbox/ui/AgentInbox.tsx` มีแถวของ Agent ที่มี `status: TaskStatus` และเรียงตาม requirement "Inbox แสดง Character และสถานะของแต่ละ Agent" สถานะที่มีอยู่แล้วคือ:

- รออนุมัติ
- กำลังทำงาน
- Turn ถูกขัดจังหวะ
- Turn ล้มเหลว
- เสร็จแล้ว
- ยังไม่ได้เริ่ม
- ออฟไลน์

กระดานบน canvas มีหน้าครบแล้ว แต่ 20 หน้าที่วาดโดยตัวช่วยยังขาด state ส่วนใหญ่ เช่น error, กำลังโหลด, ชื่อซ้ำ, ลิงก์ผิด และ Runtime ไม่รองรับ บางหน้ายังมีข้อมูลที่แต่งขึ้น (บันทึกไว้ใน proposal.md ส่วน Impact)

## Goals / Non-Goals

**Goals:**

- ทุกหน้าในแอปตรงกับกระดานบน canvas ครบทุก state ทั้งสองโหมดและสองภาษา
- Owner เห็นได้ทันทีว่ามี Agent กี่ตัวที่รอตัวเอง

**Non-Goals:**

- พฤติกรรมใหม่นอกจากแท็บของ Inbox: ของบนกระดานที่โค้ดไม่มี (เช่น สวิตช์ push ของ Workspace ที่ตัวช่วยใส่มา) ไม่ทำใน change นี้ และต้องลบออกจากกระดานหรือแยกเป็น change ของตัวเอง
- หน้า Task: อยู่ใน `task-thread-redesign`

## Decisions

### 1. แท็บแบ่งตามสิ่งที่ Owner ต้องทำ ไม่ใช่ตามสถานะทุกค่า

```
แท็บ       สถานะที่อยู่ในแท็บ                                   จำนวน
--------  ------------------------------------------------  ------
ทั้งหมด     ทุก Agent ตามลำดับเดิมของ requirement               ไม่มี
รอคุณ      รออนุมัติ, Turn ล้มเหลว, Turn ถูกขัดจังหวะ             ส้ม
ทำงาน      กำลังทำงาน                                         เทา
เสร็จ       เสร็จแล้ว                                          ไม่มี
```

ยังไม่ได้เริ่มและออฟไลน์อยู่ในแท็บทั้งหมดเท่านั้น เพราะไม่ต้องให้ Owner ทำอะไรและไม่มีงานค้าง

"รอคุณ" รวม Turn ล้มเหลวและถูกขัดจังหวะด้วย เพราะทั้งสองกรณี Agent จะไม่ทำต่อเองจนกว่า Owner จะส่งข้อความหรือกดทำต่อ

แท็บที่เลือกจำไว้ระหว่างที่แอปเปิดอยู่ และกลับเป็นทั้งหมดเมื่อเปิดแอปใหม่ เพื่อไม่ให้ Owner เปิดแอปมาแล้วไม่เห็น Agent ที่อยู่แท็บอื่น

การจัดแท็บเป็นฟังก์ชันล้วน `tabOf(status)` ใน `widgets/agent-inbox/model` พร้อม test

- **ทางที่ไม่เลือก: แท็บละหนึ่งสถานะ** มีเจ็ดแท็บซึ่งเกินความกว้างของจอโทรศัพท์ และแยก "ล้มเหลว" ออกจาก "รออนุมัติ" ทั้งที่ Owner ต้องทำเหมือนกัน
- **ทางที่ไม่เลือก: แถบ Agent ด้านบนกับรายการด้านล่าง (v3 บน canvas)** ข้อมูลซ้ำกันสองที่ ซึ่งถูกตัดไปแล้วตอนออกแบบ

### 2. แบบต้องครบก่อนโค้ด ทีละกลุ่ม

ก่อนเริ่มโค้ดของกลุ่มใด กระดานของทุกหน้าในกลุ่มนั้นต้องผ่านรายการนี้:

- มีทุก state ที่หน้านั้นมีในโค้ด โดยไล่จาก `i18n/th.json` ของ slice (ทุก key ที่เป็น error, empty, loading, offline ต้องมีที่วาด)
- มีโหมดมืดของหน้าที่มีการ์ดสีของ Agent (หน้าอื่นใช้การแทนสีตาม token ได้)
- ไม่มีข้อมูลหรือปุ่มที่โค้ดไม่มี ถ้ามี ต้องลบออก หรือบันทึกเป็นงานแยก

ลำดับกลุ่ม:

1. Inbox (ใช้บ่อยที่สุดและมีพฤติกรรมใหม่)
2. Agent
3. Workspace
4. เริ่มต้นและระบบ

แต่ละกลุ่มเป็น PR ของตัวเอง

### 3. หน้า Machine ทีละเครื่องคงลำดับ Section ของโค้ด

แบบบน canvas ใช้ลำดับเดียวกับ `MachinePage.tsx` (สถานะ, Agent, Provider, Egress) ที่เพิ่มมาคือส่วนบนกับ `Stat` สามช่องที่มาจากข้อมูลเดิม: จำนวน Agent, พื้นที่ว่าง และ Budget วันนี้ ส่วน `features` แสดงเป็น `Chip` และ `lastError` แสดงเป็น `Note` warning ตามแบบ

## Risks / Trade-offs

- **[แท็บซ่อน Agent ที่ Owner มองหา]** → เปิดแอปมาที่แท็บทั้งหมดเสมอ และจำนวนบนแท็บรอคุณบอกว่ามีงานรออยู่แม้อยู่แท็บอื่น
- **[กระดานไม่ครบทำให้เริ่มโค้ดช้า]** → แบ่งตามกลุ่ม Inbox เริ่มได้ก่อนเพราะกระดานของ Inbox ครบที่สุด
- **[ข้อมูลแต่งบนกระดานหลุดเข้าโค้ด]** → รายการตรวจข้อ 2 บังคับให้ลบก่อนเริ่มกลุ่ม
- **[change ที่ค้างอยู่ชนกัน]** `agent-memory-page` แตะหน้า Memory และ `push-notifications` แตะหน้า Workspace → ปิดสองอันนั้นก่อนเริ่มกลุ่ม Agent และ Workspace
