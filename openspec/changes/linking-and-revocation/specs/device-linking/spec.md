## ADDED Requirements

### Requirement: เครื่องใหม่แสดง QR ของ Linking
Controller ที่สร้างกุญแจแล้วแต่ยังไม่มี Machine SHALL เลือก Link กับเครื่องเดิมได้ เครื่องใหม่ SHALL แสดงลิงก์ `veeloe://link` เป็น QR และเป็นข้อความที่คัดลอกได้ ลิงก์ SHALL มี URL ของ Hub, กุญแจสาธารณะของเครื่องใหม่, ชื่อเครื่องเริ่มต้นจากรุ่นเครื่องหรือเบราว์เซอร์, รหัสลับสุ่มใหม่อย่างน้อย 256 bit และเวลาหมดอายุ 10 นาที รหัสลับ MUST NOT ออกจากเครื่องใหม่ทางอื่นนอกจากลิงก์นี้

#### Scenario: เลือก Link บนเครื่องใหม่
- **WHEN** เจ้าของสร้างกุญแจบนเครื่องใหม่แล้วเลือก Link กับเครื่องเดิม
- **THEN** แอปแสดง QR กับลิงก์ และรอจนกว่าจะได้รายชื่อ Machine จากเครื่องเดิมหรือหมดอายุ

#### Scenario: หมดเวลา
- **WHEN** ครบ 10 นาทีแล้วยังไม่ได้รายชื่อ Machine
- **THEN** แอปบอกว่าหมดอายุ ทิ้งรหัสลับ และให้สร้าง QR ใหม่ได้

### Requirement: เครื่องเดิมตรวจลิงก์และยืนยันตัวก่อนเซ็น
Controller ที่อยู่ใน Workspace แล้ว SHALL รับลิงก์ `veeloe://link` จากการสแกนหรือการวาง SHALL ปฏิเสธลิงก์ที่รูปแบบผิด หมดอายุ หรือชี้ Hub ที่เครื่องนี้ไม่ได้ใช้ SHALL แสดงชื่อเครื่องใหม่ให้เจ้าของแก้ได้ และการอนุมัติ MUST ยืนยันตัวใหม่ตาม ADR 0012 แม้แอปปลดล็อกอยู่ เครื่องเดิม SHALL Link ได้แค่เครื่องของ Member เจ้าของเครื่องนั้นเอง

#### Scenario: ลิงก์ถูกต้อง
- **WHEN** เจ้าของสแกนหรือวางลิงก์ที่ยังไม่หมดอายุและชี้ Hub ที่ใช้อยู่
- **THEN** แอปแสดงชื่อเครื่องใหม่ และรอให้เจ้าของอนุมัติ

#### Scenario: Hub ไม่ตรง
- **WHEN** ลิงก์ชี้ Hub ที่เครื่องนี้ไม่มี Machine อยู่
- **THEN** แอปปฏิเสธลิงก์และไม่ติดต่อ Hub ใด

#### Scenario: ยกเลิกการยืนยันตัว
- **WHEN** เจ้าของยกเลิกการยืนยันตัวตอนอนุมัติ
- **THEN** ไม่มีอะไรถูกเซ็นหรือส่งออก และแอปไม่ล็อกเพราะเรื่องนี้

#### Scenario: ชื่อซ้ำ
- **WHEN** ชื่อเครื่องใหม่ซ้ำกับเครื่องอื่นที่ยังใช้งานของ Member คนเดียวกัน
- **THEN** แอปไม่ให้อนุมัติจนกว่าจะเปลี่ยนชื่อ

### Requirement: ใบรับรองของ Linking ผูกกุญแจใหม่กับ Member
ใบรับรอง `device.link` SHALL เซ็นด้วยกุญแจของเครื่องเดิม และ SHALL ระบุ Workspace, Member, กุญแจใหม่, ชื่อเครื่อง, กุญแจที่เซ็น และเวลาที่เซ็น ใบรับรอง SHALL ผูกกุญแจใหม่กับ Member ไม่ได้ผูกกับเครื่องที่เซ็น (ADR 0031) ใบรับรองเดิมที่ส่งซ้ำ SHALL ได้ผลเดิม

#### Scenario: ใบรับรองถูกแก้
- **WHEN** ค่าใดในใบรับรองไม่ตรงกับลายเซ็น
- **THEN** Hub, Runtime และ Controller ไม่ยอมรับใบรับรองนั้น

### Requirement: Hub ลงทะเบียนกุญแจใหม่จากใบรับรองเท่านั้น
`POST /links` SHALL ลงทะเบียนกุญแจใหม่เป็น Controller ของ Member คนเดิมใน Workspace เดิม เฉพาะเมื่อใบรับรองเซ็นถูกต้องด้วยกุญแจของ Controller ที่ลงทะเบียนอยู่ของ Member คนเดียวกันใน Workspace เดียวกัน Hub SHALL เก็บใบรับรองไว้เป็น metadata และ SHALL ส่งต่อให้ Machine และ Controller ทุกตัวใน Workspace ที่ต่ออยู่ทันที error SHALL เป็น code ตาม ADR 0065

#### Scenario: Link สำเร็จ
- **WHEN** เครื่องเดิมส่งใบรับรองที่ถูกต้อง
- **THEN** Hub ลงทะเบียนกุญแจใหม่ เก็บใบรับรอง และเครื่องใหม่ผ่าน handshake ได้

#### Scenario: คนเซ็นไม่ใช่ Member คนนั้น
- **WHEN** ใบรับรองเซ็นด้วยกุญแจที่ไม่ได้ลงทะเบียน หรือเป็นของ Member อื่น หรือระบุ Workspace อื่น
- **THEN** Hub ตอบ `hub.link_invalid` และไม่มีอะไรถูกเขียน

#### Scenario: กุญแจใหม่มีเจ้าของแล้ว
- **WHEN** กุญแจใหม่ลงทะเบียนอยู่แล้วกับ Member อื่น หรือเป็นกุญแจที่เคยถูกถอน
- **THEN** Hub ตอบ `hub.key_taken` และไม่มีอะไรเปลี่ยน

### Requirement: Runtime เชื่อกุญแจใหม่จากลายเซ็นต่อกัน
Runtime SHALL เชื่อกุญแจใน `device.link` เป็นของ Member ที่ระบุ เฉพาะเมื่อกุญแจที่เซ็นเป็นกุญแจที่ Runtime เชื่ออยู่แล้วของ Member คนเดียวกัน และกุญแจใหม่ไม่อยู่ในรายชื่อห้าม Runtime SHALL NOT เชื่อกุญแจเพราะ Hub ลงทะเบียนไว้ Machine ที่ปิดอยู่ตอน Link SHALL ได้ใบรับรองจาก Hub ตอนต่อเข้ามาครั้งถัดไป ก่อนรับซองอื่น

#### Scenario: Machine ต่ออยู่
- **WHEN** Hub ส่งใบรับรองที่ถูกต้องมาขณะ Machine ต่ออยู่
- **THEN** Machine บันทึกกุญแจใหม่ และรับคำสั่งจากเครื่องใหม่ได้ทันที

#### Scenario: Machine ปิดอยู่ตอน Link
- **WHEN** Machine ต่อเข้ามาหลังมีการ Link
- **THEN** Machine ได้ใบรับรองจาก Hub บันทึกกุญแจใหม่ แล้วจึงรับซองจากเครื่องใหม่

#### Scenario: Hub ปลอมใบรับรอง
- **WHEN** Hub ส่งใบรับรองที่เซ็นด้วยกุญแจที่ Runtime ไม่เชื่อ หรือเซ็นโดย Member อื่น
- **THEN** Runtime ไม่เชื่อกุญแจนั้น และไม่ทำตามซองจากกุญแจนั้น

### Requirement: เครื่องใหม่ได้ Machine จากเครื่องเดิมโดยที่ Hub แก้ไม่ได้
หลัง Hub ลงทะเบียนกุญแจใหม่ เครื่องเดิม SHALL ส่ง `device.handoff` ถึง Member ของตัวเอง ซึ่งมี Workspace, Member, รายชื่อ Machine พร้อมกุญแจ ชื่อ และ Hub ของแต่ละเครื่อง และกุญแจที่ยังใช้งานของ Member พร้อมค่าพิสูจน์ที่คำนวณจากรหัสลับใน QR เครื่องใหม่ SHALL เชื่อรายชื่อนั้นเฉพาะเมื่อค่าพิสูจน์ถูกต้อง แล้ว SHALL ตอบ `device.linked` ที่เซ็นด้วยกุญแจใหม่ เครื่องเดิม SHALL ส่งซ้ำจนได้ `device.linked` หรือลิงก์หมดอายุ

#### Scenario: Link สำเร็จบนทั้งสองเครื่อง
- **WHEN** เครื่องใหม่ได้ `device.handoff` ที่ค่าพิสูจน์ถูกต้อง
- **THEN** เครื่องใหม่บันทึก Machine แสดงบนหน้าแรก และเครื่องเดิมแสดงว่า Link สำเร็จเมื่อได้ `device.linked`

#### Scenario: Hub สลับรายชื่อ Machine
- **WHEN** `device.handoff` มีค่าพิสูจน์ที่ไม่ตรงกับเนื้อใน
- **THEN** เครื่องใหม่ไม่บันทึกอะไร และยังรอต่อจนหมดเวลา

#### Scenario: เครื่องอื่นของ Member เห็น handoff
- **WHEN** Controller อีกเครื่องของ Member คนเดียวกันได้ `device.handoff`
- **THEN** เครื่องนั้นไม่ทำอะไร เพราะไม่ได้ถือรหัสลับ

### Requirement: เครื่องอื่นของ Member รู้ว่ามีการ Link
Controller ของ Member SHALL แจ้งเจ้าของเมื่อได้ใบรับรอง `device.link` ใหม่ที่ไม่ได้เซ็นเอง โดยบอกชื่อเครื่องใหม่และเครื่องที่ Link

#### Scenario: Link จากอีกเครื่อง
- **WHEN** มือถือ Link เบราว์เซอร์ ขณะที่ iPad ของ Member คนเดียวกันเปิดแอปอยู่
- **THEN** iPad แจ้งว่ามีเครื่องใหม่ถูก Link พร้อมชื่อเครื่องทั้งสอง

### Requirement: Machine ที่ Pair จากเครื่องไหนก็เชื่อทุกเครื่องของ Member
`pairing.claim` SHALL มีกุญแจอื่นที่ยังใช้งานของ Member ผู้ Pair ในส่วนที่เซ็น Machine ที่ Pair ใหม่ SHALL เชื่อกุญแจเหล่านั้นเป็นของ Member คนเดียวกัน Runtime ที่ไม่รู้จักช่องนี้ SHALL ยังเชื่อแค่กุญแจผู้ Pair ตามเดิม (ADR 0023)

#### Scenario: Pair Machine ใหม่จากเครื่องที่ Link มา
- **WHEN** เบราว์เซอร์ที่ Link จากมือถือ ทำ Pairing กับ Machine ใหม่
- **THEN** Machine ใหม่รับคำสั่งจากทั้งเบราว์เซอร์และมือถือ

### Requirement: เครื่องใหม่เห็น Task เดิม
Controller SHALL ส่ง `task.list` ถึงทุก Machine ตอนต่อเข้ามา Runtime SHALL ตอบ `task.listed` ด้วย Task ที่ Member ผู้ขอเปิดดูได้ (ADR 0060) พร้อม Agent ของแต่ละ Task และ Controller SHALL ใช้ `task.sync` ดึง event ของ Task ที่ยังไม่มีบนเครื่อง

#### Scenario: เปิดแอปครั้งแรกบนเครื่องที่ Link มา
- **WHEN** เครื่องใหม่ต่อ Machine ที่มี Task เดิมของ Member
- **THEN** Inbox แสดง Task เหล่านั้นพร้อมบทสนทนา

#### Scenario: Task ของ Member อื่น
- **WHEN** Runtime ตอบ `task.list`
- **THEN** รายการไม่มี Task ที่ Member ผู้ขอเปิดดูไม่ได้
