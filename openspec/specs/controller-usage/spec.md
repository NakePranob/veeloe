# controller-usage Specification

## Purpose
หน้า "การใช้ token" ใน Controller ที่แสดงยอดตามช่วง 1, 3, 7 หรือ 30 วัน เป็นกราฟต่อวัน พร้อมยอดตามเครื่องและ Agent งานที่ใช้ token มากที่สุด และแคชที่อ่านได้ตอน Machine ออฟไลน์ (ADR 0066)

## Requirements

### Requirement: หน้ารวมการใช้ token ตามช่วง 1, 3, 7 หรือ 30 วัน

Controller SHALL มีหน้า "การใช้ token" ที่เปิดจาก Workspace และ SHALL ให้เลือกช่วง 1, 3, 7 หรือ 30 วันของ Budget โดยค่าเริ่มต้นคือ 7 วันและจดจำค่าที่เลือกไว้บนเครื่อง หน้า SHALL ขอข้อมูลใหม่เมื่อเปิดและเมื่อเปลี่ยนช่วง และ MUST NOT แสดงตัวเลขเงินหรือเปอร์เซ็นต์ของ Budget ในมุมมองหลายวัน เพราะ Budget เป็นค่าของวันนี้

#### Scenario: เปิดครั้งแรก
- **WHEN** Owner เปิดหน้า "การใช้ token" ครั้งแรก
- **THEN** หน้าเลือกช่วง 7 วันและขอข้อมูลของ 7 วันนั้น

#### Scenario: เปลี่ยนเป็น 30 วันแล้วเปิดใหม่
- **WHEN** Owner เลือก 30 วันแล้วออกจากหน้า แล้วเปิดใหม่
- **THEN** หน้ายังเลือก 30 วันและขอข้อมูลช่วงเดิม

#### Scenario: ไม่มีตัวเลขเงิน
- **WHEN** หน้าแสดงยอดของทุกช่วง
- **THEN** ทุกตัวเลขเป็น token และไม่มีสกุลเงินหรือราคา

### Requirement: กราฟแท่งต่อวันและยอดรวมตาม Machine กับ Agent

หน้า SHALL แสดงกราฟแท่งหนึ่งแท่งต่อวันของ Budget ในช่วง และ SHALL แสดงยอดรวมต่อ Agent กับต่อ Machine โดยจัดกลุ่มตาม Machine แล้วตาม Agent ยอดของ Machine MUST เป็นผลรวมที่ใช้ไป ไม่ใช่เพดาน และ MUST NOT มีตัวหาร Budget แท่งที่ไม่มีข้อมูล SHALL เป็นช่องว่าง ไม่ใช่ศูนย์ ทุกแท่ง SHALL มีข้อความให้ screen reader อ่าน และวันที่ SHALL เริ่ม 04:00 ตามเวลาของ Machine

#### Scenario: Machine หนึ่งมีสอง Agent
- **WHEN** Machine หนึ่งมีสอง Agent ที่ใช้ token ในช่วง
- **THEN** หน้ามียอดรวมของ Machine และแถวของทั้งสอง Agent ใต้เครื่องนั้น

#### Scenario: วันที่ไม่มีข้อมูล
- **WHEN** วันหนึ่งในช่วงไม่มีคำตอบที่ถูกรายงาน `usage`
- **THEN** แท่งของวันนั้นเป็นช่องว่างและไม่ถูกวาดเป็นศูนย์

#### Scenario: แตะแถว Agent
- **WHEN** Owner แตะแถวของ Agent
- **THEN** แอปเปิดหน้าของ Agent นั้น

### Requirement: งานที่ใช้ token มากที่สุด

หน้า SHALL แสดง Task ที่ใช้ token มากที่สุด 10 อันในช่วง พร้อมชื่อ Agent และข้อความตัวอย่างของ Task จากฐานข้อมูลบนเครื่อง ถ้าไม่รู้จัก Task นั้น SHALL แสดงรหัสสั้น ๆ และเมื่อคำตอบมี Task เกิน 20 อัน ส่วนที่เหลือ SHALL ถูกรวมเป็น "อื่น ๆ"

#### Scenario: Task ที่รู้จัก
- **WHEN** Task ที่ใช้มากที่สุดมีอยู่ในฐานข้อมูลของ Controller
- **THEN** รายการแสดงข้อความตัวอย่างของ Task และชื่อ Agent

#### Scenario: Task ที่ไม่รู้จัก
- **WHEN** ประวัติอ้างถึง Task ที่ Controller ไม่มี
- **THEN** รายการแสดงรหัสสั้น ๆ ของ Task แทน

#### Scenario: Task เกิน 20 อัน
- **WHEN** คำตอบมี Task 20 อันและยังมียอดของ Task อื่นเหลือ
- **THEN** หน้ารวมส่วนที่เหลือเป็นแถว "อื่น ๆ" ไม่หายไปเงียบ ๆ

### Requirement: ข้อมูลแคช เวลาที่ได้ล่าสุด และการออฟไลน์

Controller SHALL แคชยอดรายวันต่อ Agent ไว้บนเครื่อง และ SHALL แสดงแคชนั้นพร้อมเวลาที่ได้ล่าสุดเมื่อ Machine ออฟไลน์หรือระหว่างรอคำตอบ MUST NOT ติดป้ายยอดของวันก่อนว่าเป็นของวันนี้ และ MUST NOT แสดงยอดเก่าเสมือนว่าสด คำตอบที่มี `request` ไม่ใช่คำขอล่าสุด SHALL ถูกทิ้ง

#### Scenario: เปิดตอนออฟไลน์
- **WHEN** Owner เปิดหน้าขณะ Machine ออฟไลน์และเคยได้ข้อมูลมาก่อน
- **THEN** หน้าแสดงยอดที่แคชไว้พร้อมเวลาที่ได้ล่าสุดและบอกว่า Machine ออฟไลน์

#### Scenario: คำตอบเก่ามาถึงช้า
- **WHEN** Owner เปลี่ยนช่วงวันที่ แล้วคำตอบของช่วงก่อนมาถึงทีหลัง
- **THEN** หน้าทิ้งคำตอบนั้นและยังแสดงของช่วงล่าสุด

#### Scenario: ยังไม่เคยได้ข้อมูล
- **WHEN** Owner เปิดหน้าครั้งแรกขณะ Machine ออฟไลน์
- **THEN** หน้าแสดงว่ายังไม่มีข้อมูลและบอกว่าต้องให้ Machine ออนไลน์

### Requirement: สิทธิ์และคำ

หน้า SHALL แสดงเฉพาะ Agent ที่ Member มี Manage (ADR 0059) ซึ่งใน v0.1 คือ Owner ทุกคน คำทุกคำ SHALL มีทั้งภาษาไทยและอังกฤษ (ADR 0065) และ code `usage.invalid_range` SHALL มีคำอธิบายใน `errors` ทั้งสองภาษา

#### Scenario: Agent ที่ไม่มี Manage
- **WHEN** Member ที่ไม่มี Manage ที่ Agent ตัวหนึ่งเปิดหน้า
- **THEN** Agent นั้นไม่ปรากฏในยอดรวมและรายการ

#### Scenario: ช่วงวันที่ผิด
- **WHEN** Machine ตอบ `usage.invalid_range`
- **THEN** หน้าแสดงคำอธิบายของ code นั้นในภาษาของ Owner
