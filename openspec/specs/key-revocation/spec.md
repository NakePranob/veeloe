# key-revocation Specification

## Purpose

กำหนดว่า Member ถอนกุญแจของ Controller เครื่องหนึ่งจากเครื่องอื่นของตัวเองอย่างไร เพื่อให้เครื่องที่หายหรือถูกขโมยสั่ง Agent ไม่ได้อีก ทั้งที่ Hub และ Runtime (ADR 0013, 0031)

## Requirements

### Requirement: หน้า เครื่องของฉัน แสดงทุกเครื่องของ Member
Controller SHALL มีหน้า เครื่องของฉัน ที่เปิดจาก Workspace แสดงเครื่องที่ยังใช้งานของ Member พร้อมชื่อเครื่อง เครื่องที่ Link และเวลาที่ Link หรือบอกว่าเป็นเครื่องแรก SHALL บอกว่าเครื่องไหนคือเครื่องนี้ และ SHALL แสดงเครื่องที่ถูกถอนแล้วแยกไว้ รายการ SHALL มาจากใบรับรองที่ลายเซ็นถูกต้องเท่านั้น เมื่อ Member มีเครื่องเดียว หน้านี้และหน้า Workspace SHALL เตือนให้ Link เครื่องที่สอง

#### Scenario: มีสองเครื่อง
- **WHEN** Member มีมือถือที่ทำ Pairing และเบราว์เซอร์ที่มือถือ Link
- **THEN** หน้านี้แสดงมือถือเป็นเครื่องแรก และเบราว์เซอร์ว่า Link โดยมือถือเมื่อไหร่

#### Scenario: มีเครื่องเดียว
- **WHEN** Member มีเครื่องที่ใช้งานอยู่เครื่องเดียว
- **THEN** แอปเตือนว่าถ้าเครื่องนี้หายต้องทำ Pairing ใหม่ที่ทุก Machine และพาไป Link เครื่องที่สอง

### Requirement: คำสั่งถอนเซ็นและระบุใบรับรองที่ยังเก็บ
ใบรับรอง `device.revoke` SHALL เซ็นด้วยกุญแจที่ยังใช้งานของ Member คนเดียวกัน และ SHALL ระบุ Workspace, Member, กุญแจที่ถอน, กุญแจที่เซ็น, เวลาที่เซ็น และรายชื่อกุญแจที่กุญแจดอกที่ถอนเคย Link และยังเก็บไว้ ใบรับรอง `device.link` อื่นที่เซ็นด้วยกุญแจที่ถอน SHALL ใช้ไม่ได้ ไม่ว่าจะลงเวลาไว้เมื่อไหร่ (ADR 0031) การถอน MUST ยืนยันตัวใหม่ตาม ADR 0012

#### Scenario: ถอนมือถือที่หาย
- **WHEN** เจ้าของถอนมือถือจากเบราว์เซอร์ และเลือกเก็บ iPad ที่มือถือเคย Link ไว้
- **THEN** มือถือใช้ไม่ได้อีก ส่วน iPad กับเบราว์เซอร์ยังใช้ได้

#### Scenario: ไม่ได้เลือกเก็บ
- **WHEN** เจ้าของถอนกุญแจโดยไม่เลือกเก็บเครื่องที่กุญแจนั้นเคย Link
- **THEN** เครื่องเหล่านั้นหลุดด้วย และหน้า เครื่องของฉัน บอกก่อนยืนยันว่าเครื่องไหนจะหลุด

#### Scenario: คนร้ายลงเวลาย้อนหลัง
- **WHEN** หลังถอน มีใบรับรอง `device.link` จากกุญแจที่ถอนซึ่งลงเวลาก่อนการถอน และไม่อยู่ในรายชื่อที่เก็บ
- **THEN** Hub และ Runtime ไม่เชื่อกุญแจในใบรับรองนั้น

#### Scenario: ยกเลิกการยืนยันตัว
- **WHEN** เจ้าของยกเลิกการยืนยันตัวตอนถอน
- **THEN** ไม่มีอะไรถูกเซ็นหรือส่งออก

### Requirement: เครื่องสุดท้ายถอนไม่ได้
การถอนที่ทำให้ Member ไม่เหลือกุญแจที่ใช้งานเลย SHALL ถูกปฏิเสธที่ Controller, Hub และ Runtime Controller SHALL บอกทางออกคือ Link เครื่องอื่นก่อน หรือรัน `veeloe unpair` ที่ Machine แล้วทำ Pairing ใหม่ (ADR 0031, 0035)

#### Scenario: ถอนเครื่องเดียวที่มี
- **WHEN** Member ที่มีเครื่องเดียวกดถอนเครื่องนั้น
- **THEN** แอปไม่เซ็นอะไร และบอกทางออกทั้งสองทาง

#### Scenario: Hub ส่งคำสั่งถอนเครื่องสุดท้ายมา
- **WHEN** Runtime ได้ `device.revoke` ที่ถ้าทำตามแล้ว Member ไม่เหลือกุญแจ
- **THEN** Runtime ไม่ทำตาม และยังเชื่อกุญแจเดิม

### Requirement: Hub ตัดสายทันที
`POST /revocations` SHALL ตรวจลายเซ็นกับกุญแจของ Controller ที่ลงทะเบียนอยู่ของ Member คนเดียวกัน แล้ว SHALL ลบกุญแจที่ถอนและกุญแจที่หลุดตาม ปิดสายของกุญแจเหล่านั้นที่ต่ออยู่ด้วย close code ที่บอกว่าถูกถอน เก็บคำสั่งถอนเป็น metadata และส่งต่อให้ Machine และ Controller ทุกตัวใน Workspace ที่ต่ออยู่ ทั้งหมด SHALL สำเร็จหรือไม่เกิดขึ้นพร้อมกัน กุญแจที่ถูกถอน SHALL ผ่าน handshake ไม่ได้อีก

#### Scenario: เครื่องที่ถูกถอนต่ออยู่
- **WHEN** Hub รับคำสั่งถอนที่ถูกต้องขณะเครื่องนั้นต่ออยู่
- **THEN** สายของเครื่องนั้นถูกปิดทันที และต่อใหม่ไม่ได้

#### Scenario: คนเซ็นเป็นของ Member อื่น
- **WHEN** คำสั่งถอนเซ็นด้วยกุญแจที่ไม่ได้ลงทะเบียน หรือของ Member อื่น
- **THEN** Hub ตอบ `hub.revocation_invalid` และไม่มีอะไรเปลี่ยน

### Requirement: Runtime จดคำสั่งถอนลงรายชื่อห้ามของตัวเอง
Runtime SHALL ทำตาม `device.revoke` ที่เซ็นถูกต้องโดยกุญแจที่เชื่ออยู่ของ Member คนเดียวกัน โดยเลิกเชื่อกุญแจที่ถอนกับกุญแจที่หลุดตาม และ SHALL จดกุญแจเหล่านั้นลงรายชื่อห้ามที่อยู่รอดข้ามการเริ่มใหม่ กุญแจในรายชื่อห้าม SHALL NOT กลับมาเชื่อได้อีกจากใบรับรองใด Machine ที่ปิดอยู่ตอนถอน SHALL ได้คำสั่งถอนจาก Hub ตอนต่อเข้ามา ก่อนรับซองอื่น Runtime SHALL เชื่อคำสั่งถอนเพราะลายเซ็น ไม่ใช่เพราะ Hub บอก

#### Scenario: ซองที่มาหลังถอน
- **WHEN** ซองที่เซ็นด้วยกุญแจที่ถูกถอนมาถึง Runtime หลังทำตามคำสั่งถอน รวมถึงซองที่ค้างในคิวขาออกของเครื่องนั้น
- **THEN** Runtime ทิ้งซองนั้นเพราะไม่รู้จักกุญแจ

#### Scenario: Machine ปิดอยู่ตอนถอน
- **WHEN** Machine ต่อเข้ามาหลังมีการถอน
- **THEN** Machine เลิกเชื่อกุญแจนั้นก่อนรับซองใด

#### Scenario: ใบรับรองเก่าถูกส่งซ้ำ
- **WHEN** Hub ส่ง `device.link` ของกุญแจที่อยู่ในรายชื่อห้ามมาอีก
- **THEN** Runtime ไม่เชื่อกุญแจนั้น

### Requirement: ถอนเครื่องที่ถืออยู่ได้
เจ้าของ SHALL ถอนกุญแจของเครื่องที่ถืออยู่ได้เมื่อยังเหลือเครื่องอื่น เมื่อ Hub ยอมรับแล้ว เครื่องนั้น SHALL ลบกุญแจและข้อมูลบนเครื่องแล้วกลับไปหน้าสร้างกุญแจ เครื่องที่ถูกถอนจากเครื่องอื่น SHALL ทำแบบเดียวกันเมื่อ Hub ปิดสายด้วย close code ที่บอกว่าถูกถอน

#### Scenario: ยกเครื่องให้คนอื่น
- **WHEN** เจ้าของถอน iPad จาก iPad เอง ขณะที่ยังมีมือถืออยู่
- **THEN** iPad กลับไปหน้าสร้างกุญแจโดยไม่มี Machine หรือ Task ค้าง และมือถือยังใช้ได้

#### Scenario: เครื่องที่หายเปิดขึ้นมา
- **WHEN** มือถือที่ถูกถอนจากเบราว์เซอร์เปิดแอปและต่อ Hub
- **THEN** มือถือบอกว่าเครื่องนี้ถูกถอนแล้ว ลบข้อมูลบนเครื่อง และสั่งงานใดไม่ได้
