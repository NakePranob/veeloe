ทำงานยังไง: Veeloe Agent vs OpenClaw

Veeloe = Agent เป็นโปรเซสบน Machine ของเรา · OpenClaw = Gateway บน host + tool execution ย้ายเข้า container เมื่อเปิด sandbox

Veeloe — Agent บน Machine ของ Owner

1 Agent = 1 worker (Rust) · 1 คิว · 1 Workdir · รันบนเครื่องจริง ไม่ต้องมี Docker
1
Controller (แอป) → Hub

Member ส่งข้อความ/คำสั่งที่เซ็นแล้ว; Hub เป็นแค่ตัวส่งต่อ ไม่เก็บเนื้อหา

2
Supervisor บน Machine

ตรวจลายเซ็น, ถือ Provider key, เป็น proxy ของ LLM, คุม Budget/usage, เปิด–ปิด worker

3
Worker = Agent

Harness ประกอบ prompt (คำสั่ง + MEMORY.md + Skills + tools) → เรียก LLM ผ่าน proxy → เรียก tool → บันทึก event ลง tasks.db

4
Tools

bash, read/write/edit/glob/grep, memory, send_file — ทุก tool ใช้ path resolver ชุดเดียวกับ sandbox

5
Sandbox ระดับ OS

Seatbelt (macOS) / bwrap (Linux): อ่าน–เขียนเฉพาะ Workdir + Project ที่ได้งาน; อ่าน Library/system; deny home/secrets
WorkdirProjectLibrary ตามสิทธิ์home/secrets

6
Memory

MEMORY.md ที่ Workdir (≤4,000) + memory/YYYY-MM-DD.md; tool memory เขียน, flush ก่อน compaction

OpenClaw — Gateway บน host + sandbox container

Gateway อยู่บน host เสมอ · sandbox ปิดเป็นค่าเริ่มต้น · เปิดเมื่อต้องการ
1
ช่องทาง (Telegram/Web/ฯลฯ)

ข้อความเข้าหา agent session ใน Gateway — ไม่มี Hub แยกแบบ Veeloe

2
Gateway + agent session

ประกอบ context จาก workspace (AGENTS.md, MEMORY.md, USER.md, memory/*.md) และเรียกโมเดล

3
Tool execution

ถ้าไม่เปิด sandbox: shell/file tools รันบน host ตาม permission mode + approval

4
Sandbox (ถ้าเปิด)

ย้าย shell/file read-write เข้า container: Docker (ค่าเริ่มต้น), Podman, SSH, OpenShell, Crabbox; workspace mount ที่ /workspace; จำกัด network/resources ได้

5
นโยบายแยกจาก sandbox

tool allow/deny + permission mode (deny/allowlist/ask/auto/full); tools.elevated เป็นทางออกไปรันนอก sandbox

6
Memory

ไฟล์ใน workspace: MEMORY.md, memory/YYYY-MM-DD.md, USER.md; index + memory_search/memory_get + dreaming/flush

เรื่องVeeloeOpenClaw

ขอบเขตไฟล์Workdir + Project ที่ได้งาน + Library ตามสิทธิ์; deny home/secretsworkspace ที่ mount เข้า container (กำหนด workspaceAccess ได้) + tool policy
ApprovalAllowlist/Approval เป็นนโยบาย; sandbox เป็นด่านจริงpermission mode + exec approvals; sandbox เป็นอีกชั้น

สรุป: Veeloe เน้นเบาและอยู่ในเครื่อง (OS sandbox) · OpenClaw เน้นแยกงานหนักออกเป็น container — ทั้งคู่ถือว่า “sandbox ≠ approval” และ approval ไม่ได้ให้สิทธิ์ไฟล์
