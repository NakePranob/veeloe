Veeloe — องค์ประกอบของ Agent และการทำงาน

Agent หนึ่งตัว = worker หนึ่งโปรเซส · หนึ่งคิว · หนึ่ง Workdir · sandbox = ขอบเขตที่ OS บังคับ ไม่ใช่ prompt หรือ approval

Supervisor (Runtime บน Machine)

  • hub-link และตรวจลายเซ็นทุกซอง
  • ทะเบียน Agent + กุญแจเครื่อง
  • ถือ Provider key และเป็น proxy ของ LLM
  • Budget / usage / log
  • เริ่ม–หยุด–restart worker, service

Hub

ส่งต่อซองที่เซ็นแล้วระหว่างแอปกับ Machine — ไม่เก็บเนื้อหา Task

Controller (แอปของ Member)

สร้าง/แก้ Agent, ส่งข้อความ, ตอบ Approval, Stop, ตั้ง Schedule / Idle Work / Watch

Trigger ที่ Member เซ็นไว้

ข้อความใน Task · Schedule · Idle Work · Watch

ทุกอย่างเข้าลูปเดียวกันผ่าน trigger ภายในของ supervisor (ADR 0067) — รอบที่ Agent ไม่ว่างจะถูกข้าม ไม่ต่อคิว

Sandbox คืออะไร

ขอบเขตที่ OS บังคับ (macOS Seatbelt / Linux bwrap) ว่า Agent แตะไฟล์หรือเน็ตอะไรได้ — ไม่ใช่ prompt และไม่ใช่ Approval

ปัจจุบันบังคับกับทุกคำสั่งที่ worker เปิด; tool ใช้ resolver ชุดเดียวกัน. เป้าหมาย ADR 0008 คือครอบทั้ง worker

AGENT (worker process)
sandbox และสิทธิ์ไฟล์ถูกกำหนดต่อ Turn

Identity & settings

  • ชื่อ · Character · Provider / model
  • Allowlist · Approval timeout
  • Budget ต่อวัน
  • git name/email · cache ในบ้านจำลอง

Tools

bash · read · write · edit · glob · grep · memory · send_file

คำสั่งนอก Allowlist → ขอ Approval จากคนที่มี Approve; Approval ไม่ได้ให้สิทธิ์นอก sandbox

Harness — ลูปของ Turn

1

รับ triggerข้อความ Member หรือ trigger ภายใน (Schedule / Idle / Watch) พร้อมเจ้าของและเวลาที่ควรเริ่ม

2

ประกอบ promptคำสั่ง Agent + MEMORY.md (pin ไว้ทั้ง Turn) + รายชื่อ Skill + tools ที่มี

3

เรียก LLM ผ่าน proxy ของ SupervisorAgent ไม่เคยเห็น Provider key; ทุก token ถูกนับเข้า Budget

4

เรียก tool → Allowlist / Approval → Sandboxshell รันใน Seatbelt; ไฟล์อยู่ใน roots ที่กำหนด; เน็ตตาม Egress

5

บันทึก event ลง tasks.dbappend-only: ข้อความ, LLM, tool call/ผล, Approval, Stop, Turn เริ่ม/จบ

6

จบ Turnตอบหรือจบเงียบ · ใกล้เต็ม context → flush Memory + compaction · push ถ้ามีเรื่องต้องบอก

Workdir

  • ไฟล์งานของ Agent
  • MEMORY.md ≤ 4,000 ตัวอักษร
  • memory/YYYY-MM-DD.md โน้ตรายวัน
  • .home / tmp (cache ของ toolchain)

Memory & Skills

memory tool เขียน MEMORY.md / โน้ตรายวัน (โค้ดคุมที่อยู่และเพดาน); flush ก่อน compaction เขียนให้เอง

Skill: อ่าน SKILL.md ได้อย่างเดียว; ติดตั้ง/แก้โดย Member ที่มี Manage

Sandbox boundary (Seatbelt / OS)

อ่าน+เขียน Workdirอ่าน+เขียน Project ตอนได้งานLibrary: อ่านตามสิทธิ์ · เขียนเฉพาะ writerอ่าน system/SDKdeny home จริง / secrets / docker socket

path นอก roots ล้มเหลวแม้ Owner กดอนุมัติ — Approval ไม่ใช่ sandbox; เขียนนอก Workdir/Project/Library ที่เป็น writer ไม่มี

Project (แยกจาก Agent)

repos/<name> + worktree + wiki
เห็นเฉพาะ Task ที่ Agent ได้รับมอบหมาย

ระหว่างงาน Project: Workdir เป็น read-only

Library

ความรู้ร่วมบน Machine + wiki ของ Project

อ่าน (ตามสิทธิ์)เขียน (writer คนเดียว)

สิทธิ์เป็นราย Agent ต่อ Library; Project wiki ตั้ง Entry เป็น writer

ระบบ / toolchain

/usr /bin /System /SDK — อ่านและรันได้ แต่เขียนไม่ได้

ห้ามตลอด

~/.ssh · ~/.aws · ~/.config/gh · ~/.veeloe · docker socket · home จริง

Network

ออกได้เฉพาะโดเมนใน Egress ผ่าน proxy ของ supervisor

เรียก / ไหลของงาน เข้าถึงตามสิทธิ์ (อ่าน · เขียนเฉพาะ writer) deny Agent ไม่เห็น Provider key · ทุก tool call อยู่ใน Task log
