# สำรองด้วย veeloe backup ที่ไม่รวมความลับ และกู้คืนได้เฉพาะใน Workspace เดิม

ทุกอย่างของ Agent อยู่บน Machine ที่ `<VEELOE_HOME>` (ADR 0032) ถ้าดิสก์เสีย Agent, Workdir, Memory, Skill, Library และประวัติ Task หายหมด Controller มีแค่สำเนา event ของ Task (ADR 0021) และการคัดลอกโฟลเดอร์ตรงๆ ระหว่างที่ระบบทำงานอาจได้ SQLite ที่เสีย Runtime จึงมีคำสั่ง `veeloe backup <ไฟล์ปลายทาง>` ซึ่งทำสำเนา `tasks.db` ด้วย `VACUUM INTO` ระหว่างที่ระบบยังทำงาน แล้วรวมกับไฟล์อื่นเป็นไฟล์เดียว backup ไม่รวมความลับ คือ key ของ Provider, token ของ bot, credential ของ Connector และกุญแจของ Machine จึงไม่ต้องเข้ารหัสด้วยรหัสผ่านที่คนจะลืม การตั้งให้รันทุกคืนใช้ cron, launchd หรือเครื่องมือที่มีอยู่แล้วอย่าง Time Machine หรือ restic

`veeloe restore <ไฟล์>` ใช้บนเครื่องใหม่ที่ยังไม่ได้ Pairing หลังจากนั้น Owner ทำ Pairing ตามปกติ ถ้า Workspace ตรงกับใน backup แอปถามว่าเครื่องนี้แทน Machine เดิมหรือเปล่า ถ้าใช่ Agent, Grant, Project และประวัติกลับมาครบ และกุญแจของ Machine เดิมถูกถอน กันไม่ให้มีสองเครื่องที่เป็นตัวเดียวกัน Schedule กับ Channel ยังใช้ได้เพราะกุญแจของ Member ที่เซ็นไว้ไม่ได้ถูกถอน ส่วนความลับต้องใส่ใหม่ทั้งหมด backup ของ Workspace อื่นใช้ไม่ได้ การย้ายข้าม Workspace ต้องใช้คำสั่งปล่อยตาม ADR 0035

## Considered Options

- **ไม่มีคำสั่ง ให้เจ้าของเครื่องสำรองเอง**: ไม่ต้องเขียนโค้ด แต่คนที่คัดลอกโฟลเดอร์เองจะได้ `tasks.db` ที่เสียโดยไม่รู้ตัวจนถึงวันที่ต้องกู้
- **รวมความลับไว้ใน backup แล้วเข้ารหัสด้วยรหัสผ่าน**: กู้แล้วใช้ได้ทันที แต่ถ้าลืมรหัสผ่าน backup ก็ใช้ไม่ได้ ถ้ารหัสอ่อน ไฟล์ที่หลุดจะเปิดเผยทุก key
- **สำรองขึ้น cloud ผ่าน Hub อัตโนมัติ**: ไม่ต้องมีใครจำ แต่ขัดกับ ADR 0005 จนกว่าจะมี E2E หลังจากนั้นทำเป็น backup ที่เข้ารหัสแล้วฝากไว้ได้

## Consequences

- backup ยังมีประวัติ Task และไฟล์งาน ต้องเก็บไว้ในที่ปลอดภัย
- สิ่งที่เกิดหลัง backup ครั้งล่าสุดหายไป Controller มี event ของ Task อยู่ ถ้าต้องการวันหลังให้ส่ง event ที่ขาดกลับไปที่ Runtime ได้ แต่ไม่อยู่ใน v0.1
- หลังกู้ต้อง login Connector และใส่ key ของ Provider กับ token ของ bot ใหม่
