# ห้องส่วนตัวต่อคน (private threads) กับ Agent

วันนี้ Member ที่มี Use เห็นได้ทุก Task ของ Agent ตัวนั้น ไม่ว่าใครเป็นคนเริ่ม (ADR 0010, ADR 0031) เหตุผลเดิมคือทุก Task ใช้ Workdir เดียวกัน การซ่อน Task จึงเป็นความเป็นส่วนตัวแค่ครึ่งเดียว และคนที่ตอบ Approval ก็ต้องเห็นว่าคุยอะไรกันมา เจ้าของตัดสินใจแล้วว่า veeloe อยากได้ห้องส่วนตัวแบบ Grok คือ bot ตัวเดียวที่แชร์กัน แต่ละคนมีแชตส่วนตัวของตัวเองที่คนอื่นอ่านไม่ได้ (ดู docs.x.ai shared-bots) จึงออก ADR ฉบับนี้เพื่อกลับกฎ Use-sees-all เฉพาะห้องส่วนตัว

Member แต่ละคนมีห้องส่วนตัว (private thread) กับ Agent ได้ ทั้งแชตตรงแบบ 1:1 และห้องย่อยส่วนตัวของคนนั้นในบริบทกลุ่ม (group context) ตามความเหมาะสม Member ที่มี Use, Manage หรือ Owner จะเห็นห้องส่วนตัวของคนอื่นไม่ได้อีกต่อไป ข้อนี้กลับกฎ Use-sees-all เฉพาะห้องส่วนตัวเท่านั้น ส่วนงานนอกห้องส่วนตัวยังเห็นได้เหมือนเดิม Agent เก็บความจำแยกต่อห้อง (per-thread memory) ตาม ADR 0036 ส่วนความรู้ที่ใช้ร่วมกันทั้งทีมยังเข้า Library ตามเดิม โดยมีนักเขียนคนเดียวตาม ADR 0037

ห้องของ Project ยังแชร์กันทั้งห้องเหมือนเดิม ไม่เปลี่ยน ADR 0045 และ ADR 0046 ห้องส่วนตัวมีไว้คุยกับ Agent โดยตรง ไม่ใช่ที่ทำงานของ Project ถ้าเรื่องไหนเป็นงาน Project ให้คุยใน Task ของ Project ที่ทุกคนที่มีสิทธิ์เห็นได้ ไม่ใช่ในห้องส่วนตัว

Approval ที่ขอจากห้องส่วนตัวยังส่งไปหาคนที่มี Approve ที่ Agent ตัวนั้นตาม ADR 0044 เหมือนเดิม แต่เนื้อหา Task ยังซ่อนจากคนที่ไม่ใช่คนอนุมัติ คนอนุมัติเห็นเฉพาะสิ่งที่ต้องใช้ตัดสินใจ (approval payload) ไม่เห็นประวัติคุยทั้งหมดในห้องส่วนตัว เมื่อตอบ Approval เสร็จก็กลับไปไม่เห็นอะไรต่อ

ตารางเลือกผู้รับ push ยังใช้ตารางเดิมตาม ADR 0044 แต่เนื้อหายังซ่อนจนกว่าจะมี E2E (ADR 0005) คือมีแต่หัวเรื่องว่าเรื่องอะไรรออยู่ ไม่มีเนื้อหาข้อความติดไป

Owner ยังเห็นข้อมูลบริหารของ Agent ได้ คือ config ของ Agent, Grant ว่าใครมีสิทธิ์อะไร (ADR 0010, ADR 0034) และการใช้ budget/token (ADR 0043, ADR 0052) แต่เห็นเนื้อหาในห้องส่วนตัวของคนอื่นไม่ได้ เหมือน Owner ของ Grok ที่จัดการ shared bot ได้แต่อ่านแชตส่วนตัวของคนอื่นไม่ได้

งานเก่าที่มีอยู่แล้วยังเห็นได้เหมือนเดิมทั้งหมด ไม่มีการซ่อนย้อนหลัง เฉพาะห้องใหม่ที่เปิดหลัง ADR นี้มีผลเท่านั้นที่เป็นห้องส่วนตัว งานที่ย้ายเข้าห้องส่วนตัวไม่ได้ เพราะประวัติเดิมเคยมีคนอื่นเห็นแล้ว

## Considered Options

- **Use เห็นทุก Task เหมือนเดิม ไม่มีห้องส่วนตัว (status quo)**: ง่ายสุด ไม่ต้องแก้ Runtime ที่คัด event ให้ Controller ของใคร (ADR 0031) แต่ไม่มีความเป็นส่วนตัวเลย ใครคุยอะไรกับ Agent ทุกคนที่มี Use เห็นหมด
- **ติดป้าย visibility ตอนเริ่ม Task ว่าแชร์หรือส่วนตัว**: ยืดหยุ่นกว่า คนสั่งเลือกเองทุกครั้ง แต่ต้องมีหน้าเลือกทุกครั้งที่เริ่มคุย และคนลืมติดป้ายส่วนตัวก็หลุดอยู่ดี แถม Task ที่เริ่มแชร์แล้วอยากซ่อนทีหลังทำไม่ได้เพราะประวัติเคยมีคนเห็นแล้ว
- **เอาแบบ Grok ทั้งตัว แม้แต่คนอนุมัติก็เห็นแค่ approval payload**: ความเป็นส่วนตัวสูงสุด คนอนุมัติเห็นเฉพาะสิ่งที่ต้องตัดสินใจ ไม่เห็นบริบทอื่นเลย แต่คนอนุมัติอาจตัดสินใจผิดเพราะไม่เห็นเบื้องหลัง จึงเลือกทางกลาง คือคนอนุมัติเห็น payload ที่ต้องใช้ตัดสินใจ แต่ไม่เห็นประวัติคุยทั้งหมด

## Consequences

- Member ที่มี Use, Manage หรือ Owner เห็นห้องส่วนตัวของคนอื่นไม่ได้อีกต่อไป เฉพาะงานนอกห้องส่วนตัวยังเห็นได้เหมือนเดิม (ADR 0010, ADR 0031)
- ห้องของ Project มีแบบเดียวคือห้องกลุ่ม (เจ้าของตัดสิน 2026-11-01) ไม่มีห้องส่วนตัวใน Project งานส่วนตัวคุยในห้องส่วนตัวตาม ADR นี้แล้วเอาผลเข้าห้องกลุ่มเมื่อพร้อม ส่วน Project ที่มีสมาชิกคนเดียวเป็นห้องส่วนตัวโดยสิทธิ์อยู่แล้ว ไม่ต้องมีห้องแบบที่สอง
- Approval จากห้องส่วนตัวยังส่งหาคนที่มี Approve (ADR 0044) แต่คนอนุมัติเห็นเฉพาะ approval payload ไม่เห็นประวัติคุยทั้งหมด และคนที่ไม่ใช่คนอนุมัติไม่เห็นอะไรเลย
- push ยังใช้ตารางเดิม (ADR 0044) แต่ไม่มีเนื้อหาจนกว่าจะมี E2E (ADR 0005)
- Owner เห็นได้แค่ config, Grant (ADR 0010, ADR 0034) และข้อมูลใช้ budget (ADR 0043, ADR 0052) แต่เห็นเนื้อหาห้องส่วนตัวของคนอื่นไม่ได้
- งานเก่ายังเห็นเหมือนเดิมทั้งหมด ไม่ซ่อนย้อนหลัง เฉพาะห้องใหม่หลัง ADR นี้มีผลที่เป็นห้องส่วนตัว
- Entry ประสานงาน Project ลำบากขึ้น เพราะมองไม่เห็น side-chat ส่วนตัวของสมาชิก จึงต้องให้สมาชิกลิงก์หรือคัดส่วนที่เกี่ยวข้องมาแปะใน Task ของ Project เอง (ADR 0045)
- สมาชิกอาจใช้ห้องส่วนตัวสั่ง Agent ส่งข้อมูลออกนอก (exfiltration) รับได้เพราะ Egress ยังแยกต่อ Agent เหมือนเดิม ไม่เปลี่ยน (ADR 0029)
- ค้นหาข้ามห้อง (task search ตาม ADR 0036) เห็นเฉพาะห้องของตัวเอง ห้องคนอื่นไม่ขึ้นผลค้นหา
- Backup มีเฉพาะห้องของตัวเอง (ADR 0051) กู้คืนแล้วไม่เห็นห้องของคนอื่น และงานจาก Channel ยังทำในนามของ Member ที่ผูก Channel เหมือนเดิม (ADR 0028)
