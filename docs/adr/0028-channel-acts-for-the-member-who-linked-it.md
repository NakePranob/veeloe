# Agent รับงานจากแชตภายนอกผ่าน Channel และทำในนามของ Member ที่ผูก Channel นั้น

Hermes และ OpenClaw ให้ Agent คุยผ่าน Telegram ได้ เราต้องการมากกว่านั้น คือเอา Agent เข้ากลุ่มไปทำงานให้คนในกลุ่มที่ไม่ได้เป็น Member ได้ Channel คือแชตภายนอก เช่น กลุ่ม Telegram ที่ Member ซึ่งมี Manage ที่ Agent ตัวนั้นผูกไว้และเซ็น (ADR 0006) แบบเดียวกับ Schedule (ADR 0027) คือเป็นของที่ Member เซ็นทิ้งไว้ แล้ว Runtime ใช้เปิด Task เองโดยไม่ต้องเซ็นทีละข้อความ งานทุกอย่างที่มาจากแชตทำในนามของ Member ที่ผูก ระบบจึงตรวจ Use ของคนนั้น (ADR 0010) Task ขึ้นใน Inbox ของคนนั้น และค่า token ก็ไปตกที่ key ของ Provider ที่ลูกค้าใส่ไว้ (ADR 0001) คนในแชตไม่ได้เป็น Member ชื่อของคนที่พิมพ์เก็บไว้เป็นแค่ข้อมูล และทุกคนในแชตมีอำนาจเท่ากัน คือทำได้เท่าที่ Allowlist ของ Agent ปล่อย

ข้อความที่เรียก Agent เปิด Task ใหม่ ส่วนข้อความที่ตอบกลับคำตอบของ Agent คุยต่อใน Task ของคำตอบนั้น เพราะ Task คือบทสนทนาหนึ่งเรื่อง และ privacy mode ของ Telegram ส่งให้ bot เฉพาะข้อความสองแบบนี้อยู่แล้ว Agent แต่ละตัวมี bot ของตัวเองหนึ่งตัว ชื่อกับรูปของ bot จึงเป็นตัว Agent เลย supervisor ถือ token ของ bot ไว้ ไม่ให้ worker อ่านได้ เพราะคนในแชตอาจหลอก Agent ให้บอก token แล้วเอาไปปลอมเป็น bot และ supervisor ดึงข้อความจาก Telegram ด้วย long polling ซึ่งเป็นสายขาออกแบบเดียวกับที่ต่อ Hub (ADR 0001) ข้อความจากแชตจึงไม่ผ่าน Hub (ADR 0005) และเพราะ Agent อยู่บน Machine เดียวตลอด (ADR 0002) token หนึ่งตัวจึงมีคนดึงข้อความแค่ที่เดียว ซึ่งตรงกับที่ Telegram บังคับ bot ตัวเดียวอยู่ได้หลายแชต แต่แต่ละแชตต้องผูกแยกกัน แชตที่ไม่ได้ผูกไม่ได้คำตอบ

คำตอบของ Agent เข้าแชตได้ตรงๆ ทางนี้จึงเป็นทางส่งข้อมูลออกที่ Egress กันไม่ได้ อะไรที่ Agent อ่านได้ คนในแชตก็ขอได้หมด และ Allowlist ก็กันไม่ได้เพราะ Agent ที่โดนหลอกเลี่ยงมันได้ (ADR 0030) Agent ที่มี Channel จึงอ่านไฟล์ได้แค่ใน Workdir ของตัวเองกับ Library ที่ได้สิทธิ์ (ADR 0037) มี Egress ของตัวเอง (ADR 0029) และอยู่ใน Team ไม่ได้ ห้ามทั้งสองทาง คือ Agent ในทีมผูก Channel ไม่ได้ และ Agent ที่มี Channel เข้าทีมไม่ได้ Approval ของงานจาก Channel ไปที่ Controller ของ Member ที่มี Approve เหมือนงานอื่น คนในแชตเห็นแค่ว่ากำลังรออนุมัติ งานจาก Channel ต่อคิวเดียวกับงานอื่น (ADR 0011) bot บอกลำดับคิวในแชต และ Member ตั้งเพดานจำนวนงานที่รอได้ต่อ Channel ถ้าเต็มแล้ว bot ตอบว่างานเต็มและไม่เปิด Task ใหม่ Channel หยุดทันทีเมื่อกุญแจที่เซ็นมันถูกถอน (ADR 0031)

## Considered Options

- **คนในแชตแต่ละคนมีตัวตนและสิทธิ์ของตัวเอง**: แยกได้ว่าใครสั่ง deploy ได้และใครถามได้อย่างเดียว แต่ต้องมีตัวตนแบบใหม่นอกจาก Member และ ADR ทุกตัวที่พูดถึง Member ต้องเพิ่มกรณีของคนนอก ถ้าอยากแยกสิทธิ์ ให้ใช้ Agent สองตัวกับสองแชต
- **ทั้งแชตเป็น Task เดียว**: Agent เห็นว่าก่อนหน้านี้ใครถามอะไร แต่หลายเรื่องปนกัน Task ยาวจนเกิน context และต้องมีคำสั่งล้างแบบ `/new` ของ Hermes กับ OpenClaw ส่วนเรื่องที่ต้องจำข้ามกัน Agent ก็จดไว้ใน Workdir ได้อยู่แล้ว
- **bot ตัวเดียวต่อ Machine แล้วส่งต่อให้ Agent แต่ละตัว**: สร้าง bot ครั้งเดียว แต่ทุก Agent ใช้ชื่อเดียวกันในแชต คนในแชตต้องพิมพ์บอกว่าจะคุยกับตัวไหน และ Character ไม่มีที่แสดง
- **กดอนุมัติในแชตได้ แบบ `/approve` ของ Hermes**: Hermes ทำได้เพราะแชตนั้นมีเจ้าของคนเดียว ในกลุ่ม คนที่ขอเองก็กดอนุมัติตัวเองได้ ถ้าจะจำกัดให้เฉพาะ Member ก็ต้องผูกบัญชี Telegram เข้ากับ Member แล้วการอนุมัติจะไม่ได้เซ็นด้วยกุญแจ ใครยึดบัญชี Telegram ได้ก็อนุมัติได้
- **ให้ Agent ที่มี Channel อยู่ใน Team ได้ แล้วเตือนแทน**: คนในแชตสั่งงานทั้งทีมได้ แต่แม้ ADR 0026 จะให้อ่าน Workdir ของเพื่อนร่วมทีมได้เฉพาะใน Task ของทีม Workdir ของ Agent ตัวนี้ก็ยังเป็นทางเชื่อมสองฝั่ง ผลงานของทีมที่ลงไว้ในนั้นรั่วเข้าแชตได้ และคนในแชตฝากไฟล์ที่ฝังคำสั่งไว้ให้เพื่อนร่วมทีมเปิดอ่านได้ ซึ่งเท่ากับใช้ Allowlist ของ Agent ที่สิทธิ์มากกว่า นอกจากนี้คิวของทีมกับของแชตก็ขวางกัน ถ้าจำเป็นจริง ให้ออกแบบ Channel ที่ผูกกับ Team ทั้งทีมแยกต่างหาก
- **ไม่มีเพดานคิว**: ไม่ต้องมีค่าให้ตั้ง แต่คนในแชตที่ส่งรัวๆ จะทำให้คิวยาวไม่จบ และค่า token ของ Member พุ่งโดยไม่รู้ตัว
- **ให้ Agent ทำหลาย Turn พร้อมกันเมื่องานอ่านอย่างเดียว**: ขัดกับ ADR 0011 และรู้ล่วงหน้าไม่ได้ว่า Turn ไหนจะไม่เขียนไฟล์

## Consequences

- ADR 0006 มีข้อยกเว้นเพิ่มหนึ่งข้อ คือข้อความในแชตของ Channel ที่ไม่ได้เซ็นทีละข้อความ ส่วนตัว Channel ยังต้องเซ็น
- ระหว่างที่งานจากแชตรอ Approval คนอื่นในแชตต้องรอตามไปด้วย (ADR 0011) Agent ที่ใช้กับ Channel ควรตั้งเวลาหมดอายุของ Approval ให้สั้น ซึ่งตั้งต่อ Agent ได้อยู่แล้ว
- Member ต้องสร้าง bot ใน BotFather หนึ่งตัวต่อ Agent หนึ่งตัว
- ถ้าอยากให้งานในแชตเดินเร็วขึ้น ให้ใส่ Agent อีกตัวพร้อม bot ของมันเข้าแชตเดียวกัน Agent ไม่มีค่าใช้จ่ายเพิ่ม
- Member ใช้ Agent ตัวนี้ส่วนตัวผ่าน Controller ได้ตามปกติ แต่สิ่งที่ทิ้งไว้ใน Workdir คนในแชตขอดูได้ แอปต้องบอกให้ชัดตอนผูก Channel
- เริ่มจาก Telegram ก่อน แชตอื่นอย่าง Slack, LINE และ Discord ใช้แบบเดียวกันได้
- Channel ไม่อยู่ใน v0.1 และเพิ่มทีหลังได้แบบ additive (ADR 0023)
