# Agent รับงานจากแชตภายนอกผ่าน Channel และทำในนามของ Member ที่ผูก Channel นั้น

Hermes และ OpenClaw ให้ Agent คุยผ่าน Telegram ได้ เราต้องการมากกว่านั้น คือเอา Agent เข้ากลุ่มไปทำงานให้คนในกลุ่มที่ไม่ได้เป็น Member ได้ Channel คือแชตภายนอก เช่น กลุ่ม Telegram ที่ Member ซึ่งมี Manage ที่ Agent ตัวนั้นผูกไว้และเซ็น (ADR 0006) แบบเดียวกับ Schedule (ADR 0027) คือเป็นของที่ Member เซ็นทิ้งไว้ แล้ว Runtime ใช้เปิด Task เองโดยไม่ต้องเซ็นทีละข้อความ งานทุกอย่างที่มาจากแชตทำในนามของ Member ที่ผูก ระบบจึงตรวจ Use ของคนนั้น (ADR 0010) Task ขึ้นใน Inbox ของคนนั้น และค่า token ก็ไปตกที่ key ของ Provider ที่ลูกค้าใส่ไว้ (ADR 0001) คนในแชตไม่ได้เป็น Member ชื่อของคนที่พิมพ์เก็บไว้เป็นแค่ข้อมูล และทุกคนในแชตมีอำนาจเท่ากัน คือทำได้เท่าที่ Allowlist ของ Agent ปล่อย

แต่ละแชตที่ผูกมี Task ของวันละหนึ่ง Task ข้อความที่เรียก Agent ทั้ง mention และ reply คำตอบของ Agent เข้า Task ของวันนั้น ซึ่ง privacy mode ของ Telegram ส่งให้ bot เฉพาะข้อความสองแบบนี้อยู่แล้ว ส่วนในแชตส่วนตัวกับ bot ทุกข้อความเข้า Task ของวัน ข้อความที่ reply คำตอบเก่าก็เข้า Task ปัจจุบัน โดยแนบข้อความที่ถูก reply ไปเป็นบริบท ไม่กระโดดกลับไป Task เก่า ข้อความแรกหลังเวลาตัดวันเปิด Task ใหม่ ไม่ได้สร้างรอไว้ วันที่ไม่มีใครคุยจึงไม่มี Task ว่าง เวลาตัดวันคือ 04:00 ตามเวลาของ Machine ตั้งได้ต่อ Channel ตัดตีสี่แทนเที่ยงคืนเพื่อไม่ให้บทสนทนาดึกขาดกลางคัน ใครในแชตก็พิมพ์ `/new` หรือ `/reset` เพื่อเปิด Task ใหม่ได้ เพราะแค่เปิด Task ใหม่ ไม่ได้ลบอะไร และถ้า Task ยาวเกิน context ก็ย่อตาม ADR 0041 Agent จึงเห็นว่าวันนี้ใครถามอะไรไปแล้ว คนที่ถามต่อด้วยการ mention ใหม่ก็ไม่เสียบริบท ส่วนสิ่งที่ต้องรู้ข้ามวัน Agent ใช้ Memory กับการค้น Task เก่า (ADR 0036) ข้อความที่เข้ามาระหว่างที่ Agent ทำ Turn อยู่ รวมเป็นข้อความเดียวให้ Turn ถัดไป พร้อมชื่อคนพิมพ์และเวลาส่งของแต่ละข้อความ แชตหนึ่งจึงมีงานรอไม่เกินหนึ่ง Turn ไม่ว่าคนในแชตจะส่งรัวแค่ไหน Agent แต่ละตัวมี bot ของตัวเองหนึ่งตัว ชื่อกับรูปของ bot จึงเป็นตัว Agent เลย supervisor ถือ token ของ bot ไว้ ไม่ให้ worker อ่านได้ เพราะคนในแชตอาจหลอก Agent ให้บอก token แล้วเอาไปปลอมเป็น bot และ supervisor ดึงข้อความจาก Telegram ด้วย long polling ซึ่งเป็นสายขาออกแบบเดียวกับที่ต่อ Hub (ADR 0001) ข้อความจากแชตจึงไม่ผ่าน Hub (ADR 0005) และเพราะ Agent อยู่บน Machine เดียวตลอด (ADR 0002) token หนึ่งตัวจึงมีคนดึงข้อความแค่ที่เดียว ซึ่งตรงกับที่ Telegram บังคับ bot ตัวเดียวอยู่ได้หลายแชต แต่แต่ละแชตต้องผูกแยกกัน แชตที่ไม่ได้ผูกไม่ได้คำตอบ

คำตอบของ Agent เข้าแชตได้ตรงๆ ทางนี้จึงเป็นทางส่งข้อมูลออกที่ Egress กันไม่ได้ อะไรที่ Agent อ่านได้ คนในแชตก็ขอได้หมด และ Allowlist ก็กันไม่ได้เพราะ Agent ที่โดนหลอกเลี่ยงมันได้ (ADR 0030) Agent ที่มี Channel จึงอ่านไฟล์ได้แค่ใน Workdir ของตัวเองกับ Library ที่ได้สิทธิ์ (ADR 0037) มี Egress ของตัวเอง (ADR 0029) และเป็นพนักงานของ Project ไม่ได้ ห้ามทั้งสองทาง คือพนักงานผูก Channel ไม่ได้ และ Agent ที่มี Channel เข้า Project ไม่ได้ Approval ของงานจาก Channel ไปที่ Controller ของ Member ที่มี Approve เหมือนงานอื่น คนในแชตเห็นแค่ว่ากำลังรออนุมัติ งานจาก Channel ต่อคิวเดียวกับงานอื่น (ADR 0011) และ bot บอกลำดับคิวในแชต ค่า token ที่คนในแชตใช้มี Budget ของ Agent เป็นเพดาน (ADR 0043) Channel หยุดทันทีเมื่อกุญแจที่เซ็นมันถูกถอน (ADR 0031)

ในแอป Task ของ Channel อ่านได้อย่างเดียว Member กด Stop และตอบ Approval ได้ แต่พิมพ์ลงไปไม่ได้ เพราะสิ่งที่อยู่ใน Task คนในแชตขอให้ Agent เล่าได้ทั้งหมด ข้อความที่ Member พิมพ์ในแอปจึงรั่วเข้าแชตได้ และคนในแชตจะเห็น Agent ตอบอ้างถึงเรื่องที่ไม่เคยเห็น Member ที่อยากสั่งเรื่องของแชต พิมพ์ในแชตเองในฐานะคนในแชต แก้คำสั่งของ Agent ซึ่งมีผลตั้งแต่ Task ถัดไป หรือเปิด Task ใหม่กับ Agent ในแอปถ้าอยากคุยส่วนตัว

## Considered Options

- **คนในแชตแต่ละคนมีตัวตนและสิทธิ์ของตัวเอง**: แยกได้ว่าใครสั่ง deploy ได้และใครถามได้อย่างเดียว แต่ต้องมีตัวตนแบบใหม่นอกจาก Member และ ADR ทุกตัวที่พูดถึง Member ต้องเพิ่มกรณีของคนนอก ถ้าอยากแยกสิทธิ์ ให้ใช้ Agent สองตัวกับสองแชต
- **ข้อความที่เรียก Agent เปิด Task ใหม่ และ reply คุยต่อใน Task ของคำตอบนั้น**: Task หนึ่งคือหนึ่งเรื่อง แต่คนที่ถามต่อด้วยการ mention ใหม่จะได้ Task ที่ไม่มีบริบทเดิม ในแชตส่วนตัวที่คนไม่ค่อยกด reply ทุกข้อความจะเริ่มเรื่องใหม่ และ Inbox แตกเป็นหลายสิบ Task เล็กๆ
- **ทั้งแชตเป็น Task เดียวตลอดไป ล้างด้วย `/new` แบบ Hermes และ OpenClaw**: ไม่ต้องมีเวลาตัดวัน แต่ Task ยาวไม่จบถ้าไม่มีใครจำพิมพ์ `/new` การตัดวันทำให้ Task ไม่ยาวเกินหนึ่งวันโดยไม่ต้องมีใครจำ
- **bot ตัวเดียวต่อ Machine แล้วส่งต่อให้ Agent แต่ละตัว**: สร้าง bot ครั้งเดียว แต่ทุก Agent ใช้ชื่อเดียวกันในแชต คนในแชตต้องพิมพ์บอกว่าจะคุยกับตัวไหน และ Character ไม่มีที่แสดง
- **กดอนุมัติในแชตได้ แบบ `/approve` ของ Hermes**: Hermes ทำได้เพราะแชตนั้นมีเจ้าของคนเดียว ในกลุ่ม คนที่ขอเองก็กดอนุมัติตัวเองได้ ถ้าจะจำกัดให้เฉพาะ Member ก็ต้องผูกบัญชี Telegram เข้ากับ Member แล้วการอนุมัติจะไม่ได้เซ็นด้วยกุญแจ ใครยึดบัญชี Telegram ได้ก็อนุมัติได้
- **ให้ Agent ที่มี Channel อยู่ใน Project ได้ แล้วเตือนแทน**: คนในแชตสั่งงานทั้ง Project ได้ แต่แม้ ADR 0026 จะให้อ่าน Workdir ของพนักงานร่วม Project ได้เฉพาะใน Task ของ Project Workdir ของ Agent ตัวนี้ก็ยังเป็นทางเชื่อมสองฝั่ง ผลงานของ Project ที่ลงไว้ในนั้นรั่วเข้าแชตได้ และคนในแชตฝากไฟล์ที่ฝังคำสั่งไว้ให้พนักงานร่วม Project เปิดอ่านได้ ซึ่งเท่ากับใช้ Allowlist ของ Agent ที่สิทธิ์มากกว่า นอกจากนี้คิวของ Project กับของแชตก็ขวางกัน ถ้าจำเป็นจริง ให้ออกแบบ Channel ที่ผูกกับ Project ทั้ง Project แยกต่างหาก
- **เพดานจำนวนงานที่รอต่อ Channel**: กันคนในแชตส่งรัว แต่เมื่อข้อความที่รอรวมเป็น Turn เดียว แชตหนึ่งรอได้แค่หนึ่ง Turn อยู่แล้ว และ Budget กันเรื่องเงิน
- **Member พิมพ์ใน Task ของ Channel จากแอปได้**: สั่ง Agent เรื่องของแชตจากแอปได้ แต่ถ้าคำตอบขึ้นแค่ในแอป คนในแชตขอให้ Agent เล่าข้อความของ Member ได้ ถ้าโพสต์เข้าแชตด้วย ข้อความของ Member จะขึ้นในชื่อของ bot
- **แบ่ง section ในแอปตามประเภท Channel**: เห็นแยกชัด แต่ Agent ส่วนใหญ่มี Channel แค่หนึ่งหรือสองตัว จึงได้ section ว่างเยอะ และสิ่งที่คนอยากรู้คือมาจากแชตไหน ไม่ใช่มาจาก Telegram หรือ Slack
- **ให้ Agent ทำหลาย Turn พร้อมกันเมื่องานอ่านอย่างเดียว**: ขัดกับ ADR 0011 และรู้ล่วงหน้าไม่ได้ว่า Turn ไหนจะไม่เขียนไฟล์

## Consequences

- ADR 0006 มีข้อยกเว้นเพิ่มหนึ่งข้อ คือข้อความในแชตของ Channel ที่ไม่ได้เซ็นทีละข้อความ ส่วนตัว Channel ยังต้องเซ็น
- ในกลุ่ม หลายเรื่องปนกันใน Task ของวัน แต่มีแค่ข้อความที่เรียก Agent ไม่ใช่ทุกข้อความในกลุ่ม
- Memory ถูกตรึงตอนเริ่ม Task (ADR 0036) สิ่งที่ Agent จดระหว่างวันจึงเห็นผลใน Task ของวันถัดไปหรือหลัง `/new`
- Task ของ Channel ในแอปมีป้ายที่มา เช่น `Telegram · กลุ่มขาย` และรายการ Task ของ Agent กรองตามที่มาได้ ทั้งแอป Channel Schedule และ Project หน้าตั้งค่า Agent แสดง Channel ที่ผูกไว้ กดแล้วเห็น Task ของแชตนั้นเรียงตามวัน
- ระหว่างที่ Machine ปิด bot เงียบ และคนในแชตไม่รู้ว่าทำไม Telegram เก็บข้อความที่ bot ยังไม่ได้ดึงไว้ไม่เกิน 24 ชั่วโมง พอเครื่องกลับมา ข้อความที่ค้างรวมเป็น Turn เดียวตามกฎเดิม ข้อความที่เก่ากว่านั้นหายไป
- ระหว่างที่งานจากแชตรอ Approval คนอื่นในแชตต้องรอตามไปด้วย (ADR 0011) Agent ที่ใช้กับ Channel ควรตั้งเวลาหมดอายุของ Approval ให้สั้น ซึ่งตั้งต่อ Agent ได้อยู่แล้ว
- Member ต้องสร้าง bot ใน BotFather หนึ่งตัวต่อ Agent หนึ่งตัว
- ถ้าอยากให้งานในแชตเดินเร็วขึ้น ให้ใส่ Agent อีกตัวพร้อม bot ของมันเข้าแชตเดียวกัน Agent ไม่มีค่าใช้จ่ายเพิ่ม
- Member ใช้ Agent ตัวนี้ส่วนตัวผ่าน Controller ได้ตามปกติ แต่สิ่งที่ทิ้งไว้ใน Workdir คนในแชตขอดูได้ แอปต้องบอกให้ชัดตอนผูก Channel
- เริ่มจาก Telegram ก่อน แชตอื่นอย่าง Slack, LINE และ Discord ใช้แบบเดียวกันได้
- Channel ไม่อยู่ใน v0.1 และเพิ่มทีหลังได้แบบ additive (ADR 0023)
