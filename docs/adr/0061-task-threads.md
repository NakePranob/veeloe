# เส้นร้อย Task: หน้ารวม Task จากต้นกำเนิดเชิงรุกเดียวกัน

งานเชิงรุก (Schedule ตาม ADR 0027, งานตอนว่างตาม ADR 0056, event ในเครื่องตาม ADR 0057) เปิด Task ใหม่ทุกรอบ งานต่อเนื่องเรื่องเดียวจึงกระจายเป็น Task หลายอัน อยากดูภาพรวมต้องเปิดทีละ Task ไล่อ่านเอง ทิศที่เลือก (เจ้าของตัดสิน 2026-11-01) คือ Task ที่เกิดจากต้นกำเนิดเดียวกัน (Schedule หนึ่งอัน Watch หนึ่งอัน หรือลิสต์ Idle Work หนึ่งลิสต์) ผูกรวมเป็น "เส้น" หนึ่งเส้นในแอป เส้นเป็นแค่สารบัญ ไม่ได้รวม Task เข้าด้วยกัน ADR 0027 ยังเปิด Task ใหม่ทุกรอบเหมือนเดิม

หน้าเส้นแสดงลิสต์รอบเรียงตามเวลา แต่ละแถวมีวันเวลา สรุปสั้น และสถานะ (มีเรื่อง / เงียบ) กดแถวไหนกระโดดไป Task รอบนั้นได้เลย รอบที่เงียบ (Task ไม่ขึ้น Inbox ตาม ADR 0027) ยังขึ้นในเส้นเป็นแถว "ไม่มีอะไร" เพื่อให้เห็นความต่อเนื่องว่าเช็กแล้ว ไม่ใช่ขาดหาย เส้นเก็บแค่ metadata (รหัสต้นกำเนิดกับรายการ Task) ไม่เก็บเนื้อหา ตามหลักที่ Hub เก็บได้แค่ metadata (ADR 0005)

## Considered Options

- **รวมเป็น Task เดียวยาวไม่จบ**: จำได้ทุกอย่าง ไม่ต้องมีเส้น แต่ประวัติบวมจนเกิน context และค่า token แพงขึ้นทุกรอบ ADR 0027 พิจารณาแล้วปัดตก
- **ไม่ทำอะไร คุ้ย Inbox เอง**: ไม่ต้องเขียนโค้ดเพิ่ม แต่ยิ่งหลายรอบยิ่งหาไม่เจอ งานต่อเนื่องใช้ไม่ได้จริง
- **สรุปอัตโนมัติรวมเส้นเป็นรายงาน**: ดีกว่าแค่สารบัญ แต่ต้องใช้ token ทำสรุป และต้องตัดสินว่าสรุปเมื่อไร ทำทีหลังได้แบบ additive (ADR 0023)

## Consequences

- ทุก Task ที่เกิดเชิงรุกต้องติดรหัสต้นกำเนิด (Schedule ไหน Watch ไหน ลิสต์ไหน) ตั้งแต่เปิด Task
- หน้าเส้นอยู่ในแอป Controller ตามหลัก local-first (ADR 0021) ลบเส้นคือลบแค่สารบัญ ไม่ลบ Task
- ชื่อเส้นกับสรุปสั้นถือเป็นเนื้อหา จึงเข้ารหัสแบบเดียวกับ event ของ Task (ADR 0063) Hub เห็นแค่รหัส
- เส้นของ Schedule ที่ส่งงานให้ Project ใช้กติกาเดียวกับ Task ของ Project (ADR 0046)
