# Owner พาคนเข้า Workspace ส่วน Manager แค่ให้สิทธิ์ และคนทั้งหมดอยู่ในหน้าเดียว

Status: accepted

> แก้ ADR 0059 (คนที่มี Manage ออก Invitation ได้) และเพิ่มจาก ADR 0091 (ผู้ดูแลกลุ่มเชิญเข้ากลุ่มของตัวเอง) ตามที่เขียนไว้ในหัวของแต่ละตัว

ตาม ADR 0059 คนที่มี Manage ที่ Agent ตัวเดียวก็เชิญคนแปลกหน้าเข้า Workspace ได้ "ดูแล Agent ตัวหนึ่ง" กับ "พาคนเข้าองค์กร" เป็นสิทธิ์คนละขนาด แต่มาด้วยกันโดยที่คนให้ Manage ไม่รู้ตัว เพราะบอกไว้แค่ในคำอธิบายใต้ตัวเลือก ส่วนหน้าจอเรื่องคนแยกเป็นสามแถวเท่ากัน (Member, กลุ่ม, เชิญคน) รายชื่อไม่มี Owner หน้าของคนหนึ่งคนไม่บอกสิทธิ์ที่ได้จากกลุ่ม หน้าเชิญรวมทุกเรื่องไว้หน้าเดียว และคำขอเข้ามาถึงเฉพาะตอนเปิดหน้าเชิญค้างไว้ (เจ้าของตัดสิน 2026-11-28)

**ใครพาคนเข้า** Owner ออก Invitation ได้ ผู้ดูแลกลุ่มออก Invitation ได้เฉพาะที่แนบกลุ่มของตัวเอง ไม่แนบ Grant เดี่ยว คนที่มี Manage ให้ Grant ที่ Agent ของตัวเองกับคนที่อยู่ใน Workspace แล้วเท่านั้น Runtime รับใบรับรอง `member.add` เฉพาะจากกุญแจของ Owner หรือผู้ดูแลกลุ่ม Controller ไม่แสดงปุ่มเชิญกับคนที่เชิญไม่ได้ หน้าเชิญให้เลือกได้เฉพาะ Agent ที่คนออกให้ Grant ได้จริง

**หน้าเดียวของคน** แถว "คน" ใน Workspace เปิดหน้าที่มีทุกคนใน Workspace รวม Owner และตัวเอง แต่ละแถวเป็น ชื่อ · ตำแหน่ง และบอกว่าเป็น Owner ในหน้าเดียวกันมีส่วนของกลุ่ม และส่วนของลิงก์เชิญที่ยังเปิดอยู่ ปุ่มเชิญอยู่ที่หัวหน้านี้

**หน้าของคนหนึ่งคน** แสดงระดับจริงที่คนนั้นมีที่แต่ละ Agent พร้อมบอกว่ามาจากไหน เช่น "Use · จากกลุ่ม Sales" หรือ Grant ของตัวเอง และแก้ Grant ของตัวเองได้ที่เดียวกัน ระดับจากกลุ่มแก้ที่หน้ากลุ่ม ตำแหน่งแก้ได้ด้วยคำสั่งที่เซ็นโดย Owner หรือคนนั้นเอง (ADR 0091)

**คำขอเข้าอยู่ใน Inbox** คำขอเข้าที่ตรวจหลักฐานผ่านแล้วถูกเก็บไว้บนเครื่องและขึ้นในแท็บ "รอคุณ" ของ Inbox พร้อมรหัสสั้นให้เทียบ คนออกรับหรือปฏิเสธได้จากตรงนั้นโดยไม่ต้องเปิดหน้าเชิญค้างไว้ ผู้ขอยังต้องเปิดหน้าของตัวเองค้างไว้จนถูกรับเหมือนเดิม (ADR 0059)

**หน้าเชิญเหลือสองเรื่อง** เข้ากลุ่มไหน หรือเลือก Agent เอง และตำแหน่ง ส่วนจำนวนคนและเวลาหมดอายุอยู่ใต้ "ตั้งค่าลิงก์" ชื่อที่คนเปิดลิงก์เห็นใช้ชื่อ Member ของคนออก ไม่ใช่ชื่อเครื่อง

**Agent มีตัวละครเสมอ** ทุกที่ที่แสดง Agent ในเรื่องคนและสิทธิ์ใช้แถวแบบหน้า Agent คือตัวละคร ชื่อกับ model และชื่อเครื่องแทนสถานะ

## Considered Options

- **คงให้ Manager เชิญได้ แต่บอกให้ชัดตอนให้ Manage**: ไม่ต้องเปลี่ยนกติกา แต่คนที่อยากให้แค่ดูแล Agent ต้องยอมให้เชิญคนด้วยเสมอ
- **แยกสิทธิ์ "เชิญคน" เป็นอีกระดับ**: ยืดหยุ่นที่สุด แต่เพิ่มระดับที่สี่ให้ทุกคนต้องเข้าใจ และกลุ่มกับผู้ดูแลกลุ่มทำหน้าที่นี้ได้อยู่แล้ว
- **คงสามแถวใน Workspace แต่ใส่ Owner ในรายชื่อ**: แก้น้อย แต่สิทธิ์จริงของคนหนึ่งคนยังต้องดูสองหน้า และคำขอเข้ายังหายถ้าไม่เปิดหน้าเชิญ

## Consequences

- Manager ที่เคยเชิญคนได้จะเชิญไม่ได้อีก ต้องขอ Owner หรือให้ Owner ตั้งเป็นผู้ดูแลกลุ่ม
- Runtime ต้องรู้ว่าใครเป็นผู้ดูแลกลุ่มก่อนรับ `member.add` ซึ่งมีอยู่แล้วในสำเนากลุ่ม (ADR 0091)
- รายชื่อ Owner และชื่อของแต่ละคนต้องมาถึง Controller ของทุกคน ไม่ใช่แค่ Member ที่เข้ามาด้วยลิงก์
- คำขอเข้าต้องเก็บบนเครื่องจนรับ ปฏิเสธ หรือลิงก์หมดอายุ
