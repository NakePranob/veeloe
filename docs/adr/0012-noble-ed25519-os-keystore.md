# ใช้ Ed25519 ด้วย @noble ทั้งระบบ และเก็บกุญแจใน Keychain/Keystore ของ OS

ฝั่ง TypeScript ทุกที่ (Runtime บน Bun, Controller บน Hermes และบนเว็บ) ใช้ @noble (curves, ciphers, hashes) เพราะเป็น JS ล้วนที่ผ่าน audit แล้ว และใช้ตัวเดียวได้ทุกที่ ลายเซ็นทั้งของ Controller และของ Runtime ใช้ Ed25519 ส่วน sealed box สำหรับ key ของ Provider (ADR 0005) ประกอบเองจาก X25519 กับ XSalsa20-Poly1305 ให้ตรงกับรูปแบบของ libsodium บนมือถือต้องเติม getRandomValues จาก expo-crypto ฝั่ง Hub ใช้ Ed25519 จาก stdlib ของ Go ไว้ตรวจตัวตนตอนต่อเข้ามาเท่านั้น

กุญแจบนมือถือเก็บด้วย expo-secure-store (Keychain/Keystore) บนเว็บเก็บใน IndexedDB และบน Machine เก็บเป็นไฟล์สิทธิ์ 0600 ในโฟลเดอร์ของ Runtime

กุญแจของ Controller ใช้ได้หลังยืนยันตัวด้วย Face ID ลายนิ้วมือ หรือรหัสเครื่อง ไม่อย่างนั้นใครที่หยิบมือถือที่ปลดล็อกอยู่ไปได้ก็สั่ง Agent รันคำสั่งบนเครื่องของเจ้าของได้ทันที บนมือถือตั้ง `requireAuthentication` ของ expo-secure-store ซึ่งใช้การยืนยันตัวของ Keychain และ Keystore บนเว็บใช้ passkey ของเบราว์เซอร์ (WebAuthn) เป็นด่านก่อนเปิด ยืนยันครั้งหนึ่งตอนเปิดแอปและหลังไม่ได้ใช้เกิน 5 นาที คำสั่งทั่วไประหว่างนั้นไม่ต้องยืนยันซ้ำ แต่ต้องยืนยันใหม่ทุกครั้งก่อนอนุมัติ Approval, Link เครื่องหรืออนุมัติคำขอ Link, แจกหรือถอน Grant, เลื่อนขั้น Owner, ติดตั้ง Skill, Connector หรือ Blueprint, แก้ Allowlist หรือ Egress, Pairing, ปล่อย Machine และถอนกุญแจ เครื่องที่ไม่ได้ตั้งการล็อกหน้าจอสร้างกุญแจไม่ได้

## Considered Options

- **libsodium**: มี sealed box สำเร็จรูป แต่ต้องใช้สอง package (WASM กับ native) และฝั่งมือถือต้องใช้ native module
- **PIN ของแอปเอง**: ไม่ต้องพึ่ง OS แต่ซ้ำกับรหัสเครื่อง และคนมักตั้ง PIN ง่ายๆ
- **ยืนยันตัวทุกคำสั่ง**: ปลอดภัยที่สุด แต่ต้องสแกนหน้าทุกครั้งที่พิมพ์ในแชตจนคนเลิกใช้
- **P-256 ในชิปความปลอดภัย (Secure Enclave, StrongBox)**: ดึงกุญแจออกมาไม่ได้ จึงปลอดภัยที่สุด แต่ต้องใช้ native module และระบบจะมีสอง algorithm

## Consequences

- แอปยังดึงกุญแจออกมาใช้ได้ malware ที่ยึดมือถือได้จึงขโมยกุญแจของ Owner ได้ ถ้าจะย้ายไปใช้ชิปความปลอดภัยทีหลัง ให้กุญแจเก่าเซ็นรับรองกุญแจใหม่ด้วยขั้นตอนเดียวกับการเพิ่ม Controller ตัวใหม่ โดยไม่ต้องทำ Pairing ใหม่
- Controller บนเว็บปลอดภัยน้อยกว่าบนมือถือ เพราะ IndexedDB ไม่ได้มีฮาร์ดแวร์ช่วยป้องกัน และ passkey บนเว็บเป็นแค่ด่านของแอป ไม่ได้ล็อกตัวกุญแจ
- คนที่รู้รหัสเครื่องผ่านด่านนี้ได้ ด่านนี้กันกรณีเครื่องถูกหยิบไปตอนปลดล็อก ส่วนกรณีโดนขโมยพร้อมรหัสต้องพึ่งการถอนกุญแจ (ADR 0031)
