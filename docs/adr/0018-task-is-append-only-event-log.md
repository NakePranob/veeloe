# Task เก็บเป็น event log ที่ต่อท้ายอย่างเดียว และมีเลขลำดับ

Task คือลำดับของ event ได้แก่ ข้อความของ Member, ผลจาก LLM (เก็บตามที่ได้มาทุกตัวอักษร รวมถึง thinking block), การเรียก tool และผลของ tool, Approval และคำตอบ, Delegation, Stop, การเริ่มและจบ Turn แต่ละ event มีเลขลำดับภายใน Task ของตัวเอง และเก็บไว้ใน bun:sqlite ของ Runtime (ADR 0014) ที่นี่เป็นแหล่งข้อมูลจริงเพียงแห่งเดียว harness สร้างบทสนทนาที่จะส่งให้ LLM จาก event ชุดนี้ ตอนที่ Controller ต่อใหม่จะขอแค่ "event หลังเลข N" แล้ว cache ไว้ตามนั้น และ Mood ก็คำนวณจาก event ล่าสุด

Claude รุ่นปัจจุบันบังคับให้ harness ต่อท้ายบทสนทนาอย่างเดียว ถ้าแก้ประวัติย้อนหลัง thinking block จะใช้ไม่ได้ การเก็บแบบต่อท้ายอย่างเดียวจึงเป็นสิ่งที่ต้องทำอยู่แล้ว ไม่ใช่แค่ทางเลือกเรื่องโครงสร้าง

## Considered Options

- **เก็บบทสนทนาของ LLM กับ event ของ UI แยกกัน**: แต่ละส่วนออกแบบได้อิสระ แต่มีแหล่งข้อมูลสองที่ซึ่งอาจไม่ตรงกัน เช่น ตอนไฟดับกลางทาง
- **เก็บ snapshot แล้วส่ง stream แบบชั่วคราว**: ทำง่ายตอนเริ่ม แต่ต่อใหม่ทีไรต้องโหลดใหม่ทั้งหมด และอาจตกหล่นช่วงที่หลุดไป

## Consequences

- event ห้ามแก้และห้ามลบ บทสรุปจากการย่อประวัติต่อท้ายเป็น event ใหม่ แล้ว harness ส่งให้ LLM แค่บทสรุปกับ event ที่ตามมา ส่วน Member ยังเห็นประวัติเต็ม (ADR 0041)
- `tasks.db` ค้นแบบ full-text ด้วย FTS5 ได้ Agent จึงค้น Task เก่าของตัวเองได้ (ADR 0036)
- ข้อความที่ LLM กำลังพิมพ์ทีละส่วน (delta) ส่งให้ดูสดแต่ไม่เก็บลง log จะเก็บเป็น event ก็ต่อเมื่อข้อความ block นั้นจบ ถ้าหลุดไประหว่าง block แล้วต่อกลับมา จะเห็นข้อความของ block นั้นตอนที่ block จบ
