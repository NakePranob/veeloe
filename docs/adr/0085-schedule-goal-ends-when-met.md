# Schedule มีเป้าหมายได้ จำความคืบหน้าข้ามรอบ และหยุดเองเมื่อสำเร็จ

> แก้ ADR 0027 และ 0044 บางส่วน ตามที่เขียนไว้ในหัวของแต่ละตัว

Schedule ตาม ADR 0027 เปิด Task ใหม่ทุกรอบ และไม่รู้ว่าเมื่อไหร่ควรหยุด งานที่มีจุดจบ เช่น "ตาม PR #41 จนกว่าจะ merge" หรือ "เช็กราคาตั๋วจนกว่าจะต่ำกว่า 5,000 บาท" จึงรันต่อไปเรื่อยๆ จนคนมากดหยุดเอง และแต่ละรอบต้องค้น Task เก่าเพื่อรู้ว่าถึงไหนแล้ว Memory ใช้ไม่ได้ เพราะเป็นของทั้ง Agent ไม่ใช่ของ Schedule หนึ่งอัน OpenBot มี goal ที่มีเกณฑ์สำเร็จ บันทึกความคืบหน้าที่ส่งต่อทุกรอบ และจบเองเมื่อครบเกณฑ์ (เจ้าของตัดสิน 2026-11-27)

**เป้าหมายใส่หรือไม่ใส่ก็ได้** ตอนตั้ง Schedule ใส่เกณฑ์สำเร็จเป็นประโยคได้หนึ่งข้อ และเกณฑ์นี้อยู่ในสิ่งที่เซ็น Schedule ที่ไม่มีเป้าหมายทำงานเหมือนเดิม

**ความคืบหน้าข้ามรอบ** ทุกรอบของ Schedule ที่มีเป้าหมาย ข้อความของรอบมีเกณฑ์สำเร็จกับบันทึกความคืบหน้าล่าสุด Agent เขียนบันทึกด้วย tool ยาวไม่เกิน 2,000 ตัวอักษร และบันทึกใหม่แทนที่ของเดิม Runtime เก็บบันทึกไว้กับ Schedule บน Machine และส่งให้ LLM ในฐานะข้อมูล ไม่ใช่คำสั่ง เพราะ Agent อาจจดมาจากหน้าเว็บ หน้าเส้นของ Schedule (ADR 0061) แสดงบันทึกล่าสุด

**จบเมื่อสำเร็จ** Agent เรียก tool บอกว่าครบเกณฑ์พร้อมเหตุผล Runtime หยุด Schedule ทันที บันทึก event พร้อมเหตุผลลง Task ของรอบนั้น และส่ง push หนึ่งครั้งไปที่คนตั้ง (ADR 0044) Controller แสดงว่า Schedule จบเพราะสำเร็จ ซึ่งต่างจากที่คนกดพักและที่พักเองเพราะล้ม (ADR 0083) ถ้าคนตั้งไม่เห็นด้วย กดเปิดต่อได้ด้วยคำสั่งที่เซ็น tool นี้ใช้ได้ในรอบที่ไม่มีคนเฝ้าโดยไม่ต้องขอ Approval (ADR 0079) เพราะมันแค่หยุดงาน

## Considered Options

- **ใช้ Memory จำความคืบหน้า**: ไม่ต้องสร้างอะไรใหม่ แต่ Memory เป็นของทั้ง Agent และมีเพดาน 4,000 ตัวอักษร Schedule หลายอันจะแย่งที่กัน
- **รวมทุกรอบเป็น Task เดียว**: จำได้ทุกอย่าง แต่ประวัติบวมจนเกิน context ตามที่ ADR 0027 และ 0061 ปฏิเสธไว้
- **ให้คนเป็นคนตัดสินว่าสำเร็จเสมอ**: ไม่มีทางที่ LLM จะหยุดงานผิดเวลา แต่คนต้องคอยเปิดดูทุกรอบ ซึ่งเป็นเรื่องที่ Schedule ตั้งใจจะไม่ให้ต้องทำ

## Consequences

- LLM อาจตัดสินว่าสำเร็จเร็วเกินไป เหตุผลที่แสดงในแอปกับปุ่มเปิดต่อคือทางแก้
- บันทึกความคืบหน้าเป็นเนื้อหา จึงเข้ารหัสแบบเดียวกับ event ของ Task (ADR 0063)
- Idle Work กับ Watch ยังไม่มีเป้าหมาย ชิ้นของ Idle Work จบในรอบเดียวอยู่แล้ว ส่วน Watch จะตัดสินตอนทำ
