# Member มีชื่อที่ Owner ตั้งตอนเชิญ และ Controller หลายเครื่องของคนเดียวกันเห็นสถานะตรงกัน

Member หนึ่งคนมี Controller ได้หลายเครื่อง เช่น มือถือ, iPad และเบราว์เซอร์ ระบบรู้ว่าเครื่องไหนเป็นของใครจากใบรับรองที่เซ็นต่อกัน (ADR 0031) และใช้รหัสของ Member เช่น `m_kai` ตัดสินสิทธิ์ แต่คนใน Workspace ต้องเห็นว่าใครพิมพ์ ใครอนุมัติ และ Mention ใคร และคนที่ใช้หลายเครื่องต้องไม่เจอแจ้งเตือนค้างหรือ Inbox ที่ไม่ตรงกัน

**ชื่อ**: Owner ตั้งชื่อของ Member ตอนสร้าง Invitation เพราะเป็นคนรู้ว่ากำลังเชิญใครและเป็นคนเทียบรหัสกับคนนั้น คนที่เข้ามาใหม่จึงตั้งชื่อตัวเองเป็นคนอื่นไม่ได้ตั้งแต่แรก หลังจากนั้น Member เปลี่ยนชื่อตัวเองได้ และ Owner เปลี่ยนให้ใครก็ได้ ด้วยคำสั่งที่เซ็น ชื่อห้ามซ้ำกับคนอื่นใน Workspace และการเปลี่ยนชื่อแจ้งให้ทุกคนเห็น ข้อความทุกข้อเก็บรหัสของ Member ไม่ได้เก็บชื่อ ประวัติจึงแสดงชื่อปัจจุบันเสมอ ชื่อเก็บที่ Hub เป็น metadata แบบเดียวกับชื่อของ Agent (ADR 0006) เพื่อให้แอปแสดงรายชื่อได้แม้ Machine ปิดอยู่ และ Runtime ได้สำเนาที่เซ็นแล้ว Controller แต่ละเครื่องมีชื่อเครื่องที่ตั้งให้อัตโนมัติจากรุ่นเครื่องหรือเบราว์เซอร์และแก้ได้ ใช้ในหน้ารายการเครื่องกับการแจ้งเตือนตอนมีการ Link เจ้าของกับ Owner เห็นชื่อเครื่อง คนอื่นไม่เห็น

**สถานะที่ต้องตรงกันทุกเครื่อง**: เมื่อเรื่องที่รอคนหนึ่งอยู่จบแล้ว เช่น Approval ถูกตอบ หรือ Mention ถูกอ่าน Runtime ส่ง event ไปที่ทุก Controller ของ Member คนนั้นพร้อม silent push ให้ลบแจ้งเตือนที่ค้าง Hub เก็บว่าแต่ละ Member อ่าน Task ไหนถึงข้อความลำดับที่เท่าไหร่ ซึ่งเป็นแค่รหัสกับตัวเลข ไม่ขัดกับ ADR 0005 และ sync ได้แม้ Machine ปิดอยู่ การไม่ส่ง push ซ้ำของ Mention (ADR 0046) ใช้ข้อมูลนี้ตัดสินว่าอ่านแล้วหรือยัง ค่าว่าจะแจ้งเรื่องอะไร เช่นปิดบางหมวดหรือบาง Agent (ADR 0044) เป็นของ Member และ sync ผ่าน Hub ส่วนการปิดเสียงแจ้งเตือนบนเครื่องนี้เป็นของแต่ละเครื่อง ข้อความที่พิมพ์ค้างไว้อยู่บนเครื่องที่พิมพ์เท่านั้น

## Considered Options

- **Member ตั้งชื่อตัวเองได้อิสระ**: Owner ไม่ต้องคิดชื่อให้ แต่คนที่เข้ามาใหม่ตั้งชื่อเป็นคนอื่นแล้วพิมพ์สั่งงานใน Project ได้ ระบบสิทธิ์ยังกันได้เพราะใช้รหัส แต่คนอ่านไม่ได้ดูรหัส
- **ประวัติแสดงชื่อ ณ ตอนที่พิมพ์**: เห็นว่าตอนนั้นใช้ชื่ออะไร แต่คนเดียวกันจะมีหลายชื่อในประวัติเดียว
- **สถานะอ่านแล้วเก็บที่ Runtime**: Hub ไม่ต้องรู้ว่าใครอ่านอะไร แต่ถ้า Machine ปิด เครื่องอื่นจะไม่รู้ว่าอ่านไปแล้ว และ Member ที่ใช้ Agent หลายเครื่องต้องรวมสถานะจากหลาย Runtime
- **sync ข้อความที่พิมพ์ค้าง**: พิมพ์บนมือถือแล้วไปต่อบนโน้ตบุ๊กได้ แต่ต้องส่งทุกการกดแป้นผ่าน Hub ซึ่งเห็นเนื้อหา

## Consequences

- Hub รู้ว่าแต่ละ Member อ่าน Task ไหนเมื่อไหร่ ซึ่งเป็นรูปแบบการใช้งานที่ Hub เห็นอยู่แล้วบางส่วนจากซองที่ส่งต่อ
- คนที่ถูกลบแล้วแสดงในประวัติเป็นอดีต Member (ADR 0024)
- รูปโปรไฟล์ยังไม่มี แอปใช้ตัวอักษรแรกของชื่อไปก่อน
- SSO ขององค์กรยังไม่มี ระบบรู้แค่ว่ากุญแจนี้ Owner รับรองไว้ ไม่รู้ตัวตนจริงของคน
