# Turn ที่ค้างอยู่ตอน Runtime เริ่มใหม่จบเหมือนโดน Stop และการอัปเดตพักรับงานก่อนสลับไฟล์

worker พังได้ และ supervisor เปิดใหม่ให้ (#11) เครื่องก็รีบูตได้ แต่ยังไม่มีใครกำหนดว่า Turn ที่มี event เริ่มแต่ไม่มี event จบใน log (ADR 0018) ต้องเป็นยังไง ถ้าปล่อยไว้ Agent แม่ที่รอผลของ Delegation จะรอไปตลอด เพราะการรอไม่มีเวลาหมดอายุ (ADR 0003) และถือ Turn ไว้จนคิวของมันไม่เดินอีกเลย เราจึงให้ worker หรือ Runtime ที่เริ่มใหม่ปิด Turn ที่ค้างอยู่ทุกตัวเหมือนโดน Stop (ADR 0017) โดยต่อ event "Turn ถูกขัดจังหวะเพราะเริ่มใหม่" ท้าย log ไฟล์ที่แก้ไปแล้วคงสภาพเดิม Approval ที่ค้างอยู่ใน Turn นั้นนับว่าถูกปฏิเสธ Turn ของ Task ย่อยที่อยู่ข้างใต้จบตามแบบ Stop และ Agent แม่ได้ผลกลับว่า Task ย่อยถูกขัดจังหวะ แล้วตัดสินใจเองว่าจะส่งซ้ำหรือแจ้งคน งานที่ต่อคิวอยู่เดินต่อตามลำดับ และคนสั่งเห็นใน Task ว่าโดนขัดจังหวะ พิมพ์ "ทำต่อ" ได้เลย

Runtime ไม่ทำ Turn ต่อเองจาก log เพราะถ้า worker พังหลังรัน `git push` หรือ `./deploy.sh` ไปแล้วแต่ยังไม่ทันบันทึกผล การทำต่อจะรันคำสั่งนั้นซ้ำ และถ้า tool ตัวไหนทำให้ worker พังทุกครั้ง เช่นใช้ RAM จนหมด การทำต่อเองจะพังวนไม่จบ

กฎนี้ทำให้การ restart กลาง Turn ปลอดภัย การอัปเดตตัวเอง (ADR 0009) จึงไม่ต้องรอให้ทุก Agent ว่างพร้อมกัน ซึ่งเครื่องที่มีหลาย Agent มี Schedule และมี Channel อาจไม่มีจังหวะแบบนั้นเลย จนแพตช์ไม่ได้ลงและเครื่องหลุดเมื่อ Hub ขยับเวอร์ชันต่ำสุด Runtime เช็ก release ใหม่ได้ตลอด เมื่อเจอแล้วให้พักรับ Turn ใหม่ งานที่เข้ามาต่อคิวตามปกติ Schedule ที่ถึงรอบถูกข้ามตาม ADR 0027 และข้อความจาก Channel ต่อคิวไปจนถึงเพดาน (ADR 0028) จากนั้นรอ Turn ที่ทำอยู่ให้จบไม่เกิน 30 นาที Turn ที่เกินเวลาจบตามกฎข้างบน แล้วสลับไฟล์และ restart ทั้งเครื่อง เพราะ supervisor กับ worker ใช้ binary เดียวกัน (ADR 0020)

## Considered Options

- **ให้ Turn ทำต่อเองจาก event log**: งานยาวไม่ต้องรอคนสั่งต่อ แต่คำสั่งที่รันแล้วยังไม่มีผลอาจรันซ้ำ ต้องมีตัวกันการพังวน และต้องบอก LLM ว่าคำสั่งไหนไม่รู้ผล ซึ่ง LLM ก็ยังอาจเลือกรันใหม่อยู่ดี
- **Owner ตั้งช่วงเวลาอัปเดตต่อ Machine เช่น ตีสาม**: คาดเดาได้และไม่ขัดงานกลางวัน แต่แพตช์อาจรอถึง 24 ชั่วโมง ต้องมีค่าเพิ่มให้ตั้ง และเครื่องที่ปิดทุกคืนจะไม่เคยได้อัปเดต
- **สลับไฟล์ทันทีที่เจอ release**: ปลอดภัยเพราะกฎข้างบน แต่ขัดงานที่ทำอยู่ทุกครั้งที่มี release

## Consequences

- Agent ลูกที่ไม่ได้พังแต่ค้าง เช่นรันคำสั่งที่วนไม่จบ ยังต้องใช้ Stop จากแอป
- 30 นาทีเป็นค่าตั้งต้น ถ้าใช้จริงแล้วสั้นหรือยาวไป ค่อยปรับ
- คิวต้องเก็บลงดิสก์ เพื่อให้งานที่รออยู่ยังอยู่หลัง restart
