# Watch เปิดงานเมื่อไฟล์ในเครื่องเปลี่ยน และต้องมีลายเซ็นก่อนเฝ้า

Watch คือคำสั่งที่ Member เซ็นไว้ล่วงหน้าตามหลักเดียวกับ Schedule (ADR 0027) ระบุว่าเฝ้าอะไร เงื่อนไขไหน และถึงแล้วให้ทำอะไร เมื่อถึงเงื่อนไข Runtime เปิด Task ใหม่ในนามคนตั้ง ซึ่งตรวจสิทธิ์ ขออนุมัติ และใช้ Budget เหมือนงานปกติ รอบแรกมีแค่สองเงื่อนไข คือไฟล์เปลี่ยนกับมีไฟล์ใหม่ เงื่อนไขอื่นเพิ่มทีหลังแบบ additive ได้ (ADR 0023) เหตุการณ์เหล่านี้ Runtime เห็นเองโดยตรง ไม่ผ่าน Hub

คนเริ่มได้ทั้งสองฝั่ง Member บอกเองในแชต หรือ Agent สังเกตแล้วเสนอ แต่ต้องมีลายเซ็นของ Member ก่อนเฝ้าครั้งแรกเสมอ Member ที่มี Use สร้าง Watch ได้ และแอปมีหน้ารายการงานพื้นหลังให้ทุกคนที่มี Use ดู เนื้อไฟล์ที่เปลี่ยนถือเป็นข้อมูลดิบ ไม่ใช่คำสั่ง

กฎของ Watch (เจ้าของตัดสิน 2026-11-01):

- การเขียนไฟล์ของ Agent เองไม่นับเป็น event ไม่อย่างนั้น Agent ที่เขียนสรุปลงไฟล์ที่เฝ้าอยู่จะปลุกตัวเองไม่จบ
- การเปลี่ยนแปลงถี่ๆ รวมเป็นงานเดียว รอเงียบ 5 นาทีซึ่งตั้งค่าได้ แต่รอนานสุด 30 นาที ไฟล์ log ที่เปลี่ยนตลอดจึงไม่ทำให้งานถูกเลื่อนไปเรื่อยๆ
- ถ้า Agent ไม่ว่าง event ที่เข้ามารวมเป็นงานรอหนึ่งงาน แบบเดียวกับ Channel (ADR 0028)
- ถ้าไฟล์เปลี่ยนตอนเครื่องปิด Runtime เทียบไฟล์ตอนเครื่องกลับมา แล้วเริ่มงานครั้งเดียว แบบเดียวกับ Schedule (ADR 0027)
- เฝ้าได้เฉพาะที่ที่คนตั้งอ่านได้ (ADR 0059) คนที่มีแค่ Use จึงเฝ้าได้แค่ Workdir กับ Library และใช้ Watch สืบเรื่องไฟล์อื่นบนเครื่องไม่ได้
- ใช้ token ภายใต้เพดานร่วมกับ Idle Work (ADR 0056)

## Considered Options

- **เฝ้าทุกอย่างแล้วทำเอง ไม่ต้องเซ็น**: ฉลาดสุด แต่ขัดกับ ADR 0006 ไม่มีคนรับผิดชอบ และใช้เงินโดยไม่มีคนอนุมัติ
- **รวมกับ Idle Work เป็นก้อนเดียว**: เกิดในเครื่องเหมือนกัน แต่ Watch ตื่นตามสิ่งที่เกิด ส่วน Idle Work ตื่นตามสภาพว่าง รวมกันแล้วกฎตื่นจะซับซ้อน
- **ไม่ชดเชยตอนเครื่องปิด**: ทำง่ายกว่า แต่ไฟล์ที่เข้ามาตอนเครื่องปิดจะไม่เกิดงาน โดยผู้ใช้ไม่รู้ตัว

## Consequences

- ถ้า Agent แก้ไฟล์ผ่าน script ที่รันอยู่ ระบบอาจแยกไม่ออกว่าเป็นการเขียนของ Agent ถ้าเกิดวงจรแบบนี้ เพดาน token เป็นตัวหยุดสุดท้าย
- Watch หยุดทันทีเมื่อกุญแจที่เซ็นมันถูกถอน หรือคนตั้งไม่เหลือ Grant ที่ Agent ตัวนั้น (ADR 0031)
- เหตุการณ์จากอินเทอร์เน็ต เช่น webhook ยังไม่มีการตัดสินใจ และยังถูกปฏิเสธตาม ADR 0027
