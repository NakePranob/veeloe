# งาน event ในเครื่องต้องมีลายเซ็นก่อนเฝ้า และไม่มีเฝ้าถ้าไม่มีเซ็น

งาน event ในเครื่องคือเหตุการณ์ที่เกิดในเครื่องลูกค้าเองแล้ว Runtime เห็นเองโดยตรง ไม่ผ่าน Hub เช่น ไฟล์เปลี่ยน มีไฟล์ใหม่ เกณฑ์เกินกำหนด หรือเวลารวมกับเงื่อนไข ทิศที่เลือกคือใช้หลักเดียวกับตั้งเวลาปลุก (ADR 0027) คือ Member เซ็นคำสั่งเฝ้าไว้ล่วงหน้าหนึ่งชุด ประกอบด้วยสามอย่าง คือเฝ้าอะไร เงื่อนไขไหน และถึงแล้วให้ทำอะไร ถึงเงื่อนไข Runtime เปิดงานใหม่ในนามคนตั้ง กฎตรวจสิทธิ์ ขออนุมัติ และเผางบเหมือนงานปกติทุกอย่าง

คนเริ่มได้ทั้งสองฝั่ง Member บอกเองในแชต หรือ agent สังเกตแล้วเสนอ (เช่น เห็นไฟล์เปลี่ยนบ่อยแล้ว Member ต้องสั่งสรุปเองทุกครั้ง ก็เสนอว่าให้เฝ้าไฟล์นี้มั้ย) แต่ลายเซ็น Member ต้องมีก่อนเฝ้าครั้งแรกเสมอ ไม่มีเซ็น ไม่มีการเฝ้า ข้อนี้ปัดตกแบบเฝ้าทุกอย่างแล้วลุกมาทำเอง เพราะขัดกับหลักเซ็นล่วงหน้าใน ADR 0006

ของใหม่มีสามอย่างเล็กๆ คือภาษาเงื่อนไข (ตัดสินทิศแล้ว: ต้องยืดหยุ่นตามคำสั่ง เริ่มจากแบบง่ายแล้วขยายได้ทีหลังแบบ additive รายละเอียดขอบเขตเป็นงานก่อนสร้างจริง) กันรัว (ตัดสินแล้ว: รวมเป็นงานเดียว รอเงียบประมาณ 5 นาทีซึ่งตั้งค่าได้ แล้วค่อยให้ agent ทำงาน) และสิทธิ์สร้าง (ตัดสินแล้ว: Member ทุกคนที่มี Use สร้างได้ แต่ต้องมีหน้ารายการงานพื้นหลังให้ทุกคนดูได้) เนื้อไฟล์ที่เปลี่ยนถือเป็นข้อมูลดิบ ไม่ใช่คำสั่ง เช่นเดียวกับเนื้อ event จากข้างนอก (ADR 0055) ส่วนเกราะสามชั้นของ ADR 0055 ไม่ต้องใช้กับงานในเครื่องเพราะไม่ผ่าน Hub

## Considered Options

- **เฝ้าทุกอย่างแล้วทำเอง ไม่ต้องเซ็น**: ฉลาดสุด แต่ขัดกับหลักเซ็นล่วงหน้า (ADR 0006) ไม่มีคนรับผิดชอบ แยกไม่ออกว่าใครสั่ง และเผางบโดยไม่มีคนอนุมัติ (ADR 0043)
- **รวมกับงานตอนว่างเป็นก้อนเดียว**: เป็นไปได้เพราะเกิดในเครื่องเหมือนกัน แต่เงื่อนไขตื่นคนละแบบ (event ในเครื่องตื่นตามสิ่งที่เกิด ตอนว่างตื่นตามสภาพว่าง) รวมกันจะทำให้กฎตื่นซับซ้อน จึงแยกฉบับ
- **ไว้ทีหลัง ไม่เลือกทิศตอนนี้**: ได้เช่นกัน แต่ทิศนี้เล็กพอ (ต่อจากตั้งเวลาเกือบตรงๆ) จึงเลือกเลย

## Consequences

- กฎกันรัวตัดสินแล้ว (เจ้าของ 2026-11-01): เหตุการณ์ถี่ๆ รวมเป็นงานเดียว รอเงียบประมาณ 5 นาที (ตั้งค่าได้) แล้วค่อยให้ agent ทำงาน
- สิทธิ์สร้างคำสั่งเฝ้าตัดสินแล้ว (เจ้าของ 2026-11-01): Member ทุกคนที่มี Use สร้างได้ แต่ต้องมีหน้ารายการงานพื้นหลัง/คำสั่งเฝ้าให้ทุกคนดูได้
- ภาษาเงื่อนไขตัดสินทิศแล้ว (เจ้าของ 2026-11-01): ต้องยืดหยุ่นตามคำสั่ง เริ่มจากเงื่อนไขง่าย (ไฟล์เปลี่ยน/ไฟล์ใหม่) แล้วเพิ่มแบบได้ทีหลังแบบ additive (ADR 0023) รายละเอียดขอบเขตเป็นงานก่อนสร้างจริง
- ขอบเขตใน ADR 0027 อัปเดตตามทิศนี้ เหลือกฎกันงานพื้นหลังแย่งงบงานคนเป็นงานออกแบบชิ้นสุดท้ายของชุดเชิงรุก
