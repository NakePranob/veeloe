# รอบที่ไม่มีคนเฝ้าไม่ขอ Approval: สิ่งที่ทำได้ถูกเซ็นไว้กับ Schedule ตั้งแต่ตอนตั้ง

> **ADR 0087 แก้บางส่วน** รอบที่ไม่มีคนเฝ้าใช้ระดับในโฟลเดอร์ ยกเว้นโฟลเดอร์ที่ระบุไว้ใน scope ที่เซ็นของ Schedule

> **ADR 0080 แก้บางส่วน** รอบไม่ถูกข้ามเพราะมี Turn อื่นทำอยู่ ข้ามเฉพาะเมื่อรอบก่อนของ Schedule เดียวกันยังไม่จบ

> **แทนที่บางส่วนของ ADR 0027** ข้อที่ว่า "Grant กับ Approval ทำงานเหมือนเดิมทุกอย่าง" ใช้กับรอบที่ Member กด "รันเลย" เท่านั้น ไม่ใช้กับรอบที่ถึงเวลาเอง

รอบของ Schedule ที่ถึงเวลาเองไม่มีใครเฝ้าอยู่ ถ้ารอบนั้นขอ Approval ระบบจะถือ Agent ไว้จน Approval หมดอายุ (ค่าเริ่มต้น 1 ชั่วโมง) ระหว่างนั้นรอบถัดไปจะถูกข้ามเพราะ Agent ไม่ว่าง และ Task ที่คนพิมพ์เองก็ต้องรอด้วย ทั้งที่สุดท้ายคำขอก็ถูกนับว่าปฏิเสธอยู่ดี

แต่ละ Schedule จึงมี scope ของตัวเอง เป็นรายการแบบเดียวกับ Allowlist (ADR 0030) คือคำนำหน้าของคำสั่ง bash และชื่อเต็มของ tool ของ Connector ซึ่งเซ็นมากับ `trigger.set` และใช้ได้เฉพาะรอบของ Schedule นั้น รอบที่ถึงเวลาเองจะไม่ขอ Approval เลย สิ่งที่อยู่นอก Allowlist ของ Agent และนอก scope ถูกปฏิเสธทันที Task ของรอบนั้นจะบันทึก `approval.skipped` ไว้ แล้ว Agent ทำส่วนที่ทำได้ต่อ รอบที่มีสิ่งถูกปฏิเสธจะจบแบบเงียบไม่ได้ จึงขึ้นใน Inbox เสมอ และ Member กดเพิ่มสิ่งที่ถูกปฏิเสธเข้า scope ได้จากใน Task นั้นเลย โดเมนที่อยู่นอก Egress ก็ถูกปฏิเสธเหมือนกัน แต่ไม่เข้า scope เพราะ Egress เป็นของ Agent ทั้งตัว (ADR 0029)

รอบที่ Member กด "รันเลย" มีคนเฝ้าอยู่ จึงขอ Approval ตามปกติ ทุก Approval ในรอบแบบนี้เลือก "ให้ Schedule นี้ทำได้เลย" ได้ ซึ่งจะเพิ่มคำสั่งนั้นเข้า scope การลองรันหนึ่งรอบจึงเป็นวิธีสร้าง scope ที่พอดีกับงาน

scope คือการอนุมัติไว้ล่วงหน้า คนที่เซ็น scope ที่ไม่ว่างจึงต้องมี Approve ที่ Agent นั้น ถ้าคนเซ็นเสีย Approve ไปทีหลัง รอบต่อไปจะทำงานเหมือน scope ว่าง แต่ Schedule ไม่หยุด เพราะคนเซ็นยังมี Use อยู่

## Considered Options

- **ขอ Approval ตอนถึงรอบเหมือนเดิม และส่ง push**: ไม่ต้องตั้งอะไรล่วงหน้า แต่ Agent ถูกถือไว้จนกว่าจะมีคนตอบ ถ้า Schedule รันตอนตีสาม คำขอก็จะหมดอายุก่อนที่ใครจะตื่นมาเห็น
- **ให้ Agent ทั้งตัวทำได้ทุกอย่างในรอบของ Schedule**: ไม่ต้องตั้งอะไรเลย แต่ข้อความที่เซ็นไว้ครั้งเดียวจะกลายเป็นสิทธิ์ที่ไม่มีขอบเขต และ prompt injection จากหน้าเว็บที่ Agent อ่านในรอบนั้นจะรันอะไรก็ได้
- **เพิ่มสิ่งที่ต้องการเข้า Allowlist ของ Agent แทน**: ใช้ของที่มีอยู่แล้ว แต่สิทธิ์ที่จำเป็นสำหรับงานตอนตีสามจะติดไปกับทุก Task ที่คนพิมพ์ด้วย และการแก้ Allowlist ต้องใช้ Manage ไม่ใช่ Approve
- **ทำให้ Approval ที่ค้างในรอบที่ไม่มีคนเฝ้าหมดอายุเร็วขึ้น**: Agent ถูกถือไว้สั้นลง แต่รอบนั้นก็ยังทำไม่ได้ และผู้ใช้ไม่ได้อะไรเพิ่ม

## Consequences

- Schedule ใหม่ที่ scope ว่างจะทำได้แค่สิ่งที่ Allowlist ของ Agent กับ ADR 0075 ให้ผ่านอยู่แล้ว คนตั้งควรกด "รันเลย" หนึ่งครั้งเพื่อดูว่ารอบนั้นต้องใช้อะไร
- รอบที่ถูกปฏิเสธบางส่วนจะขึ้นใน Inbox เสมอ เพื่อไม่ให้สิ่งที่ทำไม่สำเร็จหายไปเงียบๆ
- การ์ดของ Schedule แสดงผลของรอบล่าสุด รวมถึงรอบที่ถูกข้ามและเหตุผลที่ข้าม supervisor จึงเก็บรอบที่ถูกข้ามครั้งล่าสุดไว้ด้วย
- Idle Work (ADR 0056) และ Watch (ADR 0057) ก็มีรอบที่ไม่มีคนเฝ้า และใช้หลักเดียวกันนี้
- scope ไม่ครอบโดเมน โดเมนที่ Schedule ต้องใช้ ต้องอยู่ใน Egress ของ Agent
