# Stop จบแค่ Turn ไม่ย้อนไฟล์กลับ และหยุด Task ย่อยทั้งหมดที่อยู่ข้างใต้

การกด Stop ทำให้ Turn ที่กำลังทำอยู่จบทันที ไฟล์ที่แก้ไปแล้วคงสภาพเดิม และ Task ยังคุยต่อได้ด้วย context เดิม เช่น พิมพ์ต่อว่า "ไม่ใช่แบบนั้น ทำแบบนี้แทน" Stop ไหลลงไปตามสาย Delegation ภายใน Runtime (Team อยู่บน Machine เดียว ADR 0026) ทำให้ Turn ของ Task ย่อยทั้งหมดที่อยู่ข้างใต้หยุดตามด้วย แต่ไม่ไหลย้อนขึ้นไปหา Task แม่ ถ้า Stop ที่ Task ย่อยตัวเดียว Agent แม่จะได้รับแจ้งว่า Task ย่อยถูกหยุด แล้วตัดสินใจเองว่าจะทำอะไรต่อ ก่อนกด Controller จะแสดงให้ดูว่ามี Task ไหนจะหยุดตามบ้าง Stop เป็นคำสั่งที่ต้องเซ็นเหมือนคำสั่งอื่น (ADR 0006) และทำในนามของ Member ที่กด Member ที่มี Use กับ Agent ตัวไหน กด Stop ได้ทุก Turn ของ Agent ตัวนั้น ไม่ว่าใครเป็นคนสั่ง เพราะ Stop เป็นเบรก ไม่ได้ทำให้ใครทำอะไรเกินสิทธิ์ และคนที่เห็นว่า Agent กำลังทำพลาดควรหยุดได้ทันที Stop ที่ Task ของ Team ไหลลงไปถึง Agent ลูกทุกตัว แม้คนกดจะไม่มี Use ที่บางตัว ส่วนคนในแชตของ Channel กด Stop ไม่ได้ (ADR 0028)

## Considered Options

- **หยุดแล้วย้อนไฟล์กลับ**: ปลอดภัยกว่า แต่ Runtime ต้องเก็บสำเนา Workdir ก่อนทุก Turn ซึ่งทำได้ยากถ้า Workdir ไม่ใช่ git หรือใหญ่มาก และย้อนสิ่งที่ shell ทำไว้นอกไฟล์ไม่ได้อยู่ดี เช่น การ deploy หรือการแก้ database
- **หยุดแล้วปิด Task**: ถ้าจะทำต่อต้องเริ่ม Task ใหม่และเสีย context เดิม
- **หยุดแค่ Task ที่กด**: เลี่ยงการหยุดงานอันตรายกลางทางได้ แต่ถ้าอยากหยุดทั้งสาย ต้องไล่กดทีละ Task

## Consequences

- Turn ที่ค้างอยู่ตอน worker หรือ Runtime เริ่มใหม่จบด้วยกฎเดียวกับ Stop (ADR 0033)
- Stop ถูกบันทึกลง event log ว่าใครกด ถ้ามีคนกดขัดงานคนอื่นบ่อย ไล่ย้อนดูได้
- Stop อาจหยุดงานที่ทำค้างไว้ครึ่งทาง เช่น migrate database ที่ทำไปได้ครึ่งหนึ่ง Controller จึงต้องแสดงให้เห็นว่ามี Task ไหนจะหยุดตามบ้างก่อนกด
