# UI ของ Controller เป็นขาวดำ เขียนด้วย Uniwind และ component ของ React Native Reusables ที่คัดลอกมาไว้ใน repo ส่วนหน้าตาอยู่ใน DESIGN.md

Controller เป็นที่ที่คนกด Approve หรือ Stop คำสั่งที่รันอยู่บนเครื่องจริง บางครั้งเป็นการ deploy ขึ้น production จากมือถือ หน้าจอจึงต้องนิ่งและชัด ไม่มีอะไรแย่งความสนใจตอนที่คนกำลังตัดสินใจ เราจึงให้ส่วนที่เป็นเครื่องมือเป็นขาวดำทั้งหมด สีหลักคือสีที่ตัดกับพื้นมากที่สุด ได้แก่ดำใน light mode และขาวใน dark mode สีมีแค่สองที่: Character ของแต่ละ Agent กับสีของสถานะ

หน้าจอจัดตาม Agent ไม่ใช่ตามหมวด หน้าแรกเป็น inbox ที่มีหนึ่งแถวต่อหนึ่ง Agent และ Agent ที่รอคุณขึ้นก่อน บนมือถือไม่มี tab bar ส่วนบนจอกว้างแบ่งเป็นสามช่อง คือ inbox, Task ที่เปิดอยู่ และแผงรายละเอียดของ Agent ข้อความของคนสั่งอยู่ในฟอง ส่วนข้อความของ Agent ไม่มีฟอง เพราะมักยาวและมีโค้ด สถานะยังมีสามชั้นจาก event log เดียวกัน (ADR 0018): บรรทัดสถานะในหัวของ Task, ขั้นตอนในแผงหรือในหน้าโปรไฟล์ และ log ทั้งหมด รายละเอียดของหน้าตา (token, ฟอนต์, component และกติกา) อยู่ใน `controller/DESIGN.md` ซึ่งเป็นแหล่งข้อมูลจริงเพียงแห่งเดียว

ส่วนเทคนิค:
- **Style:** เขียนด้วย Uniwind (Tailwind v4 บน React Native) token เป็น CSS variable ใน `global.css` ไฟล์เดียว ตั้งชื่อตาม shadcn เพื่อให้ component ของ Reusables อ่านได้โดยไม่ต้องแก้ ซึ่ง React Flow ใน DOM component ของผัง Flow ก็ใช้ชุดเดียวกัน
- **Component:** คัดลอก component ของ React Native Reusables รุ่น Uniwind มาไว้ใน `src/shared/ui` โค้ดเป็นของเราและแก้ได้ทุกบรรทัด เช่นเราเอาเงาออกจากปุ่ม เพราะเงามีไว้ให้ของที่ลอยเท่านั้น Reusables สร้างบน RN Primitives ซึ่ง port มาจาก Radix และใช้ไอคอน Lucide ส่วน Character เราเขียนเอง ถ้า OS มีของให้อยู่แล้วให้ใช้ของ OS ได้แก่ sheet และ modal ของ Expo Router และการเคลื่อนไหวด้วย Reanimated
- **State:** ไม่ใช้ library ข้อมูลอ่านจาก SQLite ด้วย live query (ADR 0021) ส่วน state ของหน้าจอใช้ React state กับ params ของ Expo Router เช่นแผงของ Agent เปิดหรือปิดก็เก็บใน URL
- **ฟอนต์:** ใช้ "Veeloe Sans" ซึ่งรวมตัวอังกฤษของ Geist กับตัวไทยของ Anuphan เป็นไฟล์เดียว เพราะ React Native รับ `fontFamily` ได้ตัวเดียว ถ้าไม่รวม ตัวไทยบนมือถือจะกลายเป็นฟอนต์ของระบบ
- **ภาษา:** มีทั้งอังกฤษและไทยตั้งแต่หน้าจอแรก

ADR นี้ฉบับแรกเลือกเขียน component เองทั้งหมด และใช้แนวของ Muse คือ Character อยู่บนสุดของ Task และไม่มีฟองแชท พอทำ prototype หลายรอบแล้วเทียบกับ Grok Bot ซึ่งเป็นสินค้าแบบเดียวกัน control ที่เขียนเองกับไอคอนที่วาดเองดูเป็นงานสำเร็จรูป และหัวของ Task ที่ใหญ่ก็กินจอมือถือจนเหลือที่อ่านน้อย ฉบับแรกยังปัด Reusables ตกเพราะเข้าใจว่าผูกกับ NativeWind ซึ่งไม่จริง Reusables รองรับ Uniwind ตั้งแต่ ธ.ค. 2025

## Considered Options

- **เขียน component เองทั้งหมด** (ฉบับแรกของ ADR นี้): คุมหน้าตาได้ทุกชิ้น แต่ต้องเขียน dialog, menu และ select เองพร้อม accessibility ทั้งหมด และงานที่ออกมาดูไม่เป็นระบบ
- **Reusables บน NativeWind**: ได้ component ชุดเดียวกัน แต่ Uniwind เร็วกว่าบน React Native
- **HeroUI Native**: สวยและสร้างบน Uniwind โดยตรง แต่รองรับแค่ iOS กับ Android บนเว็บต้องใช้ HeroUI React อีกชุด
- **Expo UI (`@expo/ui`)**: เป็น SwiftUI และ Jetpack Compose จริง แต่ฝั่งเว็บยัง experimental และยังไม่ชัดว่าใส่ token กับฟอนต์ของเราได้แค่ไหน อาจใช้เฉพาะบาง control ทีหลัง
- **Tamagui**: มีครบทั้ง component, theme และ compiler แต่ API เป็นของตัวเองและผูกแน่น
- **Character อยู่บนสุดของ Task และไม่มีฟองแชท (แนวของ Muse)**: Character เด่น แต่หัวใหญ่กินที่บนมือถือ และแยกไม่ออกว่าข้อความไหนเป็นของใครเมื่อมีหลาย Agent ใน Task เดียว
- **Zustand หรือ Jotai**: มีที่เก็บ state ของ UI กลาง แต่คนจะเอาข้อมูลจริงไปใส่ใน store ซ้ำกับ SQLite จนกลายเป็นสองแหล่งที่อาจไม่ตรงกัน
- **ปล่อยให้เครื่องเลือกฟอนต์ไทยเอง**: ไม่ต้องทำอะไร แต่ตัวไทยจะเป็น Sukhumvit บน iOS และ Noto บน Android หน้าตาไม่เหมือนกันและไม่ใช่ Anuphan

## Consequences

- **accessibility ส่วนหนึ่งได้มาจาก RN Primitives:** dialog, menu และ select มี focus และ role มาให้ ส่วนที่เหลือยังเป็นงานของเรา ได้แก่ label ของปุ่มที่มีแต่ไอคอน, พื้นที่ให้แตะอย่างน้อย 44 และการขยายตัวอักษร กติกาเหล่านี้อยู่ใน DESIGN.md
- **Reusables ไม่อัปเดตเอง:** ถ้าจะเอารุ่นใหม่ ต้องคัดลอกจาก registry ใหม่แล้วเทียบกับที่เราแก้ไว้ ไฟล์ที่มาจาก Reusables บอกไว้ในบรรทัดแรกว่ามาจากไหนและแก้อะไร
- **ต้องมีสคริปต์รวมฟอนต์:** ใช้ fonttools ทำครั้งเดียวต่อการอัปเดตฟอนต์ต้นทาง ฟอนต์ที่รวมแล้วต้องใช้ OFL และตั้งชื่อใหม่ จนกว่าจะมี แอปใช้ฟอนต์ของระบบ ส่วนฟอนต์ mono กำหนดแยกต่อ platform ใน `global.css` เพราะ iOS กับ Android ไม่มี `ui-monospace`
- **Character เลือกใช้ Rive** เพราะ state machine ของ Rive รับ Mood เป็น input ได้ตรงๆ แต่ยังต้องยืนยันพร้อมกับการออกแบบหน้าตาของ Character (#23) ระหว่างนี้เป็น SVG นิ่ง
- **ข้อความทุกชิ้นต้องผ่านตารางแปลตั้งแต่ตั๋วแรก (#8):** คำใน CONTEXT.md ใช้เหมือนกันทั้งสองภาษา ส่วนคำที่เป็นการกระทำแปลเป็นไทย
- **DESIGN.md กับ `global.css` ต้องแก้ไปพร้อมกันเสมอ:** ถ้าไม่แก้คู่กัน agent จะทำตาม token ที่ไม่ตรงกับของจริง
- **`uniwind-types.d.ts` ต้องอยู่ใน git:** Metro สร้างไฟล์นี้ขึ้นมา แต่ typecheck ใน CI รันก่อนที่ Metro จะได้รัน ถ้าไม่มีไฟล์นี้ `className` จะไม่ผ่าน typecheck
