# ขึ้น store ด้วย Demo Workspace, ขายบนเว็บอย่างเดียว และลบบัญชีในแอปได้โดยมีเวลารอ 30 วัน

**review:** reviewer ของ Apple ไม่มี Machine และไม่มี Controller เดิมไว้ทำ Linking (ADR 0013) แอปจึงมี Demo Workspace ที่อยู่บน Controller อย่างเดียว ใส่ event ตัวอย่างลง SQLite บนเครื่อง (ADR 0021) แล้วให้ลองทุกฟีเจอร์ได้ ทั้ง Task, Approval, Project และ Character โดยไม่ต่อ Hub เลย Apple ยอมรับโหมดตัวอย่างที่ใช้ได้ครบทุกฟีเจอร์แทน demo account ได้ วิธีนี้ไม่มีทางเข้าพิเศษสู่ระบบจริงให้ใครหาช่องโจมตีได้ และใช้เป็น onboarding ให้คนที่ยังไม่ได้ติดตั้ง Runtime ด้วย ส่วนการใช้งานจริงให้แนบวิดีโอ Pairing กับเครื่องจริงไว้ใน review notes

**การขาย:** subscription ขายบนเว็บอย่างเดียว ในแอปไม่มีราคา ไม่มีปุ่มซื้อ และไม่มีลิงก์ไปซื้อ (3.1.3(b)) เราจึงไม่เสีย 15-30% ให้ store และมีระบบเก็บเงินระบบเดียว เมื่อเกินโควตาตอน Pairing (ADR 0001) แอปบอกได้แค่ว่าเกินโควตา ถ้ากฎของ store สหรัฐฯ ยังอนุญาต ค่อยเพิ่มลิงก์ไปซื้อให้เฉพาะ store นั้น

**การลบบัญชี:** แอปมีเมนูลบบัญชี (5.1.1(v)) เมื่อกด Hub จะเตรียมลบ email, Controller, Grant และ push token ของ Member คนนั้น และ Task ที่คนนั้นเคยสั่งจะแสดงเป็น "Member ที่ลบบัญชีแล้ว" ถ้าเป็น Owner คนสุดท้าย ต้องยืนยันก่อนว่าจะลบ Workspace ทั้งหมดด้วย subscription ถูกยกเลิกทันที แต่การลบจริงรอ 30 วัน ระหว่างนั้น Workspace ถูกแช่แข็ง Hub ปฏิเสธทุกอย่าง ยกเว้นคำสั่ง "ยกเลิกการลบ" ที่เซ็นมาจาก Controller เดิม เมื่อครบ 30 วัน Hub ลบข้อมูลทั้งหมดและไม่รับ Machine ของ Workspace นั้นอีก Runtime ที่ได้คำตอบว่า Workspace ถูกลบแล้วแสดงสถานะนี้ใน CLI และลดความถี่ในการต่อใหม่ แต่ไม่ลบอะไรบนเครื่องและไม่หยุดลองถาวร เพราะ Hub ที่โดนเจาะปลอมคำตอบนี้ได้ เจ้าของเครื่องที่อยากเก็บกวาดรัน `veeloe unpair` เอง เราไม่ให้ Owner เซ็นคำสั่งเลิกผูกไว้ล่วงหน้า เพราะถ้ายกเลิกการลบ คำสั่งนั้นจะค้างอยู่ในมือ Hub และใช้ได้ตลอดไป เนื่องจากลายเซ็นไม่ได้ผูกกับเวลา (ADR 0019) ทั้งที่ Hub ที่โดนเจาะตัดทุกเครื่องได้อยู่แล้วด้วยการไม่ส่งต่อข้อความ ลายเซ็นจึงไม่ได้กันอะไรเพิ่ม ส่วนประวัติ Task และค่าของ Agent บนเครื่องของลูกค้ายังอยู่ เพราะเป็นข้อมูลของลูกค้าบนเครื่องของลูกค้า (ADR 0005) แอปจะบอกวิธีลบเอง

## Considered Options

- **Workspace สำหรับ review ที่เรารันจริง**: ใกล้กับของจริงที่สุด แต่ต้องดูแล VM ให้ออนไลน์ตลอดช่วง review และต้องมีทางเข้าที่ข้าม Linking อยู่ใน Hub จริง
- **ขายในแอปด้วย IAP**: ซื้อได้ทันทีตอนเกินโควตา แต่ store หัก 15-30% และต้องมีระบบเก็บเงินสองระบบ
- **ให้ Runtime ลบข้อมูลบนเครื่องของลูกค้าด้วย**: สะอาดกว่า แต่เป็นการลบข้อมูลบนเครื่องคนอื่นจากระยะไกล ถ้าเครื่องออฟไลน์อยู่ก็ส่งคำสั่งไม่ถึง และถ้าลบผิดก็กู้คืนไม่ได้
- **ลบทันทีไม่มีเวลารอ**: ง่ายกว่า แต่ถ้ากดผิด ต้องตั้ง Workspace กับทำ Pairing ใหม่ทุกเครื่อง

## Consequences

- ต้องมี event ตัวอย่างฝังมากับแอป และต้องอัปเดตตามทุกครั้งที่ event เปลี่ยนรูปแบบ (ADR 0018, 0023)
- Hub ต้องมีสถานะ "รอลบ" กับงานที่คอยลบเมื่อครบกำหนด
- การเพิ่มลิงก์ไปซื้อใน store สหรัฐฯ ขึ้นกับกฎของ Apple ในตอนนั้น ต้องเช็กใหม่ทุกครั้งที่จะส่ง review
