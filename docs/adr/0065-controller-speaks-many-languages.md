# Controller รองรับหลายภาษา โดยข้อความอยู่กับเจ้าของ และ Runtime กับ Hub ส่ง code ไม่ส่งประโยค

Controller ต้องรองรับภาษาไทยและอังกฤษตั้งแต่แรก และเพิ่มภาษาอื่นได้ในอนาคต ถ้าเขียนข้อความลงในหน้าจอตรงๆ แบบ `controller-prototype` แล้วค่อยแก้ทีหลัง จะต้องไล่แก้ทุกหน้าจอ และถ้า Runtime หรือ Hub ส่งประโยคมาใน Protocol แอปจะแปลไม่ได้เลย เรื่องนี้จึงต้องตัดสินก่อนเริ่มเขียน Protocol และ Controller

ข้อความอยู่ใน slice ที่ใช้มันตามโครงของ ADR 0022 เช่น `src/pages/inbox/i18n/th.json` และ `en.json` ส่วนคำที่ใช้ร่วมกันอยู่ใน `src/shared/i18n/` ลบหน้าจอแล้วคำก็หายไปด้วย จึงไม่มีไฟล์กลางที่สะสมคำที่เลิกใช้ โค้ดเรียกข้อความด้วย key ที่บอกความหมาย เช่น `task.approval.expiresIn` และส่งค่าเป็นตัวแปร ห้ามต่อประโยคด้วย string เพราะแต่ละภาษาเรียงคำไม่เหมือนกัน key ตรวจด้วย type และ CI ตรวจว่าภาษาไทยกับอังกฤษมี key ครบ การเพิ่มหน้าจอต้องเขียนทั้งสองภาษาใน change เดียวกัน ภาษาอื่นที่ขาดคำใช้ภาษาอังกฤษแทน

แอปอ่านภาษาจากเครื่องด้วย `expo-localization` และใช้ `i18next` จัดการข้อความกับรูปพหูพจน์ วันที่และตัวเลขใช้ `Intl` เครื่องที่ใช้ภาษาที่ยังไม่รองรับเริ่มที่ภาษาอังกฤษ และ Member เปลี่ยนภาษาในแอปได้ ค่านี้เป็นของแต่ละเครื่อง

Runtime และ Hub ส่ง error และสถานะเป็น code กับค่าประกอบ ไม่ส่งประโยคที่ให้คนอ่าน แอปเป็นคนแปล Protocol ที่เพิ่ม code ใหม่ทำแบบ additive (ADR 0023) ดังนั้นแอปรุ่นเก่าที่ไม่รู้จัก code ต้องแสดงข้อความกลางที่บอกว่าเกิดอะไรขึ้นแบบกว้างๆ พร้อม code นั้น ส่วนสิ่งที่ Agent เขียน และชื่อที่คนตั้ง เช่นชื่อ Agent หรือ Task ไม่แปล แสดงตามที่ได้รับ

คำใน `CONTEXT.md` เช่น Agent, Task และ Approval คงเป็นภาษาอังกฤษในทุกภาษา เพื่อให้แอป เอกสาร และ ADR พูดคำเดียวกัน ส่วนประโยครอบคำเหล่านั้นแปลตามปกติ

ข้อความใน push ควรให้แอปแปลบนเครื่องจาก code และค่าประกอบ เพื่อให้ Runtime ไม่ต้องรู้ภาษาของแต่ละเครื่อง ข้อนี้ยังต้องลองกับ iOS และ Android ใน change `push-notifications` ถ้าทำไม่ได้ครบ ให้กลับมาแก้ ADR นี้

เริ่มที่ Controller ก่อน รวมถึง Demo Workspace ที่อยู่ในแอป (ADR 0024) ส่วนเว็บอื่นตัดสินเมื่อมีจริง

## Considered Options

- **ไฟล์ข้อความกลางไฟล์เดียวต่อภาษา**: หาง่ายและส่งให้นักแปลง่าย แต่ไฟล์โตเรื่อยๆ และคำที่เลิกใช้ค้างอยู่ เพราะไม่ผูกกับเจ้าของ
- **ใช้ประโยคภาษาอังกฤษเป็น key**: เขียนเร็วและอ่านโค้ดรู้เรื่อง แต่แก้คำหนึ่งครั้งต้องแก้ key ในทุกภาษา และคำเดียวกันที่ความหมายต่างกันตามบริบทแยกไม่ได้
- **เขียนตัวแปลภาษาเอง**: ไม่เพิ่ม dependency แต่ต้องดูแลรูปพหูพจน์ของทุกภาษาเอง
- **Runtime ส่งประโยคตามภาษาของ Member**: แอปไม่ต้องรู้จัก code แต่ Runtime ต้องเก็บคำแปล และเครื่องหลายเครื่องของคนเดียวกันใช้คนละภาษาไม่ได้
- **แปลคำใน glossary เป็นภาษาไทยด้วย**: คนทั่วไปอ่านง่ายกว่า แต่แอปกับเอกสารจะพูดคนละคำ และบางคำยังไม่มีคำไทยที่ตรง
- **เขียนภาษาไทยก่อน แล้วแปลภายหลัง**: เร็วกว่าตอนทำแต่ละหน้าจอ แต่งานแปลจะค้างและตรวจใน CI ไม่ได้

## Consequences

- ทุก change ที่เพิ่มหน้าจอช้าลงเล็กน้อย เพราะต้องเขียนสองภาษา
- `protocol-envelope` ต้องกำหนดรูปแบบของ error code กับค่าประกอบตั้งแต่แรก
- ข้อความอังกฤษมักยาวกว่าหรือสั้นกว่าไทย หน้าจอต้องรองรับข้อความที่ยาวต่างกันในทั้งสองภาษา
- Member ที่ไม่คุ้นคำอย่าง Agent หรือ Approval ต้องเรียนรู้คำเหล่านี้ แอปจึงควรอธิบายด้วยประโยคตรงจุดที่พบครั้งแรก
- `controller-prototype` ไม่ต้องแก้ เพราะเป็นของที่จะทิ้ง
