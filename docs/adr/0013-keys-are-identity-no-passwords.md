# ใช้กุญแจเป็นตัวตน ไม่มีรหัสผ่าน

Controller และ Runtime ทุกตัวต้องต่อสายเข้า Hub และต้องพิสูจน์ตัวตนทุกครั้ง เพราะใน v0.1 ยังไม่มี E2E Hub ส่งเนื้อหาของ Task ให้ใครก็ตามที่ Hub เชื่อว่าเป็น Controller ของ Workspace นั้น การพิสูจน์ทำแบบนี้: Hub ส่งข้อความสุ่มมาให้ แล้วอีกฝั่งเซ็นกลับด้วยกุญแจ Ed25519 ของตัวเอง (ADR 0012) Hub จึงต้องรู้กุญแจสาธารณะของทุก Controller และทุก Machine ซึ่งไม่ขัดกับ ADR 0006 เพราะกุญแจสาธารณะไม่ใช่ความลับ และ Runtime ก็ไม่ได้เชื่อรายชื่อกุญแจจาก Hub แต่เชื่อเฉพาะกุญแจที่ได้มาตอน Pairing หรือ Linking

Controller ตัวแรกเป็นคนสร้างกุญแจและสร้าง Workspace แล้วกลายเป็น Owner ยกเว้นแอปที่เปิดจากลิงก์ Invitation ซึ่งเข้า Workspace ที่มีอยู่แล้ว (ADR 0031) ส่วน Controller เครื่องต่อไปของ Member คนเดิมเข้ามาด้วย Linking คือเครื่องใหม่แสดง QR แล้วให้ Controller เครื่องเดิมสแกน email ใช้แค่กับเรื่อง billing และกู้บัญชีที่ Hub เท่านั้น ใช้สั่งหรือดู Machine ไม่ได้

## Considered Options

- **email/OAuth สำหรับ Hub ควบคู่กับกุญแจสำหรับ Runtime**: คนคุ้นเคยกว่า แต่ต้องทำสองระบบ และคนที่ login ได้แต่ยังไม่ผ่าน Linking จะงงว่าทำไมสั่งงานไม่ได้
- **ใช้บริการ auth สำเร็จรูป เช่น Clerk**: ได้หน้า login, หน้าเชิญคน และ MFA มาเลย แต่ต้องเพิ่มผู้ให้บริการอีกเจ้า ซึ่งขัดกับ ADR 0007 และยังต้องทำ Linking อยู่ดี

## Consequences

- ไม่มีรหัสผ่านให้หลุด ให้ลืม หรือให้ต้องรีเซ็ต
- เบราว์เซอร์ใส่ header เองตอนเปิด WebSocket ไม่ได้ ข้อความสุ่มของ Hub กับลายเซ็นที่ตอบกลับจึงต้องส่งเป็น frame แรกของ WebSocket แทน header เพื่อให้ Controller บนเว็บใช้ได้ด้วย
- ถ้า Controller หายหมดทุกตัว การกู้ด้วย email จะได้คืนแค่บัญชีที่ Hub ส่วน Machine ต้องไปทำ Pairing ใหม่ที่หน้าเครื่อง ถ้า Workspace มี Owner คนอื่น ให้ Owner คนนั้นเชิญกลับเข้ามาแทน (ADR 0031)
- การเชิญ Member คนอื่น (ADR 0010) ใช้ Invitation ซึ่งเชิญจากที่ไกลได้ โดยทั้งสองฝั่งเทียบรหัสสั้นที่คำนวณจากกุญแจแทนการสแกนต่อหน้า (ADR 0031)
