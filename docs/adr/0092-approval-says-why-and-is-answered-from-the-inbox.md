# Approval บอกเหตุผลจาก Agent และตอบได้จาก Inbox โดยไม่ต้องเปิด Task

Status: accepted

> ขยาย ADR 0060 ที่ให้การ์ด Approval แสดงคำสั่งกับเหตุผลจาก Agent แต่ไม่ได้บอกว่าเหตุผลมาจากไหน

การ์ด Approval ตอนนี้มีแค่คำสั่ง คนอนุมัติไม่รู้ว่า Agent จะรันไปทำไม ต้องเปิด Task ไล่อ่านแชตเอง และการ์ดอยู่ในหน้า Task เท่านั้น คนที่เห็นแถว "รอคุณ" ใน Inbox ต้องเปิด Task ก่อนถึงจะตอบได้ ทั้งที่ ADR 0060 ตั้งใจให้คนอนุมัติตัดสินจากการ์ดได้ และเปิดบทสนทนาเฉพาะเมื่ออยากดู (เจ้าของตัดสิน 2026-11-28)

**เหตุผลมาจาก tool** tool ที่ทำให้เกิด Approval (`bash` และการขอโดเมนผ่าน proxy) มีช่อง `reason` ที่ต้องใส่ เป็นประโยคสั้นหนึ่งประโยคว่าทำไปเพื่ออะไร เขียนให้คนอนุมัติอ่าน Runtime ส่ง `reason` ไปกับ event `approval.requested` และเก็บไว้ใน Task เหมือนส่วนอื่นของคำขอ คำขอที่ไม่มีเหตุผล (Agent ไม่ใส่ หรือ Runtime รุ่นเก่า) ยังขอได้ การ์ดแสดงว่าไม่มีเหตุผลมา ไม่ปฏิเสธเอง เพราะการปฏิเสธเพราะลืมเขียนจะทำให้งานหยุดโดยไม่มีใครรู้สาเหตุ

**เหตุผลเป็นคำพูดของ Agent** การ์ดแสดงเหตุผลก่อนคำสั่ง ในรูปคำพูดของ Agent ไม่ใช่ข้อเท็จจริงที่ระบบตรวจแล้ว คำสั่งเต็มหรือโดเมนอยู่บนการ์ดเสมอและไม่ถูกตัดหรือซ่อนไว้หลังเหตุผล เพราะ Agent ที่โดนหลอกจากข้อมูลที่อ่านมาเขียนเหตุผลที่ฟังดูดีได้ (ADR 0060)

**ตอบจาก Inbox** แถวใน Inbox ที่มี Approval รออยู่มีปุ่มตอบของตัวเอง แตะแล้วเปิด sheet ที่มีชื่อ Agent, เหตุผล, คำสั่งหรือโดเมน และตัวเลือกเดียวกับการ์ดในหน้า Task ตามระดับสิทธิ์ของคนนั้น (อนุมัติ, ไม่อนุมัติ, บอกให้ทำอย่างอื่น และอนุญาตตลอดเมื่อมี Manage) การตอบยังต้องยืนยันตัวตามกติกาเดิม (ADR 0012, 0089) แตะตัวแถวยังเปิดแชตเหมือนเดิม sheet มีปุ่มดูบทสนทนาที่เปิด Task และถ้าคนเปิดไม่ใช่คนเริ่ม แอปบันทึกการเปิดไว้ใน Task ตาม ADR 0060 ถ้ามีหลาย Approval รออยู่ ตอบเสร็จหนึ่งรายการแล้ว sheet ไปรายการถัดไปของคนนั้น

push ของ Approval (ADR 0044) เปิด sheet เดียวกันนี้ และยังไม่มีเนื้อหาจนกว่าจะมี E2E (ADR 0005) การตอบจาก notification โดยไม่เปิดแอปยังไม่ทำ

## Considered Options

- **Runtime สรุปเหตุผลจากข้อความล่าสุดของ Agent**: ไม่ต้องเปลี่ยน tool แต่ข้อความล่าสุดอาจไม่เกี่ยวกับคำสั่งนี้ และ Runtime ต้องเดาว่าตัดตรงไหน
- **ให้ LLM อีกตัวอธิบายคำสั่ง**: อธิบายได้แม้ Agent ไม่เขียน แต่เสียค่า token ทุกคำขอ และยังเป็นข้อความที่ไม่มีใครตรวจเหมือนกัน
- **ปฏิเสธคำขอที่ไม่มีเหตุผล**: บังคับให้ Agent เขียนเสมอ แต่ Turn ล้มเพราะ Agent ลืม และ Runtime รุ่นเก่าใช้ไม่ได้
- **แตะแถวใน Inbox แล้วเปิด sheet แทนแชต**: ตอบได้เร็วที่สุด แต่แถวเดียวกันทำงานต่างกันตามสถานะ และขัดกับที่แถวใน Inbox เปิดแชตตรง
- **ตอบจาก notification เลย**: เร็วที่สุด แต่ push ยังไม่มีเนื้อหาจนกว่าจะมี E2E คนจะอนุมัติโดยไม่เห็นคำสั่ง

## Consequences

- คำอธิบายของ tool บอก Agent ว่า `reason` มีไว้ให้คนอนุมัติอ่าน และควรบอกเป้าหมาย ไม่ใช่อ่านคำสั่งซ้ำ
- `approval.requested` มีช่องใหม่ที่ไม่บังคับ Controller รุ่นเก่าที่ไม่รู้จักยังแสดงการ์ดได้ (ADR 0023)
- Inbox ต้องรู้ว่า Approval ไหนรอคนนี้อยู่และของ Task ไหน ซึ่งมีอยู่แล้วจากการส่ง Approval ไปหาคนที่มี Approve (ADR 0044)
