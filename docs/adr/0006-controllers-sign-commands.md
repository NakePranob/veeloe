# คำสั่งต้องเซ็นด้วยกุญแจของ Controller และ Runtime ต้องตรวจลายเซ็นก่อนทำ

TLS สิ้นสุดที่ Hub ถ้า Hub โดนเจาะ คนร้ายจะปลอมเป็นแอปได้ เช่น สร้าง Task, ตอบ Approval เอง หรือแก้ Allowlist และทำได้กับเครื่องของลูกค้าทุกคนพร้อมกัน เราจึงให้ Controller แต่ละตัวมีกุญแจเซ็นของตัวเอง และต้องเซ็นการสร้าง Task, คำตอบ Approval, การแก้ค่า Agent และการแก้ Team ทุกครั้ง Runtime ตรวจลายเซ็นกับกุญแจที่ตัวเองรู้จักก่อนลงมือทำ Runtime เองก็มีกุญแจ และวันที่มีทีมข้ามเครื่องต้องเซ็น Delegation ที่ส่งออกไป (ADR 0026) ตอน Pairing กุญแจแลกกันผ่าน QR ที่แสดงบน Machine Hub จึงไม่เคยเห็นกุญแจ ค่าของ Agent (รวม Allowlist) และค่าของ Team กับ Flow เก็บตัวจริงไว้ที่ Runtime ส่วน Hub รู้แค่ชื่อ คำอธิบาย Machine ที่ Agent อยู่ และ Character ไว้ใช้วาด Character เก็บที่ Hub ได้เพราะไม่ใช่เนื้อหาของ Task และไม่มีผลกับสิทธิ์อะไร

## Consequences

- จะเพิ่ม Controller ใหม่ (เช่น login บนมือถือเครื่องใหม่) ต้องให้ Controller เดิมกดอนุญาตก่อน คล้าย linked devices ของ Signal
- ถ้า Controller ทุกตัวหาย ต้องทำ Pairing กับ Machine ใหม่
- Hub ที่โดนเจาะส่งงานนอกเส้นใน Flow ไม่ได้ เพราะ Runtime เป็นคนตรวจเส้นเอง และ Flow แก้ได้ด้วยคำสั่งที่เซ็นเท่านั้น (ADR 0026) วันที่มีทีมข้ามเครื่องและ Hub กลับมาตรวจเส้น ถ้า Hub กับ Machine เครื่องหนึ่งโดนเจาะพร้อมกันจะส่งงานนอกเส้นได้ ให้ Runtime ฝั่งรับตรวจเส้นซ้ำกับ Flow ที่ Controller เซ็นอีกชั้น
