# คำสั่งต้องเซ็นด้วยกุญแจของ Controller และ Runtime ต้องตรวจลายเซ็นก่อนทำ

TLS สิ้นสุดที่ Hub ถ้า Hub โดนเจาะ คนร้ายจะปลอมเป็นแอปได้ เช่น สร้าง Task, ตอบ Approval เอง หรือแก้ Allowlist และทำได้กับเครื่องของลูกค้าทุกคนพร้อมกัน เราจึงให้ Controller แต่ละตัวมีกุญแจเซ็นของตัวเอง และต้องเซ็นการสร้าง Task, คำตอบ Approval และการแก้ค่า Agent ทุกครั้ง Runtime ตรวจลายเซ็นกับกุญแจที่ตัวเองรู้จักก่อนลงมือทำ Runtime เองก็มีกุญแจและต้องเซ็น Delegation ที่ส่งออกไป ตอน Pairing กุญแจแลกกันผ่าน QR ที่แสดงบน Machine Hub จึงไม่เคยเห็นกุญแจ ค่าของ Agent (รวม Allowlist) เก็บตัวจริงไว้ที่ Runtime ส่วน Hub รู้แค่ชื่อ คำอธิบาย Machine ที่ Agent อยู่ และ Character ไว้ใช้วาดและตรวจ Flow Character เก็บที่ Hub ได้เพราะไม่ใช่เนื้อหาของ Task และไม่มีผลกับสิทธิ์อะไร

## Consequences

- จะเพิ่ม Controller ใหม่ (เช่น login บนมือถือเครื่องใหม่) ต้องให้ Controller เดิมกดอนุญาตก่อน คล้าย linked devices ของ Signal
- ถ้า Controller ทุกตัวหาย ต้องทำ Pairing กับ Machine ใหม่
- ถ้า Hub กับ Machine เครื่องหนึ่งโดนเจาะพร้อมกัน ยังส่งงานข้ามเส้นใน Flow ได้ เพราะคนที่ตรวจเส้นคือ Hub ถ้าต้องปิดช่องนี้ ให้ Controller เซ็น Flow แล้วให้ Runtime ฝั่งรับตรวจเส้นซ้ำอีกชั้น
