# คำสั่งต้องเซ็นด้วยกุญแจของ Controller และ Runtime ต้องตรวจลายเซ็นก่อนทำ

> **ADR 0064 แก้บางส่วน** คำว่าพนักงานของ Project หมายถึงผู้ทำงานในรายชื่อของ Project และพนักงานใน Team ซึ่งแก้ได้ด้วยคำสั่งที่เซ็นเท่านั้นเช่นกัน

TLS สิ้นสุดที่ Hub ถ้า Hub โดนเจาะ คนร้ายจะปลอมเป็นแอปได้ เช่น สร้าง Task, ตอบ Approval เอง หรือแก้ Allowlist และทำได้กับเครื่องของลูกค้าทุกคนพร้อมกัน เราจึงให้ Controller แต่ละตัวมีกุญแจเซ็นของตัวเอง และต้องเซ็นการสร้าง Task, คำตอบ Approval, การแก้ค่า Agent และการแก้ Project ทุกครั้ง Runtime ตรวจลายเซ็นกับกุญแจที่ตัวเองรู้จักก่อนลงมือทำ Runtime เองก็มีกุญแจ ตอน Pairing กุญแจแลกกันผ่าน QR ที่แสดงบน Machine Hub จึงไม่เคยเห็นกุญแจ ค่าของ Agent (รวม Allowlist) และค่าของ Project เก็บตัวจริงไว้ที่ Runtime ส่วน Hub รู้แค่ชื่อ คำอธิบาย Machine ที่ Agent อยู่ และ Character ไว้ใช้วาด Character เก็บที่ Hub ได้เพราะไม่ใช่เนื้อหาของ Task และไม่มีผลกับสิทธิ์อะไร

## Consequences

- จะเพิ่ม Controller ใหม่ (เช่น login บนมือถือเครื่องใหม่) ต้องให้ Controller เดิมกดอนุญาตก่อน คล้าย linked devices ของ Signal
- ถ้า Controller ทุกตัวหาย ต้องทำ Pairing กับ Machine ใหม่ ยกเว้นมี Owner คนอื่นที่เชิญกลับเข้ามาได้ (ADR 0031)
- ข้อความในแชตของ Channel เป็นข้อยกเว้นเดียวที่ไม่ได้เซ็นทีละข้อความ ตัว Channel เป็นสิ่งที่ Member เซ็นไว้แบบเดียวกับ Schedule และงานที่เกิดขึ้นทำในนามของ Member คนนั้น (ADR 0028)
- Hub ที่โดนเจาะส่งงานให้ Agent ที่ไม่ได้เป็นพนักงานของ Project ไม่ได้ เพราะ Runtime เป็นคนตรวจเอง และรายชื่อพนักงานแก้ได้ด้วยคำสั่งที่เซ็นเท่านั้น (ADR 0026, 0045)
- ชื่อ คำอธิบาย และ Character ของ Agent แก้ด้วยคำสั่งที่เซ็นไปที่ Runtime เหมือนค่าอื่นของ Agent Runtime ตรวจ Manage แล้วอัปเดตโปรไฟล์ที่ Hub เอง Hub รับโปรไฟล์ของ Agent จาก Machine ที่ Agent นั้นอยู่เท่านั้น เพราะ Hub ไม่รู้ Grant (ADR 0034) Hub ที่โดนเจาะเปลี่ยนได้แค่หน้าตาที่แอปแสดง และ Runtime ส่งค่าที่ถูกกลับไปทับทุกครั้งที่ต่อเข้ามา ถ้า Machine ปิดอยู่ การแก้รอในคิวขาออกของ Controller และแอปแสดงว่ารอเครื่องออนไลน์
