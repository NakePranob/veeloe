# Agent ทำหลาย Turn พร้อมกันได้ ล็อกที่เขียนเฉพาะตอนจะเขียน และงานของคนได้ล็อกก่อนงานพื้นหลัง

> แทนที่ ADR 0011 และแก้ ADR 0017, 0020, 0026, 0027, 0028, 0033, 0036, 0037, 0043, 0046, 0047, 0056, 0060, 0062, 0067, 0068, 0069, 0073, 0075 และ 0079 บางส่วน ตามที่เขียนไว้ในหัวของแต่ละตัว

ADR 0011 ให้ Agent ทำได้ทีละ Turn เพื่อไม่ให้สองงานเขียนไฟล์ทับกัน ผลคือทุกอย่างต่อคิวเดียวกัน คนที่พิมพ์ถามสั้นๆ ต้องรอ Idle Work ทำจบก่อน งานที่ใช้แค่ Connector รองานที่แก้โค้ด และรอบของ Schedule ถูกข้ามเพราะ Agent ไม่ว่าง ตัวอื่นที่ทำงานคล้ายกัน เช่น OpenClaw, Hermes และ Muse แยกคิวของคนออกจากงานพื้นหลัง และไม่ให้งานพื้นหลังขวางการตอบคน แต่ไม่มีตัวไหนกันไฟล์ชนกัน ซึ่ง Agent ของเราต้องกัน เพราะงานหลักคือแก้ไฟล์ใน Workdir หลักของ ADR 0011 ที่ยังถูกคือ "ที่เขียนหนึ่งที่มีคนเขียนคนเดียว" สิ่งที่เปลี่ยนคือจุดที่ต้องรอ จากตอนเริ่ม Turn เป็นตอนจะเขียน (เจ้าของตัดสิน 2026-11-27)

**Turn เริ่มได้ทันทีเสมอ** ไม่มีคิวต่อ Agent อีกต่อไป คุย อ่านไฟล์ ค้น เรียก Connector และรันคำสั่งที่ไม่อันตรายตาม ADR 0075 ทำพร้อมกันได้หลาย Turn ข้อยกเว้นเดียวคือ Turn ใน Task เดียวกันยังทำทีละ Turn เพราะบทสนทนาต่อจากลำดับใน log ของ Task (ADR 0018)

**ล็อกต่อที่เขียน ไม่ใช่ต่อ Agent** ที่เขียนแต่ละที่มีล็อกของตัวเอง ได้แก่ Workdir ของ Agent, checkout หลักและแต่ละ worktree ของ Project (ADR 0047), Library แต่ละอัน (ADR 0037) และ `MEMORY.md` ซึ่งมีล็อกเล็กของตัวเอง Turn ขอล็อกของที่ไหนก็ต่อเมื่อกำลังจะเขียนที่นั้น คือเรียก tool ที่เขียนไฟล์ หรือรันคำสั่งที่ไม่อยู่ในรายการของ ADR 0075 ซึ่งรวมถึงคำสั่งอย่าง `npm test` หรือ `cargo test` เพราะเขียนผล build ได้แล้วถือไว้จน Turn จบ ไม่คืนระหว่างการเขียนแต่ละครั้ง Turn อื่นจึงไม่เห็นงานสองชิ้นแทรกกันในไฟล์เดียว supervisor เป็นคนถือล็อกทุกตัว worker ขอก่อนเขียน เพราะ worktree ของ Project ใช้ร่วมกันหลาย Agent sandbox ยังเป็นขอบเขตว่าเขียนที่ไหนได้ (ADR 0068) ส่วนล็อกเป็นตัวบอกว่าเขียนได้เมื่อไหร่ จึงไม่ต้องเปลี่ยนสิทธิ์ sandbox กลาง Turn

**คนได้ล็อกก่อนงานพื้นหลัง** Turn ของคน ทั้งที่สั่งจาก Controller และจาก Channel (ADR 0028) ได้ล็อกก่อน Turn ของ Schedule, Idle Work และ Watch ในกลุ่มเดียวกันได้ตามลำดับที่ขอ งานพื้นหลังไม่ถูกขัดกลางคัน (ADR 0056) ทุก Turn ของงานพื้นหลัง รวมถึงรอบของ Schedule ซึ่งเดิมไม่มีเพดาน จบภายใน 15 นาทีเหมือนชิ้นของ Idle Work คนจึงรอล็อกจากงานพื้นหลังได้ไม่เกินนั้น Turn ที่ถือล็อกแล้วรอ Approval ยังถือล็อกไว้จนได้คำตอบหรือหมดอายุ เพราะไฟล์อาจแก้ค้างครึ่งทาง ช่วงที่ Turn รอล็อกไม่นับเป็น Turn ค้าง (ADR 0073) เหมือนช่วงรอ Approval

**Delegation ไม่ติดกันเอง** Agent ที่รับงานเขียนใน Workdir ของตัวเองซึ่งเป็นคนละล็อก ถ้าแม่กับลูกเขียน worktree เดียวกันของ Project แม่ให้ลูกยืมล็อกที่ถืออยู่ เพราะล็อกเป็นของสาย Task นั้นทั้งสาย

**worker หนึ่งตัวต่อชุดสิทธิ์** sandbox ครอบทั้งโปรเซส (ADR 0069) และสิทธิ์ของแต่ละ Turn สร้างจากงานที่ทำ (ADR 0068) Turn ที่ใช้สิทธิ์ชุดเดียวกัน เช่นงานส่วนตัวของ Agent ใน Workdir ของมัน รันพร้อมกันใน worker ตัวเดียว ส่วน Turn ที่ต้องใช้สิทธิ์ต่างออกไป เช่น Turn ของ Project หรือ Library ที่ Agent ได้สิทธิ์ต่างกัน ได้ worker ของตัวเอง Turn ใน worker เดียวกันใช้ localhost เดียวกัน proxy ต่อ Agent จึงต้องรู้ว่าคำขอแต่ละอันมาจาก Turn ไหน แทนการรู้แค่ "Turn ปัจจุบัน"

**งานพื้นหลังยังมีขอบ** Idle Work ตื่นเมื่อไม่มี Turn ของคนของ Agent นั้นกำลังทำ และ Turn ของคนล่าสุดจบมาแล้วครบเวลาที่ตั้ง Turn ของงานพื้นหลังด้วยกันไม่นับ รอบของ Schedule ไม่ถูกข้ามเพราะมี Turn อื่นทำอยู่ ถูกข้ามเฉพาะเมื่อรอบก่อนของ Schedule เดียวกันยังไม่จบ ทุก Turn ของงานพื้นหลัง ไม่ว่าจะถือล็อกหรือไม่ อยู่ใต้เพดาน 30% ของ Budget (ADR 0043, 0056)

**Stop และการเริ่มใหม่** Stop จบ Turn ที่เลือก รวมถึง Turn ที่กำลังรอล็อก (ADR 0017) Runtime ที่เริ่มใหม่จบ Turn ที่รอล็อกค้างไว้เหมือน Turn ที่ทำค้าง (ADR 0033)

**Protocol** Runtime เลิกตอบ `agent.busy` เมื่อมีข้อความเข้า Task ระหว่างที่ Agent ทำ Turn อื่น code นี้ยังอยู่ใน Protocol เพื่อ Controller รุ่นก่อน (ADR 0023) และยังใช้กับ `trigger.run` ของ Schedule ที่รอบก่อนยังไม่จบ

## Considered Options

- **คงไว้ทีละ Turn ต่อ Agent (ADR 0011)**: ง่ายสุด แต่คนต้องรองานพื้นหลัง และงานที่ไม่แตะไฟล์ก็ต้องรอ
- **แยกประเภทงานตั้งแต่สั่ง เช่นงาน Connector ทำพร้อมกัน งาน Workdir ต่อคิว**: รู้ล่วงหน้าไม่ได้ เพราะ Agent เลือก tool เองระหว่างทำ งานที่ดูเหมือนใช้แค่ Connector อาจเขียนผลลง Workdir
- **แยก worktree ให้ทุก Task**: ทำพร้อมกันได้เต็มที่ แต่ใช้ได้กับ git อย่างเดียว Task ที่ต่อกันไม่เห็นไฟล์ของกัน และทุก Task ต้องรวมงานกลับเอง ตามที่ ADR 0011 ปฏิเสธไว้
- **แยกคิวแต่ไม่กันไฟล์ชน แบบ OpenClaw หรือ Hermes**: ง่ายกว่า แต่สองงานที่แก้ไฟล์จะทับกัน
- **ขัดงานพื้นหลังเมื่อคนพิมพ์**: ไฟล์ค้างครึ่งทาง และงานเริ่มใหม่ซ้ำไม่จบ (ADR 0056)
- **ล็อกเฉพาะช่วงที่เขียนแต่ละครั้ง ไม่ถือจนจบ Turn**: คนรอน้อยกว่า แต่ Turn อื่นจะเห็นและแทรกงานที่แก้ค้างครึ่งทาง

## Consequences

- Turn ที่อ่านอย่างเดียวอาจเห็นไฟล์ที่อีก Turn แก้ค้างครึ่งทาง เหมือน Ask (ADR 0046) และเกิดบ่อยขึ้น
- คำสั่งที่รันโปรแกรมอื่น เช่น `npm test` ถือล็อก งานพัฒนาส่วนใหญ่ยังผลัดกันเขียน สิ่งที่ได้คือคุย อ่าน และ Connector ไม่ต้องรอ
- Turn ที่ถือล็อกแล้วรอ Approval อาจทำให้คนอื่นรอเขียนได้นานเท่าเวลาหมดอายุ (ค่าเริ่มต้น 1 ชั่วโมง) เหมือนเดิม
- Turn ใน worker เดียวกันใช้ localhost เดียวกัน dev server สองตัวอาจแย่งพอร์ตกัน
- Budget ถูกใช้เร็วขึ้นเมื่อหลาย Turn ทำพร้อมกัน แต่เพดานต่อวันยังเหมือนเดิม และ Provider อาจตอบ rate limit บ่อยขึ้น
- Agent มีหลาย Turn พร้อมกันได้ Character ในแถวของ Agent แสดงอารมณ์ของ Turn ของคนที่ใหม่สุด ส่วนงานพื้นหลังที่ทำอยู่แสดงเป็นจุดเล็ก
- worker ต้องรันหลาย Turn พร้อมกันได้ และ supervisor ต้องนับ Turn ทีละตัวแทน "Turn ปัจจุบันของ Agent" เช่นใน Approval, proxy และการเช็กว่าไม่ว่าง
- spec ที่ต้องแก้ตาม: task-queue, task-log, task-stop, controller-tasks, triggers, controller-schedules, controller-character, agent-memory-writes และ runtime-sandbox สามตัวแรกกับ controller-tasks ยังขัดกันเองอยู่แล้วเรื่องส่งข้อความระหว่าง Turn ต้องรวมเป็นชุดเดียว
- ถ้าวันหนึ่งงานพื้นหลังที่เขียนไฟล์ต้องไม่ทำให้คนรอเลย ทางต่อไปคือให้มันเขียนใน worktree ของตัวเอง ซึ่งเป็นเรื่องแยก
