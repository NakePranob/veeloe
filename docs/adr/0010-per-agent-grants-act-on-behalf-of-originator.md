# สิทธิ์แจกเป็นราย Agent และงานทำในนามของ Member ที่ส่งข้อความของ Turn นั้น

Workspace หนึ่งมี Member ได้หลายคน แต่ละคนมี Grant ต่อ Agent แต่ละตัวเป็น Use, Approve หรือ Manage โดย Owner ซึ่งมีได้หลายคน (ADR 0031) เป็นจุดเริ่มต้นของความไว้ใจ การแจกหรือเปลี่ยน Grant ต้องเซ็นโดย Owner หรือ Member ที่มี Manage ที่ Agent ตัวนั้น Hub ที่โดนเจาะจึงเลื่อนขั้นใครเองไม่ได้ (ADR 0006) Approval ส่งไปหา Member ที่มี Approve ที่ Agent ตัวนั้น ไม่ได้ส่งไปหาคนที่สั่งงาน ใครจะเอา Agent ตัวไหนเข้ามาเป็นพนักงานของ Project ต้องมี Manage ที่ Agent ตัวนั้น เพราะการรับงานจากใครเป็นเรื่องที่ฝั่งปลายทางตัดสินใจ การตั้ง Agent ตัวไหนเป็น Entry ก็ต้องมี Manage ที่ตัวนั้นด้วยเหตุผลเดียวกัน Project มีสิทธิ์ของตัวเองอีกชั้น (ADR 0046)

Turn ทุกตัวพกชื่อ Member ที่ส่งข้อความของ Turn นั้น ซึ่งเซ็นมาจาก Controller ของคนนั้น และ Task ย่อยในสาย Delegation พกชื่อนี้ต่อไป คนที่ส่งข้อความไม่จำเป็นต้องเป็นคนเริ่ม Task เพราะ Member หลายคนพิมพ์ใน Task เดียวกันได้ และทุกข้อความแสดงชื่อคนส่ง นอก Project ฝั่งปลายทางตรวจว่า Member คนนั้นมี Use ที่ Agent ปลายทาง ถ้าไม่มีก็ส่งไม่ได้ ข้อนี้ปิดช่อง confused deputy ที่คนมีสิทธิ์แค่ Agent ตัวเดียวใช้ Agent อื่นได้ ใน Project ใช้สิทธิ์ของ Project แทน เพราะคนดูแลพนักงานแต่ละตัวยินยอมไว้แล้วตอนเอาเข้ามา การตรวจทุกครั้งที่ส่งต่อยังอยู่ เผื่อสิทธิ์ถูกถอนระหว่างทาง

## Considered Options

- **Owner กับ Member สองบทบาท**: ง่ายกว่า แต่กำหนดไม่ได้ว่าให้เฉพาะ SRE เป็นคนอนุมัติ deployer
- **ถือว่าเส้นใน Flow คือการอนุญาตแล้ว** (ก่อนตัด Flow ใน ADR 0045): ใช้งานแบบกลุ่มได้ง่ายกว่า แต่ใครสั่ง Agent ต้นทางได้ ก็จะสั่งทุกอย่างที่อยู่ใน Allowlist ของ Agent ปลายทางได้ด้วย
- **ผูกชื่อคนสั่งไว้ต่อ Task แทนต่อ Turn**: ง่ายกว่าเพราะ Task มีเจ้าของคนเดียว แต่ถ้าอยากช่วยกันทำงานเรื่องเดียว ต้องเปิด Task ใหม่แล้วเล่าบริบทซ้ำ

## Consequences

- v0.1 มี Member คนเดียว (Owner) แต่ทุกคำสั่งและทุก Delegation ต้องระบุ Member ตั้งแต่แรก ไม่อย่างนั้นวันที่เพิ่มคนที่สองต้องแก้โปรโตคอลทั้งหมด
- ช่อง confused deputy เดียวกันเกิดได้ทางไฟล์และทางเน็ตด้วย จึงอ่าน Workdir ของพนักงานร่วม Project ได้เฉพาะใน Task ของ Project (ADR 0026) และ Egress แยกต่อ Agent (ADR 0029)
- Use ดูได้ทุก Task ของ Agent ตัวนั้น ไม่ว่าใครเป็นคนเริ่ม เพราะทุก Task ใช้ Workdir เดียวกัน (ADR 0031) ยกเว้น Task ของ Project ที่เห็นได้เฉพาะคนที่มีสิทธิ์ใน Project (ADR 0046)
- งานจาก Channel ทำในนามของ Member ที่ผูก Channel และตรวจ Use ของคนนั้น (ADR 0028)
- การเอา Agent เข้าหรือออกจาก Project ต้องมี Manage ที่ Agent ตัวนั้น เพราะการเป็นพนักงานคือการเปิด Workdir ให้พนักงานร่วม Project อ่าน (ADR 0026) และยินยอมให้รับงานจากคนที่มีสิทธิ์ใน Project
- Member ที่มี Use กด Stop ได้ทุก Turn ของ Agent ตัวนั้น (ADR 0017)
- push ตอน Turn เสร็จไปหาคนที่ส่งข้อความของ Turn นั้น ไม่ใช่คนที่เริ่ม Task (ADR 0044)
