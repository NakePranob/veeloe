# สิทธิ์แจกเป็นราย Agent และ Delegation ทำในนามของ Member ที่เริ่ม Task ต้นทาง

Workspace หนึ่งมี Member ได้หลายคน แต่ละคนมี Grant ต่อ Agent แต่ละตัวเป็น Use, Approve หรือ Manage โดย Owner เป็นจุดเริ่มต้นของความไว้ใจ การแจกหรือเปลี่ยน Grant ต้องเซ็นโดย Owner หรือ Member ที่มี Manage ที่ Agent ตัวนั้น Hub ที่โดนเจาะจึงเลื่อนขั้นใครเองไม่ได้ (ADR 0006) Approval ส่งไปหา Member ที่มี Approve ที่ Agent ตัวนั้น ไม่ได้ส่งไปหาคนที่สั่งงาน ใครจะลากเส้นเข้าหา Agent ตัวไหนต้องมี Manage ที่ Agent ตัวนั้น เพราะการรับงานจากใครเป็นเรื่องที่ฝั่งปลายทางตัดสินใจ การตั้ง Agent ตัวไหนเป็น Entry ของ Team ก็ต้องมี Manage ที่ตัวนั้นด้วยเหตุผลเดียวกัน

Task ทุกตัวในสาย Delegation พกชื่อ Member ที่เริ่ม Task ต้นทางไว้ ซึ่งเซ็นมาจาก Controller ของคนนั้น ทุกครั้งที่ส่งต่อ ฝั่งปลายทางจะตรวจว่า Member คนนั้นมี Use ที่ Agent ปลายทางด้วย ถ้าไม่มีก็ส่งไม่ได้ ข้อนี้ปิดช่อง confused deputy ที่คนมีสิทธิ์แค่ Agent ตัวเดียวใช้ Agent อื่นผ่านเส้นใน Flow ได้ Member จะเริ่ม Task กับ Team ได้ต้องมี Use ที่ Agent ทุกตัวในทีม ทีมจะได้ไม่ทำงานได้แค่ครึ่งเดียวกลางทาง และ Agent จะได้ไม่วางแผนโดยนับ Agent ที่ส่งงานให้ไม่ได้ การตรวจทุกครั้งที่ส่งต่อยังอยู่ เผื่อ Grant ถูกถอนระหว่างทาง

## Considered Options

- **Owner กับ Member สองบทบาท**: ง่ายกว่า แต่กำหนดไม่ได้ว่าให้เฉพาะ SRE เป็นคนอนุมัติ deployer
- **ถือว่าเส้นใน Flow คือการอนุญาตแล้ว**: ใช้งานแบบทีมได้ง่ายกว่า แต่ใครสั่ง Agent ต้นทางได้ ก็จะสั่งทุกอย่างที่อยู่ใน Allowlist ของ Agent ปลายทางได้ด้วย

## Consequences

- v0.1 มี Member คนเดียว (Owner) แต่ทุกคำสั่งและทุก Delegation ต้องระบุ Member ตั้งแต่แรก ไม่อย่างนั้นวันที่เพิ่มคนที่สองต้องแก้โปรโตคอลทั้งหมด
- Alice จะใช้งานผ่านเส้นจาก helper ไป deployer ได้ ก็ต่อเมื่อมี Use ที่ deployer เองด้วย
