# Member ผูกบัญชีของตัวเองได้ และบัญชีนั้นใช้ได้เฉพาะงานที่ตัวเองสั่ง

Connector หนึ่งตัวใช้บัญชีเดียวซึ่งคนที่มี Manage ผูก (ADR 0039) จึงควรเป็นบัญชี bot หรือ service account แต่บางงานต้องทำในนามคนคนหนึ่ง เช่น อ่านอีเมลของตัวเอง Member จึงผูกบัญชีของตัวเองเข้ากับ Connector ได้ บัญชีนั้นใช้ได้เฉพาะ Turn ที่คนนั้นเป็นคนส่งข้อความ ตรงกับ ADR 0010 ที่ให้งานทำในนามคนสั่ง และ Agent ถามเจ้าของบัญชีก่อนใช้ (Allow once หรือ Always allow) ซึ่งถอนได้ทุกเมื่อ Always allow ผูกกับ tool นั้นบน Agent ตัวนั้น

ไม่มีการยืมบัญชีคนอื่น (เจ้าของตัดสิน 2026-11-01) และห้ามใช้บัญชีส่วนตัวใน Channel เพราะคนในแชตไม่ใช่ Member และงานทำในนามคนผูก การตรวจ Use ของคนผูกจึงกันคนนอกไม่ได้ ถ้าใครเคยกด Always allow คนนอกก็จะสั่งงานบนบัญชีของเขาได้ ส่วนในแชตที่ทีมเห็น การยืมก็ทำให้เนื้อหาจากบัญชีไปค้างใน Task ที่คนอื่นเห็น และ Agent ไม่ว่างระหว่างรอเจ้าของบัญชีตอบ (ADR 0011)

การผูกยังเหมือน ADR 0039 คือแอป login ผ่านเบราว์เซอร์ของระบบด้วย PKCE เข้ารหัส token ด้วยกุญแจของ Machine และ supervisor เป็นคนเดียวที่ถือ token Agent เห็นแค่รายชื่อ tool

## Considered Options

- **ยืมบัญชีคนอื่นได้ในแชตที่ทีมเห็น เมื่อเจ้าของกดอนุญาต**: Kai สั่งงานบนบัญชีของ Nok ได้ แต่ Nok อาจไม่รู้ว่าผลจะไปค้างในแชต และทุกคนต้องรอ Nok ตอบ
- **ยืมได้ทุกที่รวมถึง Channel**: ยืดหยุ่นที่สุด แต่คนนอกสั่งงานบนบัญชีของ Member ได้
- **ไม่มีบัญชีส่วนตัวเลย**: ง่ายสุด แต่งานที่ต้องทำในนามตัวเองทำไม่ได้

## Consequences

- Kai สั่งงานบนบัญชีของ Nok โดยตรงไม่ได้ ต้องให้ Nok สั่งเองหรือเล่าผลให้
- ถ้า Nok เปิดแชตให้ทีมเห็น ผลที่อ่านจากบัญชีของ Nok ก็จะเห็นด้วย แอปต้องเตือนตอนเปิด
- token ส่วนตัวอยู่บนเครื่องของเจ้าของ Machine ซึ่งเข้าถึงได้ แอปต้องบอกตอนผูก
- สิทธิ์ที่จำไว้หยุดเมื่อถอนกุญแจหรือลบ Member (ADR 0031) แต่ token ที่ฝั่งผู้ให้บริการไม่ได้ถูกยกเลิกให้ (ADR 0039)
- แอปต้องมีหน้าให้เจ้าของบัญชีเห็นว่าบัญชีถูกใช้ทำอะไร
