# Skill เป็นค่าของ Agent ที่ Member ซึ่งมี Manage เซ็นติดตั้ง และ Agent อ่านได้แต่แก้ไม่ได้

Skill ตามมาตรฐาน Agent Skills ที่ Claude Code, Hermes และ OpenClaw ใช้ คือโฟลเดอร์ที่มี `SKILL.md` กับชื่อและคำอธิบาย และอาจมี script ประกอบ harness เป็นของเรา (ADR 0004) จึงทำเองได้ด้วยการใส่ชื่อกับคำอธิบายของทุก Skill ไว้ใน prompt แล้วให้ Agent อ่าน `SKILL.md` ด้วย tool read ที่มีอยู่แล้วเมื่องานตรงกับ Skill นั้น Skill คือคำสั่งที่ Agent เชื่อและทำตาม และมี script ที่สั่งรันได้ ถ้า Agent แก้ Skill ของตัวเองได้แบบ Hermes ใครที่หลอก Agent ได้ก็ฝังคำสั่งถาวรได้ ซึ่งร้ายกว่า Memory ที่โดนวางยา (ADR 0036) Skill จึงเป็นค่าของ Agent แบบเดียวกับคำสั่งของ Agent Runtime เก็บไว้ที่ `<VEELOE_HOME>/agents/<id>/skills/` นอก Workdir sandbox ให้ Agent อ่านได้อย่างเดียว และติดตั้ง แก้ หรือลบได้เฉพาะ Member ที่มี Manage ด้วยคำสั่งที่เซ็น (ADR 0006) Skill ตรึงไว้ตอนเริ่ม Task แบบเดียวกับ Memory และ script ใน Skill รันผ่าน bash จึงอยู่ใต้ Allowlist และ sandbox ตามปกติ (ADR 0030)

ติดตั้งได้สี่ทาง ทุกทาง Member อ่านไฟล์ทั้งหมดในแอปก่อนเซ็น และคำสั่งติดตั้งเซ็นทับ hash ของทุกไฟล์ที่เห็น ถ้าไฟล์เปลี่ยนหลังจากนั้น Runtime ไม่ติดตั้ง
1. **จากลิงก์** เช่น repo บน GitHub แอปเป็นคนดึงไฟล์มาเอง Runtime ไม่ต้องออกเน็ต แล้วแอปส่งไฟล์ผ่าน Hub ซึ่งส่งต่ออย่างเดียว (ADR 0005)
2. **จากไฟล์ในเครื่องของ Member** เช่น ลากโฟลเดอร์หรือ zip มาวางบนเว็บ
3. **จากร่างที่ Agent เขียนไว้ใน Workdir** แอปแจ้งว่า Agent เสนอ Skill ใหม่ แล้ว Runtime คัดลอกเองในเครื่อง hash ทำให้ Agent แอบแก้ร่างหลัง Member อ่านแล้วไม่ได้
4. **จาก Agent ตัวอื่น** ถ้าอยู่เครื่องเดียวกัน Runtime คัดลอกเอง ถ้าคนละเครื่อง แอปเป็นคนส่งต่อ

## Considered Options

- **Skill อยู่ใน Workdir และ Agent สร้างหรือแก้เองได้แบบ Hermes**: Agent เก่งขึ้นเองโดยไม่ต้องรอคน แต่ใครที่หลอก Agent ได้ก็ฝังคำสั่งถาวรได้ และ Member ไม่รู้ว่า Agent มี Skill อะไรอยู่ ทางเสนอร่างให้ Member ติดตั้งได้ประโยชน์ใกล้เคียงกันโดยมีคนตรวจ
- **ติดตั้งด้วยคำสั่งบน Machine เช่น `veeloe skill install`**: สะดวกกับคนที่อยู่หน้าเครื่อง แต่ไม่มีบันทึกว่า Member คนไหนอนุญาต ซึ่งขัดกับ ADR 0006
- **อัปเดตจากต้นทางเอง**: ได้เวอร์ชันใหม่ทันที แต่ถ้า repo ต้นทางโดนแก้ให้มีโค้ดอันตราย ก็จะไหลเข้ามาเอง

## Consequences

- Skill ไม่อัปเดตเอง ถ้าต้นทางมีเวอร์ชันใหม่ แอปแสดงว่าต่างจากเดิมตรงไหนแล้วให้ Member เซ็นใหม่
- Skill มีเพดานขนาดรวม เช่น ไม่กี่ MB เพื่อไม่ให้ Hub กลายเป็นทางส่งไฟล์ใหญ่
- คนที่อยู่หน้าเครื่องยังแก้ไฟล์ใน `~/.veeloe` ได้เอง ซึ่งอยู่นอกขอบเขตความปลอดภัยของเรา
- แชร์ Skill ข้าม Agent ด้วยการติดตั้งซ้ำ ไม่มีที่เก็บ Skill กลาง
