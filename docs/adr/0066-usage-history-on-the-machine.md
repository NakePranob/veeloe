# ประวัติการใช้ token เก็บที่ Machine และแอปขอเป็นช่วงวันที่

Budget นับ token ที่ proxy ของ supervisor (ADR 0042, 0043) แต่ Machine เก็บยอดแค่ของวันนี้ใน `usage.json` แล้วเขียนทับเมื่อวันเปลี่ยน Owner จึงตอบไม่ได้ว่าใช้เพิ่มขึ้นหรือลดลง และ token หมดไปกับงานไหน แม้ ADR 0043 จะบอกว่าแอปจะแสดงยอดต่อวันต่อ Agent และยอดต่อ Member ต่อเดือน

เราจึงให้ **Machine เก็บประวัติ** เพราะ supervisor เป็นที่เดียวที่เห็นทุกคำตอบของ LLM ถ้าให้ Controller นับเอง วันที่แอปปิดหรือเครื่องหลุดจะหายเป็นช่องโหว่ และสองเครื่องจะเห็นคนละตัวเลข ประวัติอยู่ใน SQLite ของ supervisor ตาม ADR 0014 ซึ่งเป็นที่เก็บของ Runtime อยู่แล้ว ไฟล์เดียวกับที่ใช้บังคับ Budget: หนึ่งแถวต่อ (Agent, วันของ Budget, แหล่งที่มา, Task) ยอดของวันนี้คือผลรวมของแถววันนั้น ไม่มี `usage.json` อีกต่อไป เพื่อไม่ให้มียอดสองที่ไม่ตรงกัน ไฟล์เดิมถูกนำเข้าครั้งเดียวแล้วเลิกใช้

วันใช้เขตเดียวกับ Budget คือเริ่ม 04:00 ตามเวลาของ Machine เก็บ 30 วันย้อนหลังรวมวันนี้ แล้วลบวันที่เก่ากว่าตอนเปิด supervisor และเมื่อวันเปลี่ยน แหล่งที่มาเริ่มที่ `task` เพราะ v0.1 มีแค่ Task ที่ใช้ token จริง รหัส Task มาจากหัว `x-veeloe-task` ที่ proxy อ่านอยู่แล้ว คำขอที่ไม่ระบุ Task เก็บด้วยรหัสว่าง และการนำเข้า `usage.json` เดิมก็ใช้รหัสว่างเพราะไม่รู้ว่าเป็น Task ไหน เก็บแต่จำนวน token กับรหัส ไม่เก็บเนื้อหา ชื่อไฟล์ หรือคำตอบของ Provider

Controller ขอประวัติด้วยข้อความที่เซ็นแล้ว `usage.list` ที่มี `request`, `days` และ `agent` ที่ไม่บังคับ แล้ว Machine คำนวณ `from` กับ `to` จากวันของ Budget ของตัวเอง (เครื่องที่อยู่คนละเขตเวลาจึงได้ช่วงที่ถูกของตัวเอง) และตอบ `usage.listed` ที่มี `request` เดิม, `from`, `to`, ผลรวมรายวันของแต่ละ Agent, Task ที่ใช้มากที่สุด 20 อัน และผลรวมตามแหล่งที่มา เฉพาะ Agent ที่ผู้ขอมี Manage (ADR 0059) ซึ่งใน v0.1 คือ Owner จำนวนวันต้องอยู่ระหว่าง 1 ถึง 90 คำตอบจึงมีขอบเขตคงที่และไม่โตตามจำนวนคำตอบ แอปแคชยอดรายวันไว้บนเครื่องเพื่อแสดงตอนออฟไลน์พร้อมเวลาที่ได้ล่าสุด และไม่ติดป้ายข้อมูลเก่าว่าเป็นของวันนี้

หน้าจอเป็นหน้า "การใช้ token" ที่เลือก 1, 3, 7 หรือ 30 วัน มีกราฟแท่งต่อวัน จัดกลุ่มตาม Machine แล้วตาม Agent และรายการงานที่ใช้ token มากที่สุด ไม่มีตัวเลขเงิน เพราะ ADR 0043 ตัดสินให้นับ token และไม่มีตารางราคาที่เชื่อได้ ไม่มีเปอร์เซ็นต์ของ Budget ในมุมมองหลายวัน เพราะ Budget เป็นค่าของวันนี้ ไม่ใช่ค่าเฉลี่ยของช่วง และหน้านี้ดูอย่างเดียว การตั้ง Budget ยังอยู่ที่หน้าของ Agent

## Considered Options

- **ให้ Controller นับและเก็บประวัติเอง**: ไม่ต้องแก้ Runtime แต่แอปที่ปิดอยู่จะไม่เห็นยอดของวันนั้น และสองเครื่องจะเห็นไม่ตรงกัน
- **ส่งประวัติ 30 วันไปกับ `agent.listed` ทุกครั้งที่ต่อ**: ไม่ต้องมีข้อความใหม่ แต่ทุกการต่อต้องแบกข้อมูลโตขึ้นเรื่อย ๆ และ Machine ต้องตอบทุกครั้งแม้แอปไม่ได้เปิดหน้านี้
- **ให้ Machine คำนวณรายงานสำเร็จรูป (เช่น กราฟรายสัปดาห์) แล้วส่งมา**: แอปวาดง่าย แต่เปลี่ยนหน้าจอทีต้องแก้ Runtime และเพิ่มรูปแบบคำตอบใหม่ทุกครั้งที่อยากได้มุมมองใหม่
- **เก็บเป็น JSONL ต่อวันแทน SQLite**: ไฟล์อ่านง่ายและ append เร็ว แต่ต้องอ่านทุกไฟล์เพื่อตอบช่วงวันที่ และต้องจัดการไฟล์ที่เสียกลางทางเอง
- **เก็บ 90 วันหรือตลอดไป**: กราฟยาวขึ้น แต่ข้อมูลโตและไม่มีความหมายกับ Budget ที่เป็นรายวัน — 30 วันพอต่อการดูแนวโน้ม และเพิ่มได้แบบ additive
- **นับเป็นเงินในกราฟ**: เข้าใจง่ายกว่า แต่ต้องมีตารางราคาของทุก model ทุก gateway ซึ่ง ADR 0043 ตัดทางนี้ไว้แล้ว

## Consequences

- ทุกคำตอบที่ถูกนับมีการเขียน SQLite หนึ่งครั้ง เป็นแถวเล็กและอยู่ในฐานข้อมูลเดียวกับยอดที่ใช้บังคับ Budget
- วันที่มีคำตอบแต่ gateway ไม่รายงาน `usage` จะไม่มีแถว ไม่ใช่ศูนย์ แอปต้องแสดงเป็นช่องว่าง ไม่ใช่หลอกว่าใช้ 0
- Budget เป็นค่าของวันนี้ การเทียบยอดหลายวันกับ Budget จึงไม่มีความหมาย หน้ารวมจึงแสดง token ไม่แสดงเปอร์เซ็นต์
- แหล่งที่มาอื่นจะยังว่างจนกว่า Schedule, Idle Work, Watch และ Channel จะมีจริง (ADR 0048) ยอดต่อ Member ต่อเดือนรอการระบุ Member เจ้าของ Turn
- แคชของ Controller เป็นของแต่ละเครื่อง ใครเปิดแอปบนเครื่องไหนก็เห็นประวัติเท่าที่เครื่องนั้นเคยดึงมา
- รหัส Task ในประวัติเป็น UUID ที่ไม่บอกเนื้อหา แต่ถ้า Task นั้นไม่ได้อยู่ในเครื่องของ Controller จะแสดงได้แค่รหัสสั้น ๆ
- การลบข้อมูลเก่ากว่า 30 วันทำให้ยอดเก่าหาไม่ได้อีก แม้จะเพิ่มช่วงวันที่ในคำขอภายหลังก็ตาม
