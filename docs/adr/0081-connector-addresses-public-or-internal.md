# ที่อยู่ของ Connector เป็นสาธารณะหรือภายใน และ Owner เท่านั้นที่ติดตั้ง Connector ภายในได้

> แก้ ADR 0039 บางส่วน ตามที่เขียนไว้ในหัวของ ADR นั้น

ADR 0039 ให้ supervisor เป็นคนต่อ MCP แบบ URL และถือ credential ไว้เอง supervisor ไม่ได้อยู่ใน sandbox จึงต่อได้ทุกที่ที่ Machine ต่อถึง รวมถึงเราเตอร์ NAS และเครื่องอื่นในบ้านหรือออฟฟิศของ Owner URL ของ Connector ไม่ได้มาจาก Agent มาจากคนที่มี Manage ซึ่งเซ็นตอนติดตั้ง ความเสี่ยงจึงไม่ใช่ Agent พา supervisor ไปที่ไหนก็ได้ แต่มีสามทาง คือ Member ที่มี Manage แต่ไม่ใช่ Owner ใช้ supervisor ส่องเข้าเครือข่ายของ Owner, Blueprint จากคนอื่นแอบใส่ URL ภายในมา และ server ภายนอกที่ redirect หรือเปลี่ยน DNS ให้ชี้เข้าข้างในหลังติดตั้งแล้ว ทางที่ง่ายที่สุดคือห้ามที่อยู่ภายในทั้งหมด ซึ่งเหมาะกับ server กลางของบริษัท แต่ขัดกับ ADR 0039 ที่ให้ใช้บริการในเครือข่ายภายในได้ และขัดกับคนที่รัน MCP ของตัวเองไว้บนเครื่องหรือใน Tailscale ส่วน OpenBot (nightly-labs/openbot) ไม่กันที่อยู่ภายในของ MCP เลย กันแค่ OAuth endpoint ที่ชี้เข้าข้างในเมื่อตัว MCP อยู่ข้างนอก (เจ้าของตัดสิน 2026-11-27)

**ที่อยู่มีสองชนิด** ที่อยู่สาธารณะและที่อยู่ภายในใช้นิยามเดียวกับ Egress (ADR 0029) คือฟังก์ชันเดียวกับที่ proxy ใช้ ที่อยู่ภายในคือ loopback, เครือข่ายส่วนตัว, carrier-grade NAT ซึ่งรวม Tailscale และ unique local ของ IPv6 Connector แต่ละตัวเป็นชนิดเดียว ซึ่งตั้งตอนติดตั้งและอยู่ในสิ่งที่เซ็น

**Connector สาธารณะ** ใช้ได้แค่ https กับชื่อโดเมน ห้ามใช้ IP ตรงๆ ทุกครั้งที่ต่อ supervisor resolve ชื่อเอง ตรวจว่าทุกที่อยู่ที่ได้เป็นที่อยู่สาธารณะ แล้วต่อไปที่ที่อยู่ที่ตรวจแล้วนั้น ไม่ resolve ซ้ำ DNS ที่เปลี่ยนให้ชี้เข้าข้างในหลังติดตั้งจึงไม่ได้ผล

**Connector ภายใน** ต้องติ๊ก "บริการภายใน" ตอนติดตั้ง และต้องเป็น Owner ที่เซ็น เพราะเป็นเครือข่ายของเขา ใช้ http ได้ ใช้ IP ตรงๆ ได้ และที่อยู่ที่ resolve ได้ต้องเป็นที่อยู่ภายในทั้งหมด แอปเตือนตอนติดตั้งว่า Agent ตัวนี้จะเรียกบริการในเครือข่ายนี้ได้ผ่าน tool ที่อนุมัติ ถ้าคนที่เซ็นถูกปลดจาก Owner Connector ภายในของเขาหยุดจนกว่า Owner คนอื่นจะเซ็นใหม่ เหมือนตอนกุญแจถูกถอน Blueprint ใส่ Connector ภายในมาไม่ได้ คนติดตั้งต้องใส่เอง

**ห้ามเสมอทั้งสองชนิด** link-local ซึ่งรวมที่อยู่ metadata ของ cloud (`169.254.0.0/16`, `fe80::/10`), ที่อยู่ว่าง, multicast และ broadcast รวมถึงพอร์ตที่ Runtime ฟังอยู่เอง เช่น proxy ของ Egress supervisor ไม่ตาม redirect ถ้า server ตอบ redirect tool นั้นล้มพร้อมบอกว่าที่อยู่ไหนที่ถูกส่งมา

**กฎเดียวกันทุก URL ที่ supervisor เปิด** ทั้ง endpoint ของ MCP และ endpoint ที่ supervisor ใช้ refresh token (ADR 0039) ส่วนการค้นหา metadata ของ OAuth และการ login ครั้งแรกเกิดบนมือถือ ไม่ได้ผ่าน supervisor

**การ์ดติดตั้งบอกสิ่งที่เซ็นให้ครบ** ได้แก่ host ปลายทางและชนิดของมัน, scope ของ OAuth ที่ผู้ให้บริการออกให้จริง ซึ่งอาจกว้างกว่าที่ขอ และป้ายของแต่ละ tool ซึ่งเขียนว่า "server บอกว่าแค่อ่าน" ไม่ใช่ "แค่อ่าน" ป้ายจาก server ใช้ได้แค่ทำให้เข้มขึ้น: tool ที่มี `destructiveHint` ขอ Approval ทุกครั้งแม้จะอยู่ใน Allowlist แล้ว ส่วน `readOnlyHint` ยังติ๊กไว้ให้ตอนติดตั้งตาม ADR 0039 เพราะ Member เห็นและเอาออกได้ก่อนเซ็น

## Considered Options

- **ห้ามที่อยู่ภายในทั้งหมด**: ง่ายและกันได้ครบ แต่ใช้ MCP ของตัวเองบนเครื่อง ใน NAS หรือใน Tailscale ไม่ได้ ซึ่งขัดกับ ADR 0039
- **ไม่จำกัด เพราะคนที่มี Manage เซ็นแล้ว**: ยืดหยุ่นที่สุด แต่ Member ที่มี Manage ที่ Agent ตัวเดียวจะใช้ supervisor เดินเข้าเครือข่ายของ Owner ได้ และ DNS กับ redirect พาเข้าข้างในได้โดยไม่มีใครเซ็น
- **ให้ Owner ตั้งรายชื่อ host ภายในที่อนุญาตไว้ที่ Machine**: คุมละเอียดกว่า แต่เป็นรายการกลางอีกชุดที่ต้องดูแล ทั้งที่ Owner ต้องเซ็น Connector ภายในทีละตัวอยู่แล้ว
- **ให้ Connector ภายในรันใน sandbox ของ Agent แทน**: ใช้กฎของ Egress ได้เลย แต่ credential จะอยู่ในมือ Agent ซึ่ง ADR 0039 ปฏิเสธไว้

## Consequences

- Member ที่ไม่ใช่ Owner ติดตั้ง Connector ภายในเองไม่ได้ ต้องขอ Owner ทั้งที่มี Manage ที่ Agent นั้น
- ชื่อที่ resolve ได้ทั้งที่อยู่สาธารณะและภายใน เช่น split DNS ในออฟฟิศ ไม่ผ่านทั้งสองชนิด ข้อความ error ต้องบอกว่าที่อยู่ไหนเป็นชนิดไหน และให้ติดตั้งเป็นชนิดที่ตรง
- Connector สาธารณะที่ใช้ IP ตรงๆ หรือ http ใช้ไม่ได้ บริการแบบนี้ต้องมีชื่อโดเมนพร้อม certificate
- ป้าย `destructiveHint` ที่ server ติดผิดทำให้ถาม Approval บ่อยเกินไป แต่ไม่ทำให้หลวม
- binary test ต้องมี MCP server ตัวแทนบน loopback ที่พิสูจน์ว่า Connector สาธารณะต่อไม่ได้, redirect ไม่ถูกตาม และ Connector ภายในที่ไม่ใช่ Owner เซ็นถูกปฏิเสธ
