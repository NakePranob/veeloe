# Agent แต่ละตัวมี Budget เป็นจำนวน token ต่อวัน ซึ่ง Runtime บังคับ

ลูกค้าจ่ายค่า token เอง (ADR 0001) และเงินหมดไปได้โดยไม่มีคนกด เช่น Schedule ที่รันทั้งคืน คนในแชตของ Channel ที่ส่งรัวๆ Agent ที่วนเรียก tool ไม่จบ หรือ Project ที่ส่งงานแตกหลายกิ่ง Agent แต่ละตัวจึงมี Budget เป็นจำนวน token ต่อวัน คนที่มี Manage เป็นคนตั้ง และมีค่าเริ่มต้น 10M token ตั้งแต่สร้าง Agent supervisor บังคับที่ proxy ของ LLM (ADR 0042) เพราะเห็น token ของทุกคำขอ นับเป็น token ไม่นับเป็นเงิน เพราะราคาต่างกันตาม model และ gateway ถ้านับเป็นเงินเราต้องดูแลตารางราคาเอง และถ้าตารางผิดเพดานก็ผิด แอปแสดงราคาโดยประมาณให้ดูได้ แต่ตัวบังคับคือ token นับทุก token ที่ Provider รายงาน ทั้ง input ที่รวมส่วนที่อ่านจาก cache และ output วันใหม่เริ่มตอน 04:00 ตามเวลาของ Machine เวลาเดียวกับที่ Task ของ Channel ขึ้นใหม่ (ADR 0028) เพราะ supervisor บนเครื่องเป็นคนนับ และ Workspace ไม่มีเขตเวลาของตัวเอง supervisor เก็บยอดตามวันที่ ไม่ได้ตั้งนาฬิกาไปรีเซ็ต เครื่องที่ปิดข้ามวันจึงเริ่มนับวันใหม่ตอนเปิด

เมื่อ Budget หมด Turn ที่ทำอยู่จบเหมือนโดน Stop หลังจากคำขอที่ส่งไปแล้วตอบกลับ ไฟล์ที่แก้ไว้อยู่ครบ งานใหม่ไม่เริ่มจนกว่าจะขึ้นวันใหม่หรือมีคนเพิ่ม Budget Schedule ข้ามรอบ และ bot ใน Channel ตอบว่างบของวันนี้หมดแล้ว push ไปหาคนที่มี Manage ตอนใช้ถึง 80% และตอนหมด แอปแสดงการใช้ต่อวันต่อ Agent แยกตามที่มา คือ Task, Schedule หรือ Channel และแนะนำให้ตั้ง spend limit ที่ Provider ไว้ด้วย เป็นเพดานเงินจริงชั้นสุดท้ายเผื่อ Runtime มีบั๊ก

## Considered Options

- **ไม่ทำ Budget เอง ให้ไปตั้งเพดานที่ Provider อย่างเดียว**: ไม่มีโค้ดเพิ่ม แต่เพดานของ Provider คุมทั้ง key ถ้าตัวเดียวใช้หมด ทุกตัวที่ใช้ key เดียวกันหยุดตาม และรู้ตัวก็ตอนงานพังไปแล้ว
- **นับเป็นเงิน**: เข้าใจง่ายกว่า แต่ต้องดูแลราคาของทุก model ในทุก gateway
- **ลดน้ำหนักของ token ที่อ่านจาก cache**: ใกล้กับเงินที่จ่ายจริงกว่า แต่ก็คือตารางราคาแบบย่อ ซึ่งต่างกันตาม Provider
- **ไม่มีค่าเริ่มต้น ให้คนสร้าง Agent เลือกเอง**: ได้ค่าที่เหมาะกับ model ที่เลือก แต่เพิ่มขั้นตอนตอนสร้าง ทั้งที่คนส่วนใหญ่ยังไม่รู้ว่าควรตั้งเท่าไหร่

## Consequences

- 10M token เป็นตัวเลขที่ประเมินไว้คร่าวๆ เพื่อกันงานวนไม่จบหรือคนส่งรัวทั้งคืน ไม่ใช่งบที่วางแผนใช้ Agent ที่อ่านโค้ดหนักอาจต้องตั้งสูงกว่านี้ ควรปรับเมื่อมีตัวเลขจากการใช้จริง
- โน้ตบุ๊กที่ย้ายเขตเวลาอาจได้วันที่สั้นหรือยาวกว่าปกติหนึ่งวัน
- Agent ที่รันหลาย Turn พร้อมกัน (ADR 0047) ใช้ Budget ก้อนเดียวกัน
