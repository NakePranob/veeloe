# รับแชตจากในแชตด้วย /claim และยืนยันด้วยรหัสที่ bot แสดงในแชต

Agent ที่ถูกเชิญเข้ากลุ่มยังไม่มีคนรับผิดชอบ และคนในแชตไม่รู้ว่าต้องทำอะไร bot ที่ถูกเพิ่มเข้ากลุ่มแล้วยังไม่มีคนผูกจึงเงียบทุกอย่างยกเว้นบรรทัดเดียวว่า "มีคนอยากให้รับแชตนี้ พิมพ์ /claim" ใครในแชตก็พิมพ์ได้ เพราะระบบไม่รู้ว่าบัญชี Telegram ไหนเป็น Member คนไหน (ADR 0028) จึงตรวจ Use ไม่ได้ และแอปต้องไม่อ้างว่าตรวจแล้ว

หลัง `/claim` bot แสดงรหัสสั้นในแชต และแอปแจ้งคนที่มี Manage ที่ Agent ตัวนั้น คนที่รับต้องกรอกรหัสที่เห็นในแชตก่อนเซ็น (ADR 0006) คนที่ไม่ได้อยู่ในแชตจึงยืนยันไม่ได้ ชื่อกลุ่มตั้งหลอกได้ แอปจึงไม่ใช้ชื่อกลุ่มเป็นหลักฐาน และต้องบอกว่า "กรอกเฉพาะรหัสที่คุณเห็นเอง" เมื่อยืนยันแล้ว งานเดินในนามคนเซ็น เหมือนการผูก Channel ในแอปตาม ADR 0028 ทุกอย่าง ค่า token เข้า key ของ Provider ที่ตั้งบน Machine (ADR 0042) และนับเป็นการใช้ของคนเซ็น (ADR 0043)

แต่ละแชตมีคำขอค้างได้หนึ่งคำขอ ส่ง push ได้ครั้งเดียวจนกว่าจะหมดอายุ ค่าเริ่มต้น 24 ชั่วโมง หมดเวลาแล้ว bot ออกจากกลุ่มเอง ถ้า Machine ปิดอยู่ก็ออกตอนเครื่องกลับมา แชตหนึ่งมีคนรับได้คนเดียว และ `/claim` ซ้ำไม่มีผล ในกลุ่มที่มีหลาย bot ต้องพิมพ์ `/claim@ชื่อbot` เพราะ Telegram ส่งคำสั่งที่ไม่ระบุชื่อไปหาเฉพาะ bot ที่ส่งข้อความล่าสุด

## Considered Options

- **ผูกจากในแอปอย่างเดียว**: ปลอดภัยและไม่ต้องสร้างเพิ่ม แต่คนในแชตไม่รู้ว่าต้องทำอะไร
- **Member ที่มี Use เท่านั้นที่เริ่มได้**: ฟังดูปลอดภัยกว่า แต่ต้องผูกบัญชี Telegram กับ Member ซึ่ง ADR 0028 ปฏิเสธไว้ เพราะใครยึดบัญชีได้ก็สวมสิทธิ์ได้
- **พิมพ์ /claim แล้วได้เลย**: ง่ายสุด แต่ไม่มีลายเซ็น และไม่รู้ว่ารับในนามใคร
- **ผูกอัตโนมัติกับคนที่เชิญ bot**: ไม่ต้องพิมพ์อะไร แต่คนเชิญอาจไม่มี Manage และไม่รู้ตัวว่ารับผิดชอบค่า token
- **คนรับหลายคน**: แบ่งค่า token กันได้ แต่ Task ของวันไม่รู้ว่าเป็นงานของใคร และ Inbox กระจาย

## Consequences

- ถ้ารหัสถูกส่งต่อมาจากคนร้ายก็ยังหลอกได้ วิธีนี้ทำให้ยากขึ้น แต่ไม่ได้กันได้ทั้งหมด
- คำขอที่เข้ามาช่วงวันหยุดอาจหมดอายุก่อนมีคนเห็น และต้องเชิญ bot เข้ากลุ่มใหม่
- Channel ที่รับด้วยวิธีนี้เหมือน Channel ที่ผูกในแอปทุกอย่าง รวมถึงหยุดเมื่อกุญแจที่เซ็นถูกถอน (ADR 0031)
