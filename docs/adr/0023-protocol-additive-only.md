# Protocol เปลี่ยนได้แบบเพิ่มอย่างเดียว และฝั่งรับต้องข้ามสิ่งที่ไม่รู้จัก

Controller, Runtime และ Hub อัปเดตไม่พร้อมกัน แอปบนมือถืออาจเก่ากว่า Runtime เป็นเดือนเพราะ App Store ตรวจช้าหรือลูกค้าไม่ได้กดอัปเดต และ Hub ก็ต้องรองรับ Runtime หลายเวอร์ชันพร้อมกัน (ADR 0009) Protocol จึงเพิ่ม field หรือชนิดข้อความใหม่ได้ แต่ห้ามลบหรือเปลี่ยนความหมายของสิ่งที่มีอยู่แล้ว ฝั่งรับที่เจอ field หรือชนิดข้อความที่ไม่รู้จักต้องข้ามไป ห้ามพัง ส่วน Controller ให้แสดงว่า "อัปเดตแอปเพื่อดูส่วนนี้" schema ของ Zod จึงต้องไม่ใช่แบบ strict ถ้าจำเป็นต้องเปลี่ยนแบบที่ทำให้เวอร์ชันเก่าพัง ให้ขึ้นเวอร์ชันใหญ่ แล้วใช้เวอร์ชันต่ำสุดที่ Hub กำหนดบังคับให้ทุกคนอัปเดต

## Considered Options

- **ตกลงเวอร์ชันกันทุกครั้งที่ต่อ**: เปลี่ยนได้อิสระกว่า แต่ทุกฝั่งต้องเก็บโค้ดของหลายเวอร์ชันไว้พร้อมกัน และ Hub ช่วยแปลงข้อความระหว่างเวอร์ชันไม่ได้ เพราะอ่านเนื้อในไม่ได้
- **บังคับให้อัปเดตพร้อมกันทุกฝั่ง**: ทำไม่ได้จริง เพราะคุมเวลาตรวจของ App Store และเวลาที่ลูกค้ากดอัปเดตไม่ได้

## Consequences

- field ที่เลิกใช้แล้วต้องเก็บไว้ใน schema ต่อไปจนกว่าจะขึ้นเวอร์ชันใหญ่
- ลายเซ็นยังตรวจได้แม้ข้อความจะมี field ที่ฝั่งรับไม่รู้จัก เพราะลายเซ็นครอบ byte ไม่ได้ครอบ object (ADR 0019)
