# Member อยู่ในกลุ่มที่แจก Grant ได้หลายใบในทีเดียว และมีป้ายตำแหน่งไว้แสดงผล

Status: proposed

> แก้ ADR 0010 และ 0059 บางส่วน ตามที่เขียนไว้ในหัวของแต่ละตัว

Grant ตาม ADR 0010 เป็นของ Member หนึ่งคนกับ Agent หนึ่งตัว องค์กรที่มี 20 คนกับ 8 Agent ต้องแจก Grant ได้ถึง 160 ใบทีละใบ และคนที่เข้ามาใหม่ต้องได้ทีละใบอีก หน้ารายชื่อก็เห็นแค่ชื่อ ไม่รู้ว่าใครทำหน้าที่อะไร OpenBot (nightly-labs/openbot) ใช้ role ต่อ server ที่บอกว่าสมาชิกใช้ Agent ไหนได้ และเชื่อทะเบียนบน Cloudflare ว่าใครมี role อะไร เราไม่ใช้ role เพราะสิทธิ์ต้องตรวจได้ที่ Machine จากลายเซ็น จึงทำกลุ่มเป็นทางลัดที่ข้างในยังเป็น Grant ที่เซ็น (เจ้าของตัดสิน 2026-11-28)

**กลุ่ม** Owner สร้างกลุ่มใน Workspace ได้ เช่น "ฝ่ายขาย" กลุ่มมีรายชื่อ Member และชุด Grant ราย Agent ทั้งรายชื่อและชุด Grant เป็นเอกสารที่เซ็นแล้ว Runtime ของแต่ละ Machine ถือสำเนาที่เซ็นแล้วของกลุ่มที่มี Grant ต่อ Agent บนเครื่องนั้น และตรวจคำสั่งจากสำเนานี้ ไม่ถาม Hub Member ได้สิทธิ์จากทุกกลุ่มที่อยู่รวมกับ Grant ของตัวเอง โดยเอาระดับที่สูงสุดของแต่ละ Agent

**ผู้ดูแลกลุ่ม** Owner ตั้ง Member คนหนึ่งหรือหลายคนเป็นผู้ดูแลกลุ่มได้ ผู้ดูแลเพิ่มหรือเอา Member ออกจากกลุ่มของตัวเองได้ และเชิญคนใหม่เข้ากลุ่มได้ (Invitation ตาม ADR 0059 ที่แนบกลุ่มแทน Grant) แต่แก้ชุด Grant ของกลุ่มไม่ได้ การแก้ชุด Grant ต้องมี Manage ที่ Agent นั้นทุกตัว เหมือนการแจก Grant เดี่ยว

**ป้ายตำแหน่ง** Member มีป้ายข้อความสั้นได้หนึ่งอัน เช่น "ฝ่ายขาย" หรือ "หัวหน้าทีม dev" แสดงหลังชื่อในทุกที่ Owner หรือ Member เองตั้งด้วยคำสั่งที่เซ็น Hub เก็บเป็น metadata เหมือนชื่อ (ADR 0053) ป้ายไม่ให้สิทธิ์อะไร

**ถอนสิทธิ์** เอา Member ออกจากกลุ่ม หรือแก้ชุด Grant ของกลุ่ม มีผลกับ Turn ถัดไปของทุกคนในกลุ่ม Turn ที่กำลังทำอยู่ทำจนจบ เหมือนการถอน Grant เดี่ยว ของที่ตั้งไว้ด้วยสิทธิ์จากกลุ่มแล้ว เช่น Schedule หยุดเมื่อคนตั้งไม่มี Use แล้ว (ADR 0010)

## Considered Options

- **role ต่อ Workspace แบบ OpenBot**: เข้าใจง่าย แต่ role ต้องมีคนตัดสินว่าใครมี และถ้าเชื่อทะเบียนกลาง ทะเบียนที่ถูกเจาะจะยกสิทธิ์ได้
- **คัดลอก Grant ของคนต้นแบบให้คนใหม่**: ไม่มีแนวคิดใหม่ แต่เปลี่ยนสิทธิ์ทีหลังต้องไล่แก้ทีละคน
- **ใช้ Project เป็นกลุ่มของคน**: Project เป็นที่ทำงานของ Agent (ADR 0045) ไม่ใช่กลุ่มของคน รวมกันจะทำให้สองเรื่องปนกัน

## Consequences

- เพิ่มคำว่า Group ใน CONTEXT.md และป้ายตำแหน่งในคำอธิบาย Member
- หน้า Members แสดงชื่อ ป้าย กลุ่ม และ Agent ที่ใช้ได้ พร้อมบอกว่าแต่ละสิทธิ์มาจาก Grant เดี่ยวหรือจากกลุ่มไหน
- Runtime ต้องเก็บเอกสารกลุ่มที่เซ็นแล้ว และรับเวอร์ชันใหม่ที่เลข version สูงกว่าเท่านั้น เพื่อกันการย้อนไปใช้สำเนาเก่า
