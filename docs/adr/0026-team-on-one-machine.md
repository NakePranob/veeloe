# Project อยู่บน Machine เดียว และพนักงานอ่าน Workdir ของกันได้ระหว่างทำ Task ของ Project

> ADR นี้เขียนตอนที่ยังเรียกว่า Team ADR 0045 เปลี่ยนชื่อเป็น Project และตัด Flow ออก เนื้อหาด้านล่างใช้คำใหม่แล้ว

พนักงานทุกตัวใน Project ต้องอยู่บน Machine เดียวกับ Entry Delegation จึงเกิดอยู่ภายใน Runtime ตัวเดียว ไม่ผ่าน Hub ค่าของ Project เก็บตัวจริงที่ Runtime และแก้ได้ด้วยคำสั่งที่ Controller เซ็นเท่านั้น (ADR 0006) Runtime เป็นคนตรวจเพดานและสิทธิ์เอง ส่วน Hub ไม่รู้จัก Project และส่งต่อข้อความระหว่าง Controller กับ Runtime อย่างเดียว เหตุผลหลักคือไฟล์ งานของ Project ส่วนใหญ่ส่งต่อกันเป็นไฟล์ เช่นโค้ด ร่างบทความ หรือไฟล์ข้อมูล แต่ Delegation ส่งได้แค่ข้อความ ถ้า Project ข้ามเครื่อง ไฟล์ต้องไปทาง git หรือที่เก็บกลางที่ทุกเครื่องเข้าถึงได้ หรือต้องวิ่งผ่าน Hub ซึ่งขัดกับ ADR 0005

เมื่อ Project อยู่เครื่องเดียวกัน พนักงานใน Project เดียวกันอ่าน Workdir ของกันได้ แต่เขียนได้แค่ของตัวเอง และอ่านได้เฉพาะตอนที่ Turn นั้นอยู่ใน Task ของ Project นั้น supervisor เปิด worker ใหม่ด้วยสิทธิ์อ่านชุดใหม่เมื่อ Turn ถัดไปต้องใช้สิทธิ์ต่างจากเดิม ซึ่งการครอบ sandbox เพิ่มเวลาแค่ราว 16 ms (ADR 0008) คนที่สั่งงานใน Project มีสิทธิ์ใน Project อยู่แล้ว และคนดูแลพนักงานแต่ละตัวยินยอมไว้ตอนเอาเข้ามา (ADR 0046) การอ่านจึงตรงกับสิทธิ์ ถ้าอ่านได้ตลอด Member ที่มี Use แค่ตัวเดียวจะคุยกับ Agent ตัวนั้นตรงๆ แล้วให้อ่าน `.env` ของพนักงานร่วม Project ได้ และ Agent ที่อยู่สอง Project จะกลายเป็นสะพานส่งไฟล์ข้าม Project Workdir หนึ่งจึงยังมีคนเขียนคนเดียวตาม ADR 0011 reviewer เปิดดูไฟล์ที่ frontend แก้ได้ตรงๆ และแก้แทนไม่ได้ ต้องให้ Entry ตีงานกลับให้ frontend แก้เอง ความรับผิดชอบจึงชัดว่าไฟล์ไหนเป็นงานของใคร นอกจากนี้ Delegation, Stop ที่ไหลลงทั้งสาย และการนับเพดาน กลายเป็นเรื่องภายในเครื่องเดียว ต้นไม้ของ Task ทั้ง Project อยู่บนเครื่องเดียว และภัยที่ Agent ที่โดนหลอกสั่ง Agent บนเครื่องที่มีสิทธิ์สูงกว่า เช่น deployer บน production ก็หายไป เพราะทั้ง Project อยู่ในขอบเขตความไว้ใจเดียวกัน

Project ข้ามเครื่องยังเป็นเป้าหมาย และเพิ่มทีหลังได้แบบ additive (ADR 0023) เมื่อตอบได้ว่าไฟล์จะข้ามเครื่องยังไง ตอนนั้น Hub ต้องกลับมาตรวจว่า Agent ต้นทางอยู่บน Machine ที่ส่งมาจริง และ Runtime ต้องเซ็น Delegation ที่ส่งออก

## Considered Options

- **Project ข้ามเครื่องผ่าน Hub**: เป็นจุดที่ทำให้ Veeloe ต่างจาก multi-agent บนเครื่องเดียว และส่งงานจาก dev ไปถึง deployer บน production ได้ แต่ไฟล์ข้ามเครื่องไม่ได้ ต้องพึ่ง git หรือที่เก็บกลาง และต้องใส่ปลายทางนั้นไว้ใน Egress ของทุกเครื่อง
- **แนบไฟล์ไปกับ Delegation ผ่าน Hub**: ขัดกับ ADR 0005 เพราะ Hub จะกลายเป็นทางผ่านของไฟล์ลูกค้าทุกชิ้น และค่า bandwidth เป็นต้นทุนของเรา ขณะที่รายได้คิดตามจำนวน Machine (ADR 0001)
- **Project มีโฟลเดอร์กลางที่ทุกตัวเขียนได้ หรือทั้ง Project ใช้ Workdir เดียว**: ไม่ต้องหาว่าไฟล์อยู่ไหน แต่มีหลายตัวเขียนที่เดียวกัน ซึ่งขัดกับ ADR 0011 ทางที่ได้ประโยชน์นี้โดยไม่ทับกันคือ repo ของ Project กับ Worktree (ADR 0047)

## Consequences

- ความลับที่อยู่ใน Workdir เช่น `.env` หรือ token พนักงานร่วม Project ยังอ่านได้ระหว่างทำ Task ของ Project และระหว่างนั้นคัดลอกไปไว้ใน Workdir ของตัวเองได้ ซึ่งจะค้างอยู่ให้ Task อื่นเห็น Controller ต้องบอกให้ชัดตอนเอา Agent เข้า Project
- Agent ที่มี Channel อยู่ใน Project ไม่ได้ (ADR 0028)
- การเอา Agent เข้าหรือออกจาก Project ต้องมี Manage ที่ Agent ตัวนั้น ส่วนการลบ Project ต้องมี Manage ของ Project (ADR 0046)
- งานที่หลายพนักงานแก้ repo เดียวกันใช้ repo ของ Project (ADR 0047) ไม่ต้อง clone ไว้ใน Workdir ของแต่ละตัว
- dev ส่งงานต่อให้ deployer ที่อยู่บนอีกเครื่องไม่ได้ Member ต้องไปสั่ง deployer เองแบบคุยเดี่ยว
- Controller อ่าน Project จาก Runtime แล้วเก็บไว้บนเครื่อง (ADR 0021) ถ้า Machine ดับ จะเห็นได้แค่ที่เคยเก็บไว้ และแก้ Project ไม่ได้จนกว่าเครื่องจะกลับมา เพราะ Hub ไม่มีคิว (ADR 0005) Controller ที่เพิ่ง Linking ตอนเครื่องดับจะยังไม่เห็น Project ของเครื่องนั้นเลย
- ถ้า Machine พังหรือลงระบบใหม่ Project ของเครื่องนั้นหายไปพร้อมกับ Agent และประวัติ Task (ADR 0005) หลัง Pairing ใหม่และสร้าง Agent ใหม่แล้ว Controller เสนอสร้าง Project เดิมขึ้นใหม่จากที่เก็บไว้ โดยให้ Member จับคู่ Agent เก่ากับตัวใหม่แล้วเซ็นคำสั่งใหม่ ส่งคำสั่งเดิมที่เซ็นไว้ซ้ำไม่ได้ เพราะ Agent บนเครื่องใหม่เป็นตัวใหม่
- คำโปรยว่า Agent ทำงานร่วมกันข้ามเครื่อง เปลี่ยนเป็นสิ่งที่จะทำ ไม่ใช่สิ่งที่ทำได้แล้ว
