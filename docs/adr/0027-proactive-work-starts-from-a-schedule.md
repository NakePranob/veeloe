# งานเชิงรุกเริ่มจาก Schedule ที่ Member ตั้งและเซ็น และทุกรอบเปิด Task ใหม่

Agent เชิงรุกอย่าง OpenAI dots, Meta Muse, OpenClaw และ Hermes ทำงานเองได้โดยไม่ต้องมีคนพิมพ์ Veeloe ทำแบบนี้ได้ทางเดียว คือผ่าน Schedule ซึ่งเป็นข้อความที่ Member ตั้งเวลาไว้และเซ็น (ADR 0006) Runtime เปิดเป็น Task ใหม่กับ Agent หรือ Team ทุกรอบ Turn จึงยังเริ่มจากข้อความเหมือนเดิม และทำในนามของ Member ที่ตั้ง Schedule (ADR 0010) Grant กับ Approval ทำงานเหมือนเดิมทุกอย่าง และ Runtime ทำได้เองในเครื่องโดยไม่ต้องพึ่ง Hub ส่วน heartbeat แบบ OpenClaw ก็คือ Schedule ที่ข้อความบอกให้ Agent ไล่ดู checklist ของตัวเอง

ถ้าไม่มีอะไรต้องบอก Agent จบ Turn แบบไม่แจ้งใคร และ Task ของรอบนั้นจะไม่ขึ้นใน Inbox ถ้ามีเรื่อง Task นั้นจะขึ้นมาพร้อมข้อความ และ push ไปหา Member ที่ตั้ง Schedule ซึ่งคุยต่อใน Task นั้นได้เลย ความต่อเนื่องข้ามรอบ เช่นเรื่องไหนแจ้งไปแล้ว หรือ Member บอกให้ข้ามเรื่องไหน Agent จดไว้ในไฟล์ใน Workdir ซึ่งอยู่ข้าม Task อยู่แล้ว (ADR 0011) ถ้าถึงรอบแล้ว Agent ยังไม่ว่าง หรือรอบก่อนยังต่อคิวอยู่ ให้ข้ามรอบนั้นไปเลย ไม่ต่อคิว เพราะกว่าจะถึงคิว ผลของการเช็กก็เก่าไปแล้ว

## Considered Options

- **heartbeat ที่ Agent ตื่นขึ้นมาเองโดยไม่มีข้อความ**: ไม่มี Member ที่เป็นคนสั่ง ADR 0010 จึงใช้ไม่ได้ และไม่รู้ว่าต้องตรวจ Use ของใคร
- **เหตุการณ์จากข้างนอก เช่น webhook อีเมลเข้า หรือไฟล์เปลี่ยน แล้วเริ่ม Turn ทันที**: รู้เรื่องเร็วกว่า แต่ข้อความจากข้างนอกจะกลายเป็นตัวเริ่มงาน ซึ่งเปิดทาง prompt injection แบบที่ ADR 0003 กันอยู่ และเหตุการณ์ที่มาจากอินเทอร์เน็ตต้องผ่าน Hub ซึ่งจะเห็นเนื้อใน
- **ทุกรอบเข้า Task เดิม แบบ session หลักของ OpenClaw**: Agent จำได้ทุกอย่างและไม่แจ้งเรื่องเดิมซ้ำ แต่ประวัติยาวขึ้นทุกรอบ ถ้ารอบละ 30 นาที ไม่ถึงสัปดาห์ก็เกิน context window ต้องมีการย่อประวัติก่อน (ADR 0018) และค่า token ต่อรอบจะแพงขึ้นเรื่อยๆ
- **ใส่ข้อความของ Agent ลงใน push ตรงๆ**: อ่านได้จากหน้าจอล็อกเลย แต่เนื้อหาจะผ่าน Expo และ Apple หรือ Google ซึ่งขัดกับ ADR 0005

## Consequences

- Agent รู้เรื่องที่เกิดขึ้นช้าได้ถึงหนึ่งรอบ
- ความต่อเนื่องขึ้นอยู่กับว่า Agent จดไฟล์บันทึกหรือเปล่า ถ้าลืม รอบถัดไปจะแจ้งเรื่องเดิมซ้ำ
- push บอกแค่ว่า Agent ตัวไหนมีเรื่องจะบอก ต้องเปิดแอปถึงจะอ่านได้ จนกว่าจะมี E2E (ADR 0005)
- Schedule ที่ส่งงานให้ Team ใช้กติกาเดียวกับการเริ่ม Task กับ Team คือ Member ที่ตั้งต้องมี Use ที่ Agent ทุกตัวในทีม ถ้า Grant ถูกถอนทีหลัง รอบต่อไปจะเริ่มไม่ได้
- Schedule ไม่อยู่ใน v0.1 และเพิ่มทีหลังได้แบบ additive (ADR 0023) เพราะ Turn ยังเริ่มจากข้อความเหมือนเดิม
