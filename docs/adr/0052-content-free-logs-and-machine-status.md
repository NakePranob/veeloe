# Runtime เขียน log ที่ไม่มีเนื้อหาไว้บนเครื่อง ขอดูจากแอปได้ และส่งสถานะของ Machine ให้แอป

ถ้า Agent ค้าง, Provider ตอบ error หรือการอัปเดตไม่ผ่าน Owner ต้องมีที่ดู แต่ log ที่มีเนื้อหาส่งผ่าน Hub ไม่ได้จนกว่าจะมี E2E (ADR 0005) และเราสัญญาไว้ว่าไม่เห็นข้อมูลของลูกค้า Runtime จึงเขียน log ไว้ที่ `<VEELOE_HOME>/runtime/logs/` หมุนไฟล์ทุกวันและเก็บ 14 วัน supervisor กับ worker แยกไฟล์ log มีแค่รหัสของ Agent, Task และ Turn, ชนิดของข้อความ, ชื่อ tool, ระยะเวลา, จำนวน token และ error ไม่มีข้อความแชต ผลของ tool ชื่อไฟล์ใน Workdir หรือความลับ ทุกระดับรวมถึง debug เนื้อหาที่ต้องใช้หาปัญหามีอยู่ใน event log ของ Task แล้ว (ADR 0018)

บนเครื่องดูด้วย `veeloe logs` และ `veeloe logs --follow` จากแอป Owner หรือคนที่มี Manage ขอ log ด้วยคำขอที่เซ็น Runtime ตรวจสิทธิ์แล้วส่งกลับเป็นไฟล์แบบ Attachment (ADR 0050) แอปมีปุ่มแชร์ log ที่เปิดหน้าแชร์ของ OS ให้ส่งให้เราหรือแนบใน issue ได้เมื่อเจ้าของกดเอง Runtime ส่งสถานะของ Machine เป็น event ให้ Owner และคนที่มี Manage ทุกครั้งที่ต่อเข้ามาและเมื่อมีการเปลี่ยน คือเวอร์ชันของ Runtime, รายชื่อ feature ที่มี (ADR 0022), error ล่าสุด, พื้นที่ดิสก์ที่เหลือ และการใช้ Budget ของวันนี้ แอปแสดงเป็นการ์ดในหน้าของ Machine

## Considered Options

- **ส่ง crash report ไปบริการอย่าง Sentry อัตโนมัติ**: เห็นปัญหาของทุกเครื่องโดยไม่ต้องรอใครส่ง แต่ข้อมูลออกจากเครื่องโดยเจ้าของไม่รู้ ถ้าจะมีต้องเป็นแบบที่เจ้าของเปิดเอง และเพิ่มทีหลังได้
- **ใส่เนื้อหาไว้ใน log ระดับ debug**: หาปัญหาง่ายกว่า แต่ถ้าลืมเปิดค้างไว้ เนื้อหาจะหลุดตอนกดขอ log จากแอป
- **ดู log ได้แค่บนเครื่อง**: ไม่มีเส้นทางใหม่ผ่าน Hub แต่ Owner ที่อยู่ข้างนอกหรือใช้เซิร์ฟเวอร์ที่ต้อง SSH เข้าไปจะหาปัญหาไม่ได้

## Consequences

- ปัญหาที่ต้องดูเนื้อหาถึงจะเข้าใจ ต้องเปิดดู Task นั้นในแอปควบคู่กับ log
- โค้ดที่เขียน log ต้องระวังไม่ใส่เนื้อหา ทุก slice ควรมี test ว่า log ไม่มีข้อความของ Task
- สถานะของ Machine เป็นทางที่ Controller รู้ว่า Machine มี feature อะไร จึงต้องส่งตั้งแต่ v0.1
