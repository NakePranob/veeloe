# Agent มีระดับการเข้าถึงไฟล์สามระดับ ค่าเริ่มต้นคือในโฟลเดอร์ และระดับที่กว้างกว่าเป็นของ Owner เท่านั้น

Status: proposed

> แก้ ADR 0008, 0068 และ 0079 บางส่วน ตามที่เขียนไว้ในหัวของแต่ละตัว

sandbox ตาม ADR 0008 และ 0068 ให้ Agent อ่านได้แค่ Workdir, Project ที่ได้งาน และ Library ตามสิทธิ์ ส่วน home และ secret ปฏิเสธเสมอ แม้ใน Turn ของ Owner แบบนี้ปลอดภัย แต่ Owner ที่อยากให้ Agent ทำงานในโปรเจกต์ที่มีอยู่แล้วบนเครื่อง เช่น `~/code/shop` ต้อง clone เข้า Workdir ใหม่ หรือย้ายงานทั้งหมดมาไว้ใน Veeloe OpenBot (nightly-labs/openbot) แก้ด้วยปุ่ม Access ที่ค่าเริ่มต้นคือ Full access ไม่มี sandbox และระดับแคบสุดคือ Workspace only ที่กันแค่การเขียน อ่านได้ทั้งเครื่องและเน็ตเปิด เราไม่เอาค่าเริ่มต้นแบบนั้น เพราะหน้าเว็บที่ฝังคำสั่งไว้หน้าเดียวก็พาข้อมูลออกไปได้ แต่ให้ขยายได้เป็นขั้นโดยคนที่เป็นเจ้าของเครื่อง (เจ้าของตัดสิน 2026-11-28)

**สามระดับ** ตั้งต่อ Agent และอยู่ในค่าที่เซ็นของ Agent

- **ในโฟลเดอร์** (ค่าเริ่มต้น): เหมือนปัจจุบันทุกอย่าง อ่านและเขียนได้แค่ Workdir, Project ที่ได้งาน และ Library ตามสิทธิ์ ใน Turn ของ Member ที่มีแค่ Use ได้แค่ Workdir และ Library ไม่ได้ Project ตาม ADR 0059
- **โฟลเดอร์ที่เลือก**: ในโฟลเดอร์ บวกโฟลเดอร์บนเครื่องที่ Owner ระบุทีละโฟลเดอร์ แต่ละโฟลเดอร์เลือกได้ว่าอ่านอย่างเดียวหรืออ่านเขียน Runtime ปฏิเสธโฟลเดอร์ต้องห้ามและโฟลเดอร์ที่ครอบโฟลเดอร์ต้องห้าม ได้แก่ home ทั้งก้อน, `~/.ssh`, `~/.gnupg`, `~/.aws`, `~/.config/gcloud`, `~/.config/gh`, `~/.kube`, `~/.docker`, `~/.npmrc`, `~/.netrc`, `~/.git-credentials`, Keychain, โปรไฟล์ของ browser, โฟลเดอร์ของ Runtime เอง และโฟลเดอร์ระบบ ทั้งตอนเซ็นและตอนเริ่มทุก Turn (path ที่ resolve symlink แล้ว)
- **ทั้งเครื่อง**: ไม่มี sandbox ของไฟล์ อ่านและเขียนได้ทุกที่ที่ user ของ Runtime เข้าถึง ยกเว้นโฟลเดอร์ของ Runtime เอง Egress, Allowlist และ Approval ยังทำงานเหมือนเดิม ระดับนี้คือ Full access ของ OpenBot แต่ยังมี Egress กับลายเซ็น

**กลับคำตัดสินของ ADR 0068** ADR 0068 ปฏิเสธทางที่ให้ Owner เพิ่ม read root เอง และปฏิเสธ home เสมอแม้ใน Turn ของ Owner ADR นี้กลับสองข้อนั้น เฉพาะที่ Owner ตั้งระดับที่กว้างกว่าเอง ส่วนรายการโฟลเดอร์ต้องห้ามข้างบนยังปฏิเสธในระดับโฟลเดอร์ที่เลือกเสมอ เหตุผลที่ 0068 ปฏิเสธ คือ Agent อ่าน secret ได้ ยังถูกกันด้วยรายการนั้น และระดับทั้งเครื่องเป็นการเลือกของ Owner ที่หน้ายืนยันบอกไว้ชัด

**เขียนได้ทีละ Agent** โฟลเดอร์ที่เลือกแบบอ่านเขียนมี Agent ที่เขียนได้ได้ตัวเดียว เหมือน Library ตาม ADR 0037 Runtime ปฏิเสธตอนเซ็นถ้ามี Agent อื่นถือโฟลเดอร์นั้น หรือโฟลเดอร์ที่ซ้อนกัน แบบอ่านเขียนอยู่แล้ว Agent อื่นได้แค่อ่าน และคำสั่งที่เขียนในโฟลเดอร์นั้นใช้ write lock ตาม ADR 0080 เหมือน Project

**ใครตั้งได้** ในโฟลเดอร์ตั้งได้โดยคนที่มี Manage ระดับที่กว้างกว่าตั้งได้โดย Owner เท่านั้น ต้องปลดล็อกใหม่ และหน้ายืนยันบอกว่า Agent จะอ่าน แก้ และลบอะไรได้

**Agent ที่กว้างเป็นของ Owner ที่เฝ้าอยู่เท่านั้น** ระดับเป็นของ Agent ไม่ใช่ของ Turn เพราะ sandbox ครอบ worker ทั้งโปรเซสต่อ Agent และ worker ตัวเดียวรันหลาย Turn พร้อมกัน (ADR 0080) ทุก Turn ของ Agent ที่ตั้งโฟลเดอร์ที่เลือกหรือทั้งเครื่องจึงต้องมาจาก Owner ที่สั่งเอง Runtime ปฏิเสธสิ่งต่อไปนี้บน Agent ที่กว้าง และปฏิเสธการขยายระดับถ้า Agent ยังมีอยู่ โดยบอกว่าต้องเอาอะไรออกก่อน:

- Grant ของ Member ที่ไม่ใช่ Owner (ADR 0059)
- Channel (ADR 0028)
- Trigger ทุกชนิด ทั้ง Schedule, Watch, Idle Work และ Webhook (ADR 0079, 0086)
- การอยู่ใน Team ไม่ว่าเป็น Entry หรือพนักงาน (ADR 0084)

ถ้าอยากให้คนอื่น Channel หรือรอบที่ไม่มีคนเฝ้าทำงานแบบเดียวกัน ให้ใช้ Agent อีกตัวที่อยู่ในโฟลเดอร์ `turn_files()` ใน runtime-core ยังเป็นจุดเดียวที่ตัดสินระดับของ Turn ถ้าวันหนึ่งต้องให้ Member ใช้ Agent ที่กว้างได้แบบในโฟลเดอร์ ทางต่อคือ worker ตัวที่สองต่อ Agent ซึ่งต้องย้าย write lock ไปที่ supervisor

**Agent ลดได้ เพิ่มไม่ได้** Agent ลดระดับของตัวเองได้ด้วย tool แต่เพิ่มไม่ได้ ระดับใหม่มีผลเมื่อ Turn ที่ทำอยู่จบแล้ว worker เริ่มใหม่ด้วย sandbox ที่แคบลง การเพิ่มต้องมาจากคนเสมอ Agent ที่สร้างจาก Blueprint หรือที่ Agent ช่วยร่าง เริ่มที่ในโฟลเดอร์

## Considered Options

- **ค่าเริ่มต้นเป็นทั้งเครื่องแบบ OpenBot**: ตั้งง่ายสุดและไม่ต้องถาม แต่ Agent ส่วนใหญ่จะอ่าน secret ได้ และจุดต่างหลักของ Veeloe หายไป
- **sandbox สำหรับ Agent ของ Member เท่านั้น ของ Owner เปิดทั้งเครื่อง**: แบ่งตามเจ้าของไม่ตรงกับความเสี่ยงจริง Agent ของ Owner อ่านหน้าเว็บที่วางกับดักไว้ได้เหมือนกัน
- **ไม่มีระดับที่กว้างกว่าเลย ให้ย้ายงานเข้า Workdir**: ปลอดภัยสุด แต่คนที่มีโปรเจกต์อยู่แล้วต้องย้ายทั้งหมด และหลายคนจะหนีไปใช้เครื่องมือที่ไม่มี sandbox
- **ระดับต่อ Turn ด้วย worker ตัวที่สองต่อ Agent**: Member ใช้ Agent ที่กว้างได้แบบในโฟลเดอร์ แต่ต้องย้าย write lock ไป supervisor และจัดการสองโปรเซสต่อ Agent ยังไม่มีใครต้องใช้ จึงเลื่อนไว้
- **supervisor รัน tool ทีละครั้งใน sandbox ของ Turn**: แยกต่อ Turn ได้แม่นที่สุด แต่ต้องเขียน file tool ใหม่ทั้งหมด และ supervisor กลายเป็นที่รันงานของ Agent ซึ่งขัดกับ ADR 0069
- **ทั้งเครื่องแบบกันแค่การเขียน (Workspace only ของ OpenBot)**: ไม่ปกป้อง secret เพราะอ่านได้ทั้งเครื่องและส่งออกได้

## Consequences

- โฟลเดอร์ที่เลือกใช้กลไก mount เดียวกับ Library (ADR 0037) และ Project บน macOS เป็น `subpath` ใน profile ของ sandbox-exec บน Linux เป็น bind mount ของ bwrap
- ทั้งเครื่องบน Linux ยังรันใน namespace ของเครือข่าย จึงออกเน็ตได้แค่ผ่าน proxy ของ Egress บน macOS ยังบังคับ Egress ผ่าน profile ของ sandbox-exec ที่อนุญาตแค่ port ของ proxy
- Controller แสดงระดับที่ใช้อยู่ทุกที่ที่ Owner เห็น Agent และ Task log บันทึกระดับของแต่ละ Turn
- Agent ที่กว้างแชร์ให้ Member ไม่ได้ ใช้กับ Channel ไม่ได้ และตั้ง Trigger ไม่ได้ จนกว่าจะลดกลับเป็นในโฟลเดอร์
- เปลี่ยนระดับแล้ว worker ของ Agent นั้นต้องเริ่มใหม่ จึงรอให้ Turn ที่ทำอยู่จบก่อน
