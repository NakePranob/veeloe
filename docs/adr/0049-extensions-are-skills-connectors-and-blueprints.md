# ส่วนขยายจากคนอื่นมีแค่ Skill, Connector และ Blueprint ไม่มี plugin ที่รันใน Runtime

วันหนึ่งเราอยากให้คนอื่นทำของมาเสริม Veeloe หรือทำ Agent มาวางขายใน marketplace ทางที่ตรงที่สุดคือระบบ plugin ที่โหลดโค้ดเข้า Runtime แต่ supervisor ถือ key ของ Provider, token ของ bot และ credential ของ Connector (ADR 0028, 0039, 0042) โค้ดของคนอื่นที่รันใน process เดียวกันอ่านได้ทั้งหมด และข้าม Grant, Approval, Allowlist กับ sandbox ได้ด้วย plugin ตัวเดียว ส่วนขยายจากคนอื่นจึงมีสามแบบ และไม่มีแบบไหนรันในตัว Runtime

- **Skill** (ADR 0038): คำสั่งกับ script ที่รันใน sandbox ของ Agent ติดตั้งจากลิงก์ได้อยู่แล้ว
- **Connector** (ADR 0039): ความสามารถใหม่ที่เป็นโค้ดเขียนเป็น MCP server ซึ่งรันใน sandbox หรือบนเซิร์ฟเวอร์ของคนทำ tool ถูกตรึงไว้ตอนติดตั้งและต้องอยู่ใน Allowlist
- **Blueprint**: แม่แบบของ Agent ที่มีคำสั่งของ Agent, Skill, รายชื่อ Connector ที่ต้องใช้, Allowlist กับ Egress ที่แนะนำ และ Character ตอนติดตั้ง แอปแสดงว่าขออะไรบ้าง เช่นเน็ตโดเมนไหน และคำสั่งอะไรที่ไม่ต้องขออนุมัติ แล้ว Member ที่มี Manage เซ็นทับ hash แบบเดียวกับ Skill ผลที่ได้คือ Agent ปกติหนึ่งตัวที่ใช้ Provider และ Budget ของลูกค้าเอง คนทำ Blueprint ไม่เห็นข้อมูลของลูกค้า

marketplace ช่วงแรกเป็นแค่สารบัญ เช่น repo สาธารณะที่ลงรายการไว้ แอปอ่านสารบัญแล้วติดตั้งด้วยทางเดิม ยังไม่ต้องมีระบบหลังบ้าน

## Considered Options

- **plugin ที่โหลดโค้ดเข้า Runtime**: ทำได้ทุกอย่าง แต่เท่ากับให้คนอื่นถือความลับทุกอย่างบนเครื่อง ความสามารถที่ plugin จะให้ MCP ให้ได้เกือบหมดโดยไม่ต้องเข้ามาถึงแกน
- **plugin ใน Controller**: เพิ่มหน้าจอได้ แต่ Controller ถือกุญแจที่เซ็นทุกคำสั่ง (ADR 0006) plugin ที่เซ็นแทน Member ได้อันตรายพอกัน

## Consequences

- Blueprint กับ marketplace ยังไม่ได้ทำ และมาหลัง v0.3 (ADR 0048) เพราะต้องมี E2E และระบบองค์กรก่อน
- ต้องตัดสินทีหลังเรื่องการเซ็นของคนเผยแพร่ การรีวิว และการจ่ายเงิน
- feature ของเราเองเพิ่มเป็น slice ในโค้ด (ADR 0022) ไม่ผ่านช่องทางนี้
