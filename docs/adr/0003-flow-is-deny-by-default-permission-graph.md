# Delegation ส่งได้เฉพาะตามเส้นใน Flow และค่าเริ่มต้นคือห้ามส่ง

Flow เป็นผังสิทธิ์ ไม่ใช่ลำดับขั้นตอน เส้นจาก A ไป B หมายถึง A *ส่งงานให้* B ได้ ส่วนจะส่งเมื่อไหร่ Agent เป็นคนตัดสินใจเอง Agent ที่สร้างใหม่ยังไม่มีเส้นเลยจนกว่าผู้ใช้จะลากให้ เหตุผลคือ Agent อ่านข้อมูลจากข้างนอก (เว็บ ไฟล์ issue) ที่อาจมี prompt injection แฝงมา ถ้าปล่อยให้ส่งงานหากันได้อิสระ Agent ที่โดนหลอกแค่ตัวเดียวก็สั่ง Agent บนเครื่องที่มีสิทธิ์สูงกว่าได้ทันที เช่น deployer บน production

คนที่ตรวจว่าส่งงานตามเส้นหรือไม่คือ Hub ไม่ใช่ Runtime เพราะ Delegation ทุกครั้งต้องผ่าน Hub อยู่แล้ว Hub จะตรวจว่ามีเส้นจาก Agent ต้นทางไปหาปลายทางจริง และตรวจว่า Agent ต้นทางอยู่บน Machine ที่ส่งข้อความมาจริง เครื่องที่โดนเจาะจึงส่งงานนอกเส้นไม่ได้ Flow เก็บไว้ที่ Hub ได้ เพราะเป็นข้อมูลสำหรับ routing ไม่ใช่เนื้อหาของ Task

## Considered Options

- **ค่าเริ่มต้นให้ส่งได้หมด**: ตอนเริ่มใช้สะดวกกว่า แต่เปิดช่องให้การโจมตีข้างต้น
- **Flow เป็นลำดับขั้นตายตัวแบบ n8n**: คาดเดาได้ง่าย แต่ไม่ได้ทำงานแบบทีม ทีหลังค่อยทำเป็นป้าย "ส่งต่อเสมอ" ติดบนเส้นได้
