# Hub ทำหน้าที่ส่งต่อข้อความเท่านั้น ส่วนสมองและ key ของ LLM อยู่บน Runtime

Veeloe เป็นผลิตภัณฑ์ที่เรา host Hub เอง ทั้ง Runtime และแอปจะเปิดการเชื่อมต่อออกไปหา Hub เพียงทางเดียว Hub จึงไม่ต้องต่อเข้าเครื่องของลูกค้า และลูกค้าไม่ต้องเปิด port ส่วนลูป LLM ของ Agent รันบน Runtime โดยใช้ API key ของลูกค้าเอง (BYOK) Hub มีหน้าที่แค่ส่งต่อข้อความ ไม่เรียก LLM และไม่ถือ key เราเลือกแบบนี้เพื่อให้ค่า server ต่ำ และให้ไฟล์กับ key ของลูกค้าอยู่บนเครื่องของลูกค้า

## Considered Options

- **สมองอยู่บน cloud ของเรา Runtime เป็นแค่มือ**: แบบนี้คิดเงินตาม usage ได้ และอัปเดต Agent ได้ทีเดียวทุกคน แต่เราต้องออกค่า LLM ไปก่อน ข้อมูลของลูกค้าต้องวิ่งผ่านเรา และถ้า cloud ล่ม Agent ทุกตัวจะหยุดทำงาน
- **ลูกค้า self-host Hub เอง**: ตั้งค่ายากเกินไปสำหรับผลิตภัณฑ์ และหารายได้ยากกว่า
- **ไม่มี Hub ใช้ Tailscale หรือ P2P แทน**: ลูกค้าทุกคนต้องตั้งค่าเครือข่ายเอง เหมาะกับใช้คนเดียวมากกว่าขาย

## Consequences

- รายได้ต้องมาจาก subscription เพราะบวกกำไรจาก token ไม่ได้ คิดเงินต่อ Workspace ตามจำนวน Machine ที่ Pair แล้ว ซึ่งตรงกับต้นทุนหลักของเรา คือ WebSocket ที่ต่อค้างไว้ ให้ใช้ฟรี 1 Machine ส่วน Member และ Agent ไม่คิดเงิน ทีมจะได้ชวนคนมาเป็น Approver ได้โดยไม่ต้องห่วงเรื่องเงิน Hub เป็นตัวกันไม่ให้เกินโควตาตอน Pairing
- พฤติกรรมของ Agent เปลี่ยนได้ก็ต่อเมื่อ Runtime ถูกอัปเดต Runtime จึงต้องอัปเดตตัวเองได้
