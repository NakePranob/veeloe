# ถามน้อยลงโดยไม่ขยายสิทธิ์ถาวร: อนุญาตทั้ง Task, อนุญาตตลอดเฉพาะคำสั่งอ่าน และชุดสิทธิ์สำเร็จรูป

Status: proposed

> แก้ ADR 0030 และ 0075 บางส่วน ตามที่เขียนไว้ในหัวของแต่ละตัว

การ์ด Approval ตอนนี้มีสองระดับ คืออนุญาตครั้งเดียว กับอนุญาตตลอดที่เพิ่มเข้า Allowlist งาน research หรืองานที่รันคำสั่งชุดเดิมหลายครั้งใน Task เดียวจึงต้องกดซ้ำ หรือไม่ก็ขยาย Allowlist ถาวรทั้งที่ตั้งใจแค่งานนี้ คนที่กดบ่อยจะเริ่มกดโดยไม่อ่าน ซึ่งทำให้ Approval ไร้ความหมาย Allowlist ตาม ADR 0030 ก็ไม่แยกว่าคำสั่งอ่านหรือเขียน `npm` ในรายการจึงครอบทั้ง `npm ls` และ `npm install` OpenBot (nightly-labs/openbot) มี "Always allow in this folder" ที่ครอบเฉพาะคำสั่งที่ไม่แก้ไฟล์ และคำสั่งที่แก้ไฟล์ยังถามทุกครั้ง (เจ้าของตัดสิน 2026-11-28)

**อนุญาตทั้ง Task นี้** การ์ด Approval ของคำสั่งและของโดเมนมีตัวเลือกที่สาม ใช้ได้กับคำสั่งเดียวกันทั้ง Task นั้น (เทียบคำนำหน้าแบบ Allowlist) หรือโดเมนเดียวกันทั้ง Task นั้น สิทธิ์นี้หมดเมื่อ Task จบ เก็บไว้ที่ Runtime ผูกกับ Task ไม่เข้า Allowlist ไม่ข้าม Task และไม่ใช้กับรอบที่ไม่มีคนเฝ้า คนที่มี Approve เลือกได้ ไม่ต้องมี Manage

**อนุญาตตลอดเฉพาะคำสั่งอ่าน** รายการใน Allowlist มีชนิด อ่าน หรือ อ่านเขียน รายการชนิดอ่านผ่านเฉพาะเมื่อ Runtime ตัดสินว่าคำสั่งนั้นไม่เขียนไฟล์ (ใช้ชุดคำสั่งและธงที่ ADR 0075 ตัดสินอยู่แล้ว แล้วขยายด้วยรายการธงอ่านอย่างเดียวของคำสั่งที่พบบ่อย เช่น `git log`, `npm ls`) ถ้าตัดสินไม่ได้ถือว่าเขียน รายการธงอ่านอย่างเดียวที่เพิ่มนี้ใช้แค่กับ Allowlist ชนิดอ่าน ไม่แก้รายการที่ ADR 0075 ใช้ตัดสินว่าต้องจอง write lock ตาม ADR 0080 สองรายการแยกกัน เพราะข้อผิดของแต่ละรายการต้องเอียงคนละทาง รายการที่มีอยู่แล้วเป็นชนิดอ่านเขียนตามเดิม การ์ด Approval เสนออนุญาตตลอดแบบอ่านก่อน และแบบอ่านเขียนอยู่หลังตัวเลือกอื่น

**ชุดสิทธิ์สำเร็จรูป** หน้าสร้าง Agent ให้เลือกชุดที่ตั้ง Allowlist, Egress และระดับไฟล์ (ADR 0087) ในทีเดียว: ระวัง (ค่าปัจจุบัน), อ่านโค้ด (คำสั่งอ่านอย่างเดียวของ git และตัวจัดการแพ็กเกจ), Research (ทั้งเน็ต, ในโฟลเดอร์, ไม่มีคำสั่งเพิ่ม) และทำงานในโปรเจกต์ (โฟลเดอร์ที่เลือก, คำสั่ง build และ test ชนิดอ่านเขียน, Egress ของ registry หลัก) ชุดเป็นแค่ทางลัดตอนสร้าง หลังสร้างค่าทั้งหมดแก้ได้ทีละอย่าง และไม่มีอะไรผูกกับชื่อชุดต่อ

## Considered Options

- **อนุญาตชั่วโมงหนึ่งแทนทั้ง Task**: ไม่ผูกกับงาน สิทธิ์ข้ามไปใช้กับ Task อื่นที่คนไม่ได้ดูอยู่
- **ให้ Agent ขอสิทธิ์ทั้งชุดตอนเริ่ม Task**: ถามครั้งเดียว แต่ Agent เดาไม่ได้ว่าจะต้องใช้อะไร และคนอนุมัติรายการยาวโดยไม่อ่าน
- **คงสองระดับ**: ไม่มีงานเพิ่ม แต่ปัญหาการกดซ้ำและ Allowlist ที่กว้างเกินยังอยู่

## Consequences

- Runtime ต้องจำสิทธิ์ของ Task ไว้ข้ามการรีสตาร์ต worker เพราะ Task อยู่นานกว่า Turn
- การตัดสินว่าคำสั่งอ่านหรือเขียนผิดได้ ทางที่ผิดต้องเป็นทางที่ถามมากเกินเสมอ ไม่ใช่ปล่อยผ่าน
- หน้า Allowlist แสดงชนิดของแต่ละรายการ และ "ลองคำสั่ง" บอกว่าคำสั่งตัวอย่างนับเป็นอ่านหรือเขียน
