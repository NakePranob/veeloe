# Project มีสิทธิ์ของตัวเองสี่ระดับ มี wiki และมี Ask ที่ตอบแบบอ่านอย่างเดียว

กฎเดิมของ ADR 0010 ให้คนที่จะเริ่มงานกับทีมต้องมี Use ที่ทุกตัว ซึ่งใช้กับ Project ได้ไม่ดี ไม่มีระดับดูอย่างเดียวให้หัวหน้าหรือลูกค้า ทุกครั้งที่เพิ่มพนักงานต้องไล่แจก Use ใหม่ และคนที่มี Use แค่ Entry ก็เห็นผลงานของพนักงานตัวอื่นผ่าน Task ของ Entry ได้ Project จึงมีสิทธิ์ของตัวเองสี่ระดับ คือ View (เห็น Task และ wiki), Ask (ถามได้), Use (สั่งงานและกด Stop) และ Manage (ให้สิทธิ์ใน Project ตั้ง Entry ตั้งพนักงานที่เขียน wiki ตั้งเพดานการส่งงาน และลบ Project) ใน Project ใช้สิทธิ์ของ Project นอก Project ใช้สิทธิ์ของ Agent จุดที่ทำให้สองชั้นนี้ไม่ขัดกันคือการเอา Agent เข้ามาเป็นพนักงานต้องมี Manage ที่ Agent ตัวนั้น ซึ่งเท่ากับคนดูแล Agent ยินยอมให้ Agent รับงานจากคนที่มีสิทธิ์ใน Project ถ้าไม่มีการยินยอมนี้ สิทธิ์ใน Project จะกลายเป็นทางลัดไปใช้ Agent ที่ตัวเองไม่มีสิทธิ์ ซึ่งเป็น confused deputy ที่ ADR 0010 ปิดไว้ Approval ยังไปที่คนที่มี Approve ที่ Agent ตัวนั้นเสมอ Project ไม่มีระดับ Approve ถ้า deployer ใน Project จะขึ้น production คนอนุมัติยังเป็น SRE ที่ดูแล deployer Task ของ Project เห็นได้เฉพาะคนที่มีสิทธิ์ใน Project แม้จะมี Use ที่ Entry ก็ตาม Member ที่มี Manage ที่ Agent อย่างน้อยหนึ่งตัวสร้าง Project ได้ และได้ Manage ของ Project นั้น

Project มี Library ของตัวเองเป็น wiki (ADR 0037) พนักงานทุกตัวอ่านได้ มีพนักงานที่เขียนได้ตัวเดียว ค่าเริ่มต้นคือ Entry และคนที่มีสิทธิ์ใน Project ดูได้ Member ที่อยากแก้ wiki สั่งพนักงานที่ดูแล wiki ให้แก้ ไม่แก้เองจนเกิดคนเขียนสองคน

Ask คือคำถามใน Project ที่ตอบด้วย Turn แบบอ่านอย่างเดียว คนถามคือคนที่มีสิทธิ์ Ask ขึ้นไป หรือพนักงานด้วยกัน คนตอบคือ Entry หรือพนักงานที่ถูก Mention Turn แบบนี้มีแค่ tool อ่านไฟล์ ค้น Task ของ Project และอ่าน wiki ไม่มี bash ไม่ส่งงานต่อ ไม่เรียก Connector และไม่ถามต่อ จึงเปลี่ยนอะไรในงานไม่ได้ และเพราะรู้แน่ว่าไม่เขียน จึงรันพร้อมกับ Turn ที่กำลังแก้งานได้โดยไม่ต้องรอคิว และพนักงานที่ถามกันไม่มีทางรอกันเป็นวง Ask ใช้ Budget และ model ของคนตอบ การกันว่าอะไรถามไม่ได้มีสองชั้น ชั้นที่กันได้แน่นอนคือ path ที่ Project ห้าม ซึ่งคนที่มี Manage ตั้ง รวมถึงไฟล์ลับที่ห้ามเสมอ sandbox ของ Turn แบบ Ask ไม่เปิดให้อ่าน และ Task ที่ตั้งว่าปิดจาก Ask ซึ่ง tool ค้นหาไม่เจอและคนระดับ View กับ Ask มองไม่เห็น ชั้นที่กันได้ไม่แน่นอนคือหัวข้อที่ห้ามตอบ ซึ่งเป็นแค่คำสั่งให้ LLM และคนถามเลี่ยงได้ แอปต้องบอกว่าชั้นนี้คือ "ขอให้ไม่ตอบ" ไม่ใช่ "ตอบไม่ได้"

Mention คือ @ ใน Task ของ Project Mention คนส่ง push ให้คนนั้น และทั้ง Member และ Agent Mention คนที่มีสิทธิ์ใน Project ได้ Mention พนักงานในข้อความสั่งงานเป็นการบอก Entry ว่าอยากให้ตัวนั้นทำ ข้อความยังไปที่ Entry และ Entry เป็นคนส่งงานเอง ส่วน Mention พนักงานใน Ask เป็นการถามตัวนั้นตรงๆ Mention สิ่งอื่น เช่น หน้าใน wiki หรือไฟล์ เพิ่มทีหลังได้ ถ้า Agent Mention คนเดิมซ้ำใน Task เดิมขณะที่ Mention ก่อนหน้ายังไม่ถูกอ่าน จะไม่ส่ง push ซ้ำ แต่ Mention ยังขึ้นใน Task Agent ที่โดนหลอกให้ Mention รัวๆ จึงส่ง push ได้ครั้งเดียว ส่วน Mention แบบอื่นมีตัวกันอยู่แล้ว Entry ที่ Mention พนักงานในการสั่งงานนับในเพดานการส่งงาน และ Ask ถามต่อไม่ได้ จึงไม่ต้องมีเพดาน Mention เป็นตัวเลข

## Considered Options

- **ไม่มีสิทธิ์ระดับ Project ใช้กฎต้องมี Use ที่พนักงานทุกตัว**: สิทธิ์มีชั้นเดียว แต่ไม่มีระดับดูอย่างเดียว และต้องแจกใหม่ทุกครั้งที่เพิ่มพนักงาน
- **มีระดับ Approve ใน Project**: อนุมัติงานใน Project ได้ที่เดียว แต่คนที่มีสิทธิ์ใน Project จะอนุมัติสิ่งที่ Agent สิทธิ์สูงทำได้ ซึ่งข้ามคนที่ดูแล Agent ตัวนั้น
- **ไม่มีระดับ Ask**: มีระดับน้อยกว่า แต่คนอยากรู้ต้องอ่าน wiki เอง หรือต้องได้ Use ซึ่งสั่งงานได้ด้วย
- **กันแค่หัวข้อ ไม่กันที่ path**: ตั้งง่าย แต่คนถามเลี่ยงได้ด้วยการถามอ้อม ข้อมูลลับจริงต้องอยู่ใน path ที่อ่านไม่ได้

## Consequences

- สิทธิ์มีสองชั้น แอปต้องแสดงให้ชัดว่าคนนี้ทำอะไรได้ใน Project และทำอะไรได้กับ Agent ตรงๆ
- Workdir, Memory และ Connector ของพนักงานยังเป็นของ Agent แต่คนใน Project ใช้ได้ทางอ้อมผ่าน Entry ซึ่งคนดูแล Agent ยินยอมไว้ตอนเอาเข้ามา
- Ask ที่ถามตอนที่ Turn อื่นกำลังแก้ไฟล์อาจเห็นงานที่ทำค้างครึ่งทาง
- คนที่ไม่ได้เป็น Member ที่อยากรู้เรื่อง Project ให้ใช้ Channel ที่ผูกกับ Agent ที่อ่าน wiki ของ Project ได้ (ADR 0028)
- ถ้าเพิ่มพนักงานใหม่ คนที่มีสิทธิ์ใน Project ใช้พนักงานนั้นได้ทันที ไม่ต้องแจกเพิ่ม
