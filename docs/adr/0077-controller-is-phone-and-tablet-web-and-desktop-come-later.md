# Controller บน React Native ทำแค่ iPhone, iPad และ Android ส่วนเว็บและเดสก์ท็อปเขียนใหม่ทีหลัง

Status: accepted

เปลี่ยน ADR 0012, 0021 และ 0053: เดิม Controller ตัวเดียวกันรันทั้งบนมือถือและบนเว็บผ่าน `react-native-web` ตอนนี้แอป React Native ใน `controller/` รันแค่บน iPhone, iPad และ Android ส่วน Controller บนเว็บและเดสก์ท็อปจะเขียนใหม่ด้วย Tauri กับ Next.js หลัง feature นิ่งแล้ว

เว็บทำให้ทุกเรื่องต้องมีสองทาง แต่ไม่ได้ช่วยพิสูจน์อะไรที่ v0.1 ต้องพิสูจน์ ทั้งกุญแจที่อยู่ใน IndexedDB และปลดด้วย passkey แทน Keychain (ADR 0012), SQLite ที่เป็นแค่ cache และเปิดได้ทีละแท็บ (ADR 0021), header ของ Stack ที่วาดต่างกัน และการเช็กทุกหน้าสองรอบ หน้าจอที่ออกแบบมาเพื่อมือถือก็ไม่ใช่หน้าจอที่ดีที่สุดบนจอคอม เมื่อ feature นิ่งแล้ว การเขียนเว็บและเดสก์ท็อปใหม่ด้วยเครื่องมือของมันเองจะได้ผลดีกว่าการลากโค้ดมือถือไปรันในเบราว์เซอร์

**การตัดสินใจ:**

- `controller/` เป็นแอป Expo สำหรับ iPhone, iPad และ Android เท่านั้น ลบ `react-native-web`, กุญแจบนเว็บ (IndexedDB กับ passkey), การล็อกให้เปิดได้ทีละแท็บ, หน้า "เปิดอยู่อีกแท็บ" และทางแยกของเว็บในโค้ดทั้งหมด
- กุญแจของ Controller อยู่ใน Keychain หรือ Keystore และปลดด้วย biometric อย่างเดียว (ADR 0012)
- เครื่องของ Member (ADR 0053) คือ iPhone, iPad หรือ Android จนกว่า Controller บนเว็บและเดสก์ท็อปจะมา
- Controller บนเว็บและเดสก์ท็อป (Tauri กับ Next.js) เป็นงานแยกหลัง feature นิ่ง ยังไม่ได้กำหนดว่าอยู่ phase ไหน เมื่อถึงตอนนั้นต้องมี ADR ของตัวเอง ว่ากุญแจอยู่ที่ไหนและ local-first ทำอย่างไรบนเว็บและเดสก์ท็อป
- การขาย subscription บนเว็บ (ADR 0024) ไม่เกี่ยวกับเรื่องนี้ เพราะเป็นเว็บไซต์ ไม่ใช่ Controller

## Considered Options

- **คงเว็บไว้ใน React Native**: Owner ใช้ Veeloe จากคอมได้ตั้งแต่วันแรก แต่ทุก feature ต้องทำและเช็กสองทาง และหน้าจอบนคอมก็เป็นหน้าจอมือถือที่ยืดออก
- **ตัดแค่เกณฑ์ตรวจของเว็บ แต่เก็บโค้ดไว้**: งานน้อยกว่าในวันนี้ แต่โค้ดที่ไม่มีใครเช็กจะพังเงียบๆ และยังต้องแบกทางแยกต่อไป

## Consequences

- มือถือที่ไม่ได้ตั้ง Face ID หรือลายนิ้วมือใช้ Veeloe ไม่ได้เลย เดิมยังมีทางไปใช้บนเว็บ (ADR 0012) หน้าสร้างกุญแจต้องบอกให้ตั้งก่อน
- จนกว่าจะมี Controller บนเว็บหรือเดสก์ท็อป Owner สั่ง Agent ได้จากมือถือหรือ iPad เท่านั้น และ Pairing ต้องสแกน QR ด้วยกล้องของเครื่องเหล่านั้น หรือวางลิงก์
- Hub ไม่ต้องเปลี่ยน การยืนยันตัวผ่าน WebSocket ที่รองรับเบราว์เซอร์ (ADR 0013) ยังอยู่ให้ Controller บนเว็บในอนาคตใช้
- เกณฑ์ "เปิดบน iOS Simulator และ web" ใน spec, tasks และ `controller/AGENTS.md` เปลี่ยนเป็น iOS Simulator (และ Android เมื่อต้องเช็กสิ่งที่ต่างกัน)
