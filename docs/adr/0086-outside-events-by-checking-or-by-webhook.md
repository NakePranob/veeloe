# เหตุจากระบบภายนอกเริ่มงานได้สองทาง คือเช็กเป็นระยะ หรือ Webhook ที่ Hub รับแล้วเข้ารหัสทันที

> แก้ ADR 0005 บางส่วน ตามที่เขียนไว้ในหัวของ ADR นั้น

Trigger ที่มีอยู่ (ADR 0067) มาจากเวลา (Schedule) ความเงียบ (Idle Work) และไฟล์บนเครื่อง (Watch) งานจริงหลายอย่างต้องเริ่มจากระบบอื่น เช่น มี PR ใหม่ใน GitHub, Sentry แจ้ง error หรือมีอีเมลเข้า OpenBot รับ webhook ที่ server ของตัวเอง แต่ Machine ของเราไม่เปิด port ให้ใครต่อเข้ามา (ADR 0001) และถ้าให้ Hub รับแทน Hub ก็จะเห็นเนื้อหาของ event ซึ่งขัดกับ ADR 0005 เราจึงให้เลือกได้สองทาง และให้ทางที่ Hub เห็นเนื้อหาเป็นทางที่คนเลือกเองโดยรู้ตัว (เจ้าของตัดสิน 2026-11-27)

**เช็กเป็นระยะ** เป็น Schedule ธรรมดาที่ข้อความของรอบสั่งให้ Agent เช็กผ่าน Connector เช่น ทุก 15 นาที และถ้าไม่มีอะไรใหม่ก็จบแบบไม่แจ้งใคร (ADR 0027) ไม่มีกลไกใหม่ Controller แค่มีทางลัดให้ตั้งแบบนี้ ข้อดีคือ Hub ไม่เห็นอะไรเลย ข้อเสียคือช้ากว่า และใช้ Budget ทุกรอบแม้ไม่มีอะไรใหม่

**Webhook** Member ที่มี Manage ที่ Agent ตั้ง Webhook ได้ Runtime ขอ URL สุ่มจาก Hub หนึ่งอันต่อ Webhook แล้วคนนำ URL ไปใส่ในระบบภายนอก การตั้งต้องผ่านหน้าเตือนว่า "Hub ของ Veeloe เห็นเนื้อหาของ event นี้ตอนรับ ก่อนเข้ารหัสส่งต่อให้เครื่องของคุณ" ซึ่งเป็นข้อยกเว้นเดียวของคำว่า "Hub อ่านไม่ได้" (ADR 0063) และแอปต้องบอกข้อยกเว้นนี้ในที่เดียวกับที่บอกคำนั้น

**Hub ถือเนื้อหาแค่ชั่วขณะ** เมื่อได้รับ event Hub ตรวจขนาด (ไม่เกิน 256KB) กับความถี่ต่อ URL แล้วเข้ารหัสทั้ง body และ header ด้วยกุญแจของ Machine แบบ sealed box ทันที Hub เก็บแค่ส่วนที่เข้ารหัสแล้วไว้จนกว่า Machine จะมารับ ไม่เกิน 7 วัน ไม่เขียนเนื้อหาลง log และตอบผู้ส่งว่ารับแล้วโดยไม่รอ Machine event จึงไม่หายตอนเครื่องปิด

**Runtime ตรวจและเริ่มงาน** ถ้าระบบภายนอกเซ็น event ได้ เช่น HMAC ของ GitHub คนตั้งใส่ secret ไว้ ซึ่ง supervisor ถือเองเหมือน credential ของ Connector (ADR 0039) และ Runtime ทิ้ง event ที่ลายเซ็นไม่ตรง ถ้าไม่ได้ตั้ง secret แอปเตือนว่าใครที่รู้ URL ก็ส่ง event ได้ งานที่เริ่มจาก Webhook ใช้กฎเดียวกับ Watch (ADR 0057) คือทำในนามคนตั้ง event ที่เข้ามาถี่รวมเป็นงานเดียว ใช้เพดาน 30% ของ Budget ร่วมกับ Idle Work และทำได้แค่สิ่งที่อยู่ใน Allowlist และ scope ที่เซ็นไว้ (ADR 0079) เนื้อหาของ event ส่งให้ LLM ในฐานะข้อมูล ไม่ใช่คำสั่ง เมื่อกุญแจของคนตั้งถูกถอน Webhook หยุด และ Hub ลบ URL ทิ้ง

## Considered Options

- **Webhook อย่างเดียว**: เร็วและไม่เปลือง Budget แต่ทุกคนที่อยากได้งานจากระบบภายนอกต้องยอมให้ Hub เห็นเนื้อหา
- **เช็กเป็นระยะอย่างเดียว**: รักษา ADR 0005 ได้ครบ แต่งานที่ต้องเร็ว เช่น ตอบ incident ช้าไปหนึ่งรอบ และ Agent ที่เช็กถี่ใช้ Budget มาก
- **ให้ Machine เปิด port หรือใช้ tunnel ของตัวเอง**: Hub ไม่เห็นอะไรเลย แต่คนต้องตั้งค่าเครือข่ายเอง ตามที่ ADR 0001 ปฏิเสธไว้
- **Hub ส่งต่อทันทีโดยไม่เก็บ**: Hub ไม่ต้องเก็บอะไร แต่ event ที่มาตอนเครื่องปิดหาย และระบบส่วนใหญ่ไม่ส่งซ้ำ

## Consequences

- Hub ที่โดนเจาะอ่าน event ระหว่างรับได้ ข้อยกเว้นนี้ใช้กับ Webhook ที่คนเลือกเองเท่านั้น ไม่กระทบเนื้อหาของ Task
- Hub เก็บข้อมูลที่เข้ารหัสแล้วไว้ได้ถึง 7 วัน ซึ่งเป็นต้นทุนของเรา เพดานขนาดกับความถี่ต่อ URL จึงต้องมีตั้งแต่แรก
- ระบบภายนอกที่เซ็น event ไม่ได้ รับได้แค่แบบไม่ตรวจ ซึ่งต้องพึ่ง URL ที่เดาไม่ได้
- เช็กเป็นระยะต้องมี Connector ก่อน (ADR 0039) ส่วน Webhook ทำได้โดยไม่ต้องมี
