# Runtime อัปเดตตัวเองจาก release ที่เซ็นแล้ว โดย Hub กำหนดเวอร์ชันต่ำสุด

Runtime เป็นคนรัน Agent จึงต้องได้รับการแก้ช่องโหว่ให้ถึงทุกเครื่องเร็วที่สุด และตัวอัปเดตต้องติดไปกับเวอร์ชันแรกเลย เพราะเครื่องที่ติดตั้งรุ่นที่ไม่มีตัวอัปเดตไปแล้ว จะไม่มีวันอัปเดตเองได้อีก Runtime จะเช็ก release ใหม่เฉพาะตอนที่ไม่มี Task ทำงานอยู่ ตรวจลายเซ็นของ release ด้วยกุญแจสาธารณะที่ฝังมาใน binary แล้วสลับไฟล์และ restart ผ่าน launchd หรือ systemd ส่วน Hub จะไม่รับ Runtime ที่เก่ากว่าเวอร์ชันต่ำสุดที่กำหนด

binary เก็บไว้ใน GitHub Releases ของ repo `veeloe` ซึ่งใช้ Releases กับ Runtime อย่างเดียว (ADR 0025) แต่ละ release มี manifest ที่บอกชื่อไฟล์กับ SHA-256 และ manifest นั้นเซ็นด้วย Ed25519 Runtime ตรวจลายเซ็นด้วย @noble ที่มีอยู่แล้ว (ADR 0012) จึงไม่ต้องใช้เครื่องมืออื่นเพิ่ม สคริปต์ติดตั้งแบบ `curl | sh` ก็ตรวจลายเซ็นแบบเดียวกัน เราไม่เลือก Sigstore/cosign แม้จะไม่ต้องเก็บกุญแจเอง เพราะ Runtime จะต้องตรวจลายเซ็นแบบที่ซับซ้อนกว่ามาก และต้องเชื่อใจตัวตนของ GitHub Actions แทนกุญแจที่เราคุมเอง

## Consequences

- ถ้ากุญแจที่ใช้เซ็น release หลุด ผลจะเท่ากับคนร้ายรันโค้ดบนเครื่องลูกค้าได้ทุกเครื่อง กุญแจนี้จึงต้องเก็บแยกออกจาก Hub และจาก CI ทั่วไป
- Hub ต้องรองรับ Runtime หลายเวอร์ชันพร้อมกันได้ ตั้งแต่เวอร์ชันต่ำสุดขึ้นไป
