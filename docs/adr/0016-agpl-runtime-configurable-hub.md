# ทั้ง repo ใช้ license AGPL-3.0 และให้ตั้ง URL ของ Hub เองได้

เมื่อทุกส่วนเปิด source (ADR 0025) คนอื่นก็เอา Hub ไปรันเองหรือเขียนเองได้ เรายอมรับเรื่องนี้ และให้ Runtime ตั้ง URL ของ Hub เองได้ คนทั่วไปจึง self-host ได้ฟรี ซึ่งช่วยเรื่องความไว้ใจและ community เราเลือก AGPL-3.0 เพราะบริษัทที่เอาโค้ดไปแก้แล้วเปิดเป็นบริการแข่งกับเรา ต้องเปิดโค้ดที่แก้ด้วย สิ่งที่เราขายคือ Hub ที่ลูกค้าไม่ต้องดูแลเอง แอป Controller บน store และ push ซึ่งอยู่ร่วมกับ Hub ของคนอื่นได้ในแบบเดียวกับที่ Tailscale อยู่ร่วมกับ Headscale

ข้อนี้ไม่ได้กลับคำตัดสินใน ADR 0001 โค้ดของ Hub เปิดอยู่ใน repo แต่เรายังไม่ support การ self-host คือไม่มีคู่มือและไม่รับแก้ปัญหา จนกว่าจะมีคนขอจริง

Protocol ใช้ AGPL-3.0 เหมือนส่วนอื่น ถ้าวันหนึ่งมีคนต้องการทำของปิดที่คุยกับ Veeloe จริง เช่น plugin ของ IDE ที่ขายเป็นสินค้า เราค่อยเปลี่ยน Protocol เวอร์ชันถัดไปเป็น Apache-2.0 ได้ เพราะมี CLA แต่ถ้าออกเป็น Apache ไปแล้ว เวอร์ชันนั้นจะเป็น Apache ตลอดไป

## Considered Options

- **MIT/Apache**: เปิดกว้างที่สุด แต่คู่แข่งเอาไปแก้แล้วปิด source ได้
- **Protocol ใช้ Apache-2.0 ส่วนที่เหลือใช้ AGPL**: คนทำของปิดที่คุยกับ Veeloe ได้ แต่ยังไม่มีใครขอ และเปลี่ยนกลับเป็น AGPL ไม่ได้ ส่วน AGPL บน Protocol แทบไม่ได้กันคู่แข่ง เพราะใครก็เขียนตามสเปกใหม่ได้
- **source-available (FSL/BSL) และต่อได้แค่ Hub ของเรา**: ปกป้องธุรกิจได้ดีที่สุด แต่ไม่นับเป็น open source และค้านกับเหตุผลเรื่องความไว้ใจที่ทำให้เราเปิด source ตั้งแต่แรก

## Consequences

- คนนอกที่ส่งโค้ดเข้า repo ต้องเซ็น CLA ผ่าน CLA Assistant ตั้งแต่ PR แรก เราจึงยังเปลี่ยน license ได้ทั้งสองทิศ และขาย license แบบ commercial ควบคู่ได้ CLA ยังทำให้เราส่ง Controller ขึ้น App Store ได้ด้วย เพราะเงื่อนไขของ store ขัดกับ AGPL เมื่อมีโค้ดที่คนอื่นถือลิขสิทธิ์ปนอยู่ ต้องตั้ง CLA Assistant ให้เสร็จก่อนเปิดรับ PR จากคนนอก ข้อเสียคือ dev บางคนจะไม่ยอมส่งโค้ดมาเพราะไม่อยากเซ็น CLA เราไม่เลือก DCO เพราะ DCO ไม่ได้ให้สิทธิ์เปลี่ยน license และไม่เลือกการปิดไม่รับโค้ดจากคนนอก เพราะจะเสียแรงช่วยจาก community
- แอป Controller ของเรามีช่อง "Hub แบบกำหนดเอง" ให้ต่อ Hub ที่คนอื่น host ได้ แบบเดียวกับที่แอปของ Tailscale ต่อ Headscale ได้ คนจึงกล้าเริ่มใช้ เพราะรู้ว่าจะย้ายออกเมื่อไหร่ก็ได้ แต่ Hub แบบนั้นจะไม่มี push เพราะ push ผูกอยู่กับ credential ของ Expo project ของเรา และแอปต้องเตือนให้ชัดว่า Hub ของคนอื่นไม่ได้ผ่านการตรวจจากเรา ทีหลังอาจทำตัวส่งต่อ push ให้ Hub ของคนอื่นเป็นบริการแบบจ่ายเงิน
- ใครก็เอา Hub ไป host เป็นบริการแข่งกับเราได้ AGPL บังคับแค่ให้เปิดโค้ดส่วนที่แก้ สิ่งที่ยังเป็นของเราคือ push, แอปบน store และชื่อ Veeloe ซึ่งควรจดเครื่องหมายการค้าไว้ กันไม่ให้ fork เอาชื่อไปขึ้น store
