# Runtime เลือกผู้รับจาก Grant ที่ตัวเองถือ และ Hub ส่งต่อตามรายชื่อในหัวซองโดยไม่รู้ Grant

ADR 0013 ให้ Hub ส่งเนื้อหาของ Task ให้ทุก Controller ใน Workspace ส่วน ADR 0006 ให้ Hub รู้เรื่อง Agent แค่ชื่อ คำอธิบาย Machine และ Character พอมี Member หลายคน Member ที่ไม่มี Grant กับ Agent ตัวหนึ่งเลยก็ยังได้ event ของตัวนั้น และ push ของ Approval ส่งให้เฉพาะคนที่มี Approve ไม่ได้ เพราะ Hub ไม่รู้ว่าใครมีสิทธิ์ Runtime รู้ เพราะ Grant ทุกตัวเป็นคำสั่งที่เซ็นและเก็บไว้ที่ Runtime (ADR 0010) เราจึงให้ Runtime ใส่รายชื่อ Member ที่ควรได้รับไว้ในหัวซอง แล้ว Hub ส่งให้เฉพาะ Controller ของคนในรายชื่อ ซึ่ง Hub อ่านหัวซองได้อยู่แล้ว (ADR 0005) event ของ Task ไปหาคนที่มี Use ขึ้นไป push ของ Approval ไปหาคนที่มี Approve ขึ้นไป โดย Hub แปลงรายชื่อเป็น push token ส่วนการ sync ย้อนหลังด้วย "event หลังเลข N" (ADR 0021) เป็นคำขอที่เซ็น Runtime จึงตรวจ Grant ของคนขอก่อนตอบ วันที่มี E2E ให้ Runtime เข้ารหัสเนื้อหาให้เฉพาะกุญแจของคนในรายชื่อ สิทธิ์ดูเนื้อหาจะถูกบังคับด้วยการเข้ารหัสที่ Runtime ทำ ไม่ได้พึ่งว่า Hub ส่งถูกคน

## Considered Options

- **Hub ถือสำเนา Grant ที่เซ็นแล้วและเลือกผู้รับเอง**: ซ่อนรายชื่อ Agent ที่คนนั้นไม่มีสิทธิ์ได้ และส่งถูกคนแม้ Runtime ออฟไลน์ แต่มีจุดตรวจสิทธิ์สองที่ สำเนาที่ Hub อาจเก่ากว่าของจริง และขัดกับหลักของ ADR 0006 ที่ให้ Hub รู้เรื่อง Agent ให้น้อยที่สุด

## Consequences

- Hub ไม่รู้ Grant จึงแสดงชื่อ คำอธิบาย และ Character ของ Agent ทุกตัวให้ทุกคนใน Workspace เห็น แต่เนื้อหาเห็นได้เฉพาะ Agent ที่ตัวเองมี Grant ชื่อของ Agent ไม่ถือเป็นความลับ
- ก่อนมี E2E Hub ที่โดนเจาะส่งผิดคนได้ ซึ่ง ADR 0005 ยอมรับไว้แล้ว และกำหนดว่า E2E ต้องเสร็จก่อนเปิดให้คนอื่นใช้
- event ของ Task ของ Project ไปหาคนที่มีสิทธิ์ใน Project ระดับ View ขึ้นไป (ADR 0046) ส่วนกฎว่า push เรื่องไหนไปหาใครอยู่ใน ADR 0044
- Protocol ต้องมีช่องรายชื่อผู้รับในหัวซอง ซึ่งเพิ่มได้แบบ additive (ADR 0023) v0.1 มี Member คนเดียว รายชื่อจึงมีแค่ Owner
