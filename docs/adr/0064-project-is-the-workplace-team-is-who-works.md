# Project คือที่ทำงาน ส่วนผู้ทำงานคือ Agent ตัวเดียวหรือ Team

ADR 0045 ให้ Project แทน Team เพราะกลัวว่าถ้ามีทั้งสองอย่าง คนจะงงว่างานนี้ควรตั้งเป็นอะไร แต่การรวมกันทำให้ Project ต้องตอบสองคำถามในที่เดียว คืองานอยู่ที่ไหน และใครทำ ผลคืองานที่ Agent ตัวเดียวทำก็ต้องตั้ง Project ที่มีพนักงานตัวเดียว ชุด Agent ชุดเดิมที่ใช้กับหลายงานต้องตั้งใหม่ทุก Project และหน้าตาของ Project กลายเป็นห้องแชตของ Entry ทั้งที่สิ่งที่คนอยากเห็นคือสถานะของงาน เมื่อแยกสองคำถามนี้ออกจากกัน ความงงที่ ADR 0045 กังวลก็หายไป เพราะ Project กับ Team ตอบคนละคำถาม (เจ้าของตัดสิน 2026-11-02)

Project จึงเป็นที่ทำงาน มี repo หรือไฟล์งาน (ADR 0047), wiki (ADR 0037), สิทธิ์ของคนสี่ระดับ (ADR 0046) และรายชื่อผู้ทำงานที่อนุญาต ผู้ทำงานคือ Agent ตัวเดียวหรือ Team Team คือกลุ่ม Agent ที่มี Entry ตัวเดียวและมีเพดานการส่งงาน Team หนึ่งเข้าได้หลาย Project ทั้ง Team และ Project อยู่บน Machine เดียวกันด้วยเหตุผลเรื่องไฟล์ของ ADR 0026 Team ทำงานได้เฉพาะใน Project เพราะการส่งงานต้องมี repo ร่วมกันให้ทำงาน นอก Project Member คุยกับ Agent ตัวเดียวตามเดิม

Task ของ Project มีผู้ทำงานหนึ่งราย คือ Agent หรือ Team ที่แชตนั้นคุยด้วย ถ้าเลือก Agent ตัวเดียว Agent นั้นเป็นเจ้าของ Task และไม่มี Delegation ถ้าเลือก Team ข้อความไปที่ Entry และ Entry ส่งงานให้พนักงานในทีมตามกฎของ ADR 0045 Task เป็นของ Agent ที่เป็น Entry ตอนเปิด Task แม้ทีมจะเปลี่ยน Entry ทีหลัง Project ของ Task ล็อกตั้งแต่ข้อความแรก เพราะไฟล์ Worktree และสิทธิ์ของ Turn ผูกกับ Project แล้ว Mention พนักงานยังเป็นการบอก Entry ว่าอยากให้ตัวนั้นทำ ไม่ใช่การคุยกับพนักงานตรงๆ

สิทธิ์แยกเป็นสองชั้นเหมือนเดิม การเอาผู้ทำงานเข้า Project ต้องมี Manage ของ Project และ Manage ที่ Agent ตัวนั้น หรือที่ Agent ทุกตัวใน Team ถ้าไม่มีการยินยอมนี้ Project จะกลายเป็นทางลัดไปสั่ง Agent ที่ตัวเองไม่มีสิทธิ์ ซึ่งเป็น confused deputy ที่ ADR 0010 ปิดไว้ เมื่อยินยอมแล้ว คนที่มี Use ของ Project สั่งผู้ทำงานในรายชื่อได้ โดยไม่ต้องมี Use ที่ Agent ตามหลักของ ADR 0046 การเพิ่ม Agent เข้า Team ต้องมี Manage ที่ Agent ตัวนั้น และเท่ากับยินยอมให้รับงานในทุก Project ที่ Team นั้นเข้าอยู่ แอปจึงต้องแสดงรายชื่อ Project เหล่านั้นก่อนเซ็น การตั้ง Entry ต้องมี Manage ที่ Agent ตัวที่จะเป็น Entry ส่วนการตั้งเพดานและการลบ Team ต้องมี Manage ที่ Entry ปัจจุบัน Member ที่มี Manage ที่ Agent อย่างน้อยหนึ่งตัวสร้าง Team ได้ Agent ที่มี Channel เข้า Project หรือ Team ไม่ได้ตาม ADR 0028

Project ใหม่เข้าได้เฉพาะคนสร้าง ซึ่งได้ Manage แล้วค่อยให้สิทธิ์คนอื่น และ Owner มี Manage ของทุก Project เช่นเดียวกับที่มี Manage ที่ทุก Agent (ADR 0031) Approval ยังไปที่คนที่มี Approve ที่ Agent ตัวนั้นเสมอ การเอาผู้ทำงานออกจาก Project ที่มีงานค้าง แอปเตือนก่อน และเมื่อยืนยัน Turn ที่ทำอยู่จบแบบ Stop ส่วน Task เดิมยังเปิดอ่านได้แต่สั่งต่อไม่ได้

การอ่าน Workdir ของกันตาม ADR 0026 แคบลงเหลือพนักงานร่วม Team ระหว่างทำ Task ของ Team นั้น Agent สองตัวที่แค่อยู่ในรายชื่อของ Project เดียวกันอ่าน Workdir ของกันไม่ได้ เพราะไม่ได้ทำงานสายเดียวกัน ทั้งคู่เห็นงานร่วมกันผ่าน repo ของ Project อยู่แล้ว กฎห้ามส่งงานเป็นวงทั้งเครื่องยังอยู่ แต่นับจาก Team ทุกทีมบนเครื่อง และ Runtime ปฏิเสธการตั้ง Entry หรือเพิ่มพนักงานที่ทำให้เกิดวง wiki ยังมีคนเขียนตัวเดียว คนที่มี Manage ของ Project เลือกจาก Agent ที่อยู่ในรายชื่อ หรือจากพนักงานใน Team ที่อยู่ในรายชื่อ และ Ask ตอบโดยเจ้าของ Task หรือพนักงานที่ถูก Mention คนที่มีแค่ Ask เริ่มแชตกับผู้ทำงานในรายชื่อเพื่อถามได้ ถ้าเป็น Team ให้ Entry เป็นคนตอบ

Member แชตกับ Agent หรือ Team เท่านั้น Project ไม่มีหน้าแชตของตัวเอง หน้าของ Project แสดงเรื่องที่รอคุณ งานทั้งหมดพร้อมสถานะและผู้ทำงาน ไฟล์ wiki และรายชื่อผู้ทำงาน แตะงานแล้วเปิดแชตกับ Agent หรือ Team นั้น Inbox มีแถวของ Agent และแถวของ Team ตอนแชตยังไม่มีข้อความ คนเปิดเลือก Project กลางจอ รายการแสดงเฉพาะ Project ที่คนนั้นมี Ask ขึ้นไปและผู้ทำงานนี้อยู่ในรายชื่อ แชตกับ Agent เลือกไม่มี Project ได้ ส่วน Team ต้องเลือก Project เสมอ แชตที่เลือก Project แล้วเห็นได้ตามสิทธิ์ของ Project ไม่ใช้กฎซ่อนจนกว่าคนเริ่มจะเปิดของ ADR 0060 (เจ้าของตัดสิน 2026-11-02) เพราะหน้า Project ต้องบอกสถานะงานได้ครบ ตัวเลือกจึงต้องบอกก่อนส่งข้อความแรกว่าใครจะเห็น และเรื่องที่ไม่อยากให้ Project เห็นให้เลือกไม่มี Project

## Considered Options

- **คง ADR 0045 ที่ Project รวมที่ทำงานกับพนักงานไว้ด้วยกัน**: มีแนวคิดน้อยกว่าหนึ่งอย่าง แต่งานของ Agent ตัวเดียวต้องตั้งเป็นทีมตัวเดียว และใช้ชุด Agent ซ้ำข้ามงานไม่ได้
- **Project ครอบหลาย Team และส่งงานข้ามทีมได้**: ADR 0045 ปฏิเสธทางนี้ เราก็ยังไม่เลือก Team หลายทีมอยู่ใน Project เดียวได้ก็จริง แต่แต่ละ Task มีผู้ทำงานรายเดียว และไม่มีการส่งงานข้ามทีม
- **เลือกผู้ทำงานได้อิสระทุก Task ไม่มีรายชื่อ**: ตั้งค่าน้อยกว่า แต่คนดูแล Agent ไม่ได้ยินยอมให้ Agent รับงานจากคนใน Project ซึ่งเปิด confused deputy
- **สั่งงานใน Project ต้องมี Use ทั้งที่ Project และที่ Agent**: เข้มกว่า แต่ต้องแจกสิทธิ์ซ้ำทุกครั้งที่เพิ่มผู้ทำงาน ซึ่ง ADR 0046 ตั้งใจเลี่ยง และการยินยอมตอนเอาเข้ามาก็ปิดความเสี่ยงเดียวกันแล้ว
- **Team ทำงานนอก Project ได้**: เริ่มงานเร็วกว่า แต่พนักงานไม่มี repo ร่วมกัน และต้องตอบว่าการอ่าน Workdir กับสิทธิ์ของคนใช้กฎของใคร
- **Team ข้าม Machine**: ขัดกับ ADR 0026 ด้วยเหตุผลเรื่องไฟล์เดิม

## Consequences

- ADR 0045 ยังใช้ได้เรื่อง Entry ส่งงานชั้นเดียว เพดาน และการห้ามวง แต่กฎเหล่านี้ย้ายจาก Project มาอยู่ที่ Team
- มีแนวคิดเพิ่มหนึ่งอย่าง แอปต้องสอนว่า Project คือที่ไหน และ Team คือใคร
- Schedule ที่เปิดงานใน Project ต้องระบุผู้ทำงาน ถ้าผู้ทำงานถูกเอาออกจากรายชื่อ รอบต่อไปจะเริ่มไม่ได้
- Team เก็บตัวจริงที่ Runtime แก้ได้ด้วยคำสั่งที่เซ็นเท่านั้น และ Hub ไม่รู้จัก Team เหมือน Project (ADR 0006, 0026)
- การแก้ Team หนึ่งมีผลกับทุก Project ที่ Team นั้นเข้าอยู่
- ADR ทั้งหมดยังไม่มีโค้ด ส่วน `controller-prototype` ยังเก็บ Entry และพนักงานไว้ที่ Project จนกว่าจะแก้ UI ตาม ADR นี้
- Team มาพร้อม Project ใน v0.4 (ADR 0048)
