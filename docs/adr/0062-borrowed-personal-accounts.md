# ยืมบัญชีส่วนตัวในแชตรวม

วันนี้ credential ของ Connector อยู่กับ supervisor ต่อ Agent ต่อเครื่อง (ADR 0039) ไม่มีแนวคิดว่า "บัญชีส่วนตัวของคนคุยคนหนึ่ง" Connector หนึ่งตัวใช้บัญชีเดียว ซึ่ง Member ที่มี Manage เป็นคนผูก ทุกคนที่มี Use ใช้บัญชีนั้นผ่าน Agent ได้ จึงควรใช้บัญชี bot หรือ service account ไม่ใช่บัญชีส่วนตัว

แต่ในแชตรวม (group/channel) บางงานต้องทำในนามคนใดคนหนึ่ง เช่น โพสต์ลงบัญชีของคนนั้น หรืออ่านของส่วนตัวของคนนั้น แบบ Grok ในบริบทกลุ่ม (ดู docs.x.ai shared-bots) คือ shared bot ใช้เฉพาะแอปของเจ้าของ การใช้บัญชีส่วนตัวของคนอื่นต้องถามคนนั้นก่อน (Allow once / Always allow) ADR ฉบับนี้เอาหลักนั้นมาใช้กับ veeloe

ในบริบทกลุ่มหรือ Channel Agent ใช้บัญชีที่ผูกไว้ (binder หรือ owner) เป็นค่าเริ่มต้นเสมอ ตาม ADR 0028 และ ADR 0039 การใช้บัญชีส่วนตัวของสมาชิกคนอื่นต้องขอคนนั้นก่อนทุกครั้ง (Allow once) หรือขอแบบจำไว้ (Always allow) ซึ่งถอนได้ทุกเมื่อ ทุกครั้งที่ใช้ต้องบันทึกว่าใช้บัญชีของใครทำอะไร (audit trail) และ Manager เห็นได้ ว่าบัญชีใครถูกใช้ทำอะไรไปบ้าง ตามหลัก act-on-behalf-of-originator (ADR 0010)

ขอบเขตมีเฉพาะบัญชีที่สมาชิกคนนั้นผูกเองในแอป Controller อย่างชัดแจ้งเท่านั้น ห้ามใช้รหัสผ่านโดยเด็ดขาด OAuth token ให้ supervisor เป็นคนถือเหมือนเดิม (ADR 0039) Agent เห็นแค่รายชื่อ tool และเรียกผ่าน supervisor เหมือนเดิม ไม่ได้จับ token เอง งบประมาณยังนับใต้เพดานของ Agent (ADR 0043) ไม่ได้แยกงบต่อบัญชีที่ยืม

สิทธิ์ที่จำไว้ (Always allow) ตายพร้อมการลบสมาชิกหรือการถอนกุญแจ (ADR 0031) เหมือน Connector ที่หยุดทันทีเมื่อกุญแจที่เซ็นมันถูกถอน ถ้าสมาชิกถูกถอน การยืมบัญชีของคนนั้นหยุดทันที ต้องขอใหม่ทั้งหมด

การเลือกผู้รับและสิทธิ์ยังใช้กฎเดิมตาม ADR 0034 คือ Runtime เลือกผู้รับจาก Grant ใครไม่มีสิทธิ์ก็ยืมบัญชีใครไม่ได้ตั้งแต่แรก

## Considered Options

- **ใช้เฉพาะแอปของเจ้าของ ห้ามยืม (status quo)**: ง่ายสุด ไม่ต้องแก้ supervisor ไม่ต้องมีหน้าผูกบัญชีรายคน ไม่ต้องมี audit trail เพิ่ม แต่ทำงานในนามคนอื่นไม่ได้เลย ใครอยากให้ Agent ทำอะไรในบัญชีตัวเองต้องผูก Connector แยกอีกตัว
- **Allow once เท่านั้น จำไม่ได้**: ปลอดภัยสุด คนถูกยืมเห็นทุกครั้งว่า Agent จะทำอะไรในบัญชีตัวเอง ไม่มีสิทธิ์ค้างที่ลืมถอน แต่รำคาญถ้างานเดิมทำซ้ำบ่อยๆ ทุกครั้งต้องมาตอบอนุญาตใหม่
- **Manager อนุมัติล่วงหน้าให้ยืมได้ทั้งกลุ่ม**: สะดวกสุด ขอครั้งเดียวใช้ได้ยาว ไม่ต้องรบกวนเจ้าของบัญชี แต่เจ้าของบัญชีไม่ได้เป็นคนยอมเอง Manager อนุมัติแทน ซึ่งขัดกับหลักของ Grok ที่ต้องถามเจ้าของบัญชี และเสี่ยง confused deputy เต็มๆ

## Consequences

- confused-deputy risk: คนนอกหลอกให้ Agent ใช้บัญชีของคนอื่นทำอะไรบางอย่าง รับมือด้วยการถามชัดแจ้งก่อนใช้ทุกครั้ง (Allow once) หรือสิทธิ์ที่จำไว้ซึ่งถอนได้ทุกเมื่อ บวกกับเจ้าของบัญชีเห็น audit trail ว่าบัญชีตัวเองถูกใช้ทำอะไรไปบ้าง (Manager เห็นได้ด้วย)
- Connector UX: ต้องมีหน้าผูก OAuth รายคนในแอป Controller สมาชิกแต่ละคนผูกบัญชีตัวเองได้เอง ไม่ใช่แค่ Manage ผูกบัญชีเดียวแบบเดิม (ADR 0039) และการ login ยังผ่านเบราว์เซอร์ของระบบด้วย PKCE เหมือนเดิม supervisor เป็นคนเดียวที่ถือ token
- ห้องส่วนตัว (ADR 0060) ไม่กระทบ การยืมบัญชีมีผลเฉพาะที่ที่หลายคนแชร์บริบทกัน ในห้องส่วนตัวมีแค่คนเดียวกับ Agent อยู่แล้ว ใช้บัญชีของคนนั้นได้เลยไม่ต้องยืมใคร
- ทุกครั้งที่ใช้บันทึกว่าบัญชีของใครทำอะไร (audit trail) Manager เห็นได้ ตามหลัก act-on-behalf-of-originator (ADR 0010)
- สิทธิ์ที่จำไว้ตายพร้อมการลบสมาชิกหรือการถอนกุญแจ (ADR 0031) ถอนแล้วต้องขอใหม่ทั้งหมด ไม่มีสิทธิ์ค้าง
- งบประมาณยังนับใต้เพดานของ Agent (ADR 0043) การยืมบัญชีไม่เพิ่มงบ และ Egress ยังแยกต่อ Agent (ADR 0029) ไม่เปลี่ยน
- คำสั่งยังต้องเซ็นตาม ADR 0006 และการเลือกผู้รับยังใช้ Grant ตาม ADR 0034 ใครไม่มีสิทธิ์ก็ยืมไม่ได้ตั้งแต่แรก
