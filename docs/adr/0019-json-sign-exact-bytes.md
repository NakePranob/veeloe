# ข้อความเป็น JSON และลายเซ็นครอบ byte ตามที่ส่งจริง พร้อมกับค่าในหัวซอง

JSON ชุดเดียวกันเขียนเป็น byte ได้หลายแบบ ถ้าฝั่งรับ parse แล้ว serialize ใหม่ก่อนตรวจ ลายเซ็นจะไม่ตรง ฝั่งส่งจึง serialize เนื้อในเป็น byte แค่ครั้งเดียว แล้วเซ็น byte ชุดนั้น ซองพก byte ชุดเดิมไปตามที่เซ็น ฝั่งรับต้องตรวจลายเซ็นก่อน แล้วค่อย parse และตรวจรูปร่างด้วย Zod Zod เป็น library schema ตัวเดียวของทั้งระบบ เพราะ harness ก็ใช้เขียน schema ของ tool ด้วย (Anthropic SDK มีตัวช่วยสำหรับ Zod อยู่แล้ว)

ส่วนที่เซ็นต้องมีสำเนาของค่าในหัวซอง ได้แก่ ปลายทาง, Task id และ Member ที่เริ่ม Task ต้นทาง พร้อมเลขที่เพิ่มขึ้นเรื่อยๆ ต่อผู้ส่ง Runtime ตรวจว่าค่าในหัวซองตรงกับค่าในส่วนที่เซ็น และตรวจว่าเลขมากกว่าเลขล่าสุดที่เคยเห็นจากกุญแจตัวนั้น Hub ที่โดนเจาะจึงเปลี่ยนทางคำสั่งที่เซ็นถูกต้องไปให้ Agent ตัวอื่นไม่ได้ และส่งคำสั่งเก่าซ้ำไม่ได้ วิธีนี้ไม่ต้องพึ่งนาฬิกาของทุกเครื่องให้ตรงกัน

## Considered Options

- **canonical JSON (RFC 8785)**: ส่ง object ได้ตามปกติ แต่ TypeScript กับ Go ต้องเรียง key และเขียนตัวเลขให้ตรงกันทุกตัวอักษร ซึ่งพลาดง่ายและหาต้นเหตุยาก
- **binary (CBOR หรือ protobuf)**: ข้อความเล็กกว่า และ protobuf สร้าง struct ให้ทั้งสองภาษาได้ แต่เปิดอ่านตอน debug ไม่ได้ และต้องเพิ่ม toolchain
