# Library เป็นคลังความรู้บน Machine ที่มี Agent เขียนได้ตัวเดียว และเปิดดูใน Obsidian ได้

แนวคิด LLM Wiki ของ Karpathy ให้ LLM สร้างและดูแลคลังความรู้เป็นไฟล์ Markdown หลายหน้าที่ลิงก์กัน มี `index.md` เป็นสารบัญที่อ่านก่อน `log.md` ที่ต่อท้ายอย่างเดียว และงาน ingest, query กับ lint ถ้าเก็บไว้ใน Workdir ความรู้ชุดเดียวกันต้องมีสำเนาในทุก Agent ที่ใช้ Agent ทุกตัวที่ถือ wiki เขียนทับ wiki ของตัวเองได้ และ Agent ที่มี Channel ใช้ความรู้ไม่ได้เพราะอ่านได้แค่ Workdir ของตัวเอง (ADR 0028) Library จึงเป็นคลังแยกที่ `<VEELOE_HOME>/libraries/<id>/` Owner เป็นคนสร้าง และกำหนดว่า Agent ตัวไหนอ่านได้ กับตัวไหนเป็นตัวเดียวที่เขียนได้ ตามหลักคนเขียนคนเดียวของ ADR 0011 sandbox เป็นคนบังคับ Agent ที่โดนหลอกจากหน้าเว็บหรือจากแชตจึงเขียนอะไรลงคลังที่ตัวเองอ่านได้อย่างเดียวไม่ได้ ตัวอย่างที่ใช้ได้จริงคือ bot ตอบลูกค้าในกลุ่ม Telegram ที่อ่านคลัง FAQ ได้แต่แก้ไม่ได้

ไฟล์ใน Library เป็น Markdown ที่ลิงก์กันด้วย `[[...]]` และมี YAML frontmatter ซึ่ง Obsidian เปิดเป็น vault แล้วเห็นกราฟได้ทันที โครง wiki และวิธีดูแลอยู่ใน Skill ของ Agent ที่เขียน Library (ADR 0038) ไม่ได้ฝังไว้ใน Runtime เพราะ Karpathy เองก็บอกว่าแนวคิดนี้ควรปรับตามงาน งาน lint ตั้งเป็น Schedule ได้ (ADR 0027) และถ้า Library ใหญ่จน `index.md` ไม่พอ Agent ใช้ `grep` ค้นได้ก่อน แล้วค่อยเพิ่มเครื่องมือค้นอย่าง qmd ผ่าน Connector

## Considered Options

- **wiki อยู่ใน Workdir ของแต่ละ Agent**: ไม่ต้องมีแนวคิดใหม่ แต่ความรู้ซ้ำกันหลายที่ แชร์ไม่ได้ และกันการเขียนทับไม่ได้
- **ให้ Agent อ่านโฟลเดอร์ wiki ใน Workdir ของ Agent อีกตัว**: ไม่ต้องมีที่เก็บใหม่ แต่ความรู้ผูกกับ Agent ตัวนั้น ลบ Agent แล้วความรู้หายไปด้วย และต้องทำสิทธิ์ระดับโฟลเดอร์ย่อย
- **สร้างโครง wiki ไว้ใน Runtime ให้ทุก Agent**: ทุกตัวมีที่เก็บแบบเดียวกัน แต่ Agent ส่วนใหญ่ไม่ได้ทำงานด้านความรู้ และต้องเลือกโครงตายตัวให้

## Consequences

- ให้ Agent ตัวไหนอ่าน Library ได้ เท่ากับให้ทุกคนที่มี Use ที่ Agent นั้นอ่านได้ด้วย รวมถึงคนในแชตของ Channel แอปต้องบอกให้ชัด
- Library อยู่บน Machine เดียว Agent บนเครื่องอื่นใช้ไม่ได้ เพราะไฟล์ไม่วิ่งผ่าน Hub (ADR 0005, 0026) ถ้าต้องใช้ข้ามเครื่อง ให้ Agent ที่เขียน Library push ขึ้น git แล้วอีกเครื่อง clone ไป ซึ่งได้ประวัติการแก้ไว้ตรวจย้อนด้วย
- ถ้าเจ้าของเครื่องแก้หน้าใน Obsidian เอง จะกลายเป็นคนเขียนคนที่สอง และอาจทับกับ Agent ที่กำลังเขียนอยู่ Obsidian ยังสร้าง `.obsidian/` ไว้ในคลัง ซึ่ง Agent ต้องข้ามไป
- `.veeloe` เป็นโฟลเดอร์ซ่อน ควรมีคำสั่งอย่าง `veeloe library path <ชื่อ>` ช่วยหา
- หน้าดู Library พร้อมกราฟในแอปเป็นฟีเจอร์ทีหลัง ใช้ไฟล์และลิงก์ชุดเดียวกัน และต้องตัดสินก่อนว่าใครดู Library ไหนได้
