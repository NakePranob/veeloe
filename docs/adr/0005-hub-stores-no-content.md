# Hub ไม่เก็บเนื้อหา ประวัติ Task อยู่ที่ Runtime และ key ของ Provider เข้ารหัสแยกให้แต่ละ Machine

ข้อความทุกชิ้นแบ่งเป็นสองส่วน คือหัวที่ใช้ส่งต่อ กับเนื้อใน Hub อ่านแค่หัวและไม่บันทึกเนื้อใน ประวัติของ Task เก็บอยู่ที่ Runtime ของ Agent ที่เป็นเจ้าของ Task ช่วงแรกเนื้อในป้องกันด้วย TLS อย่างเดียว ทีหลังค่อยเพิ่ม E2E ได้โดยไม่ต้องแก้ Hub ส่วน key ของ Provider ลูกค้าใส่ในแอปครั้งเดียว แอปจะเข้ารหัส key แบบ sealed box ด้วยกุญแจสาธารณะของแต่ละ Machine ที่ได้มาตอน Pairing Hub จึงส่งต่อให้ได้แต่เปิดอ่านไม่ได้ เราเลือกแบบนี้เพื่อไม่ให้ Hub กลายเป็นที่รวมโค้ดและ key ของลูกค้าทุกคน

## Consequences

- ถ้า Machine ปิดอยู่ จะดูประวัติ Task ของเครื่องนั้นได้แค่ส่วนที่แอป cache ไว้
- ถ้า Machine พังหรือลงระบบใหม่ ประวัติ Task ของเครื่องนั้นจะหายไปด้วย ทางแก้คือให้ Runtime ส่งสำเนาที่เข้ารหัสแล้ว (Hub เปิดอ่านไม่ได้) ไปฝากไว้ที่ Hub ซึ่งทำพร้อมกับ E2E ได้
- Hub ยังเห็น metadata ว่า Agent ไหนคุยกับตัวไหน เมื่อไหร่ และคุยมากแค่ไหน แม้จะมี E2E แล้วก็ตาม
- push แจ้งเตือน Approval วิ่งผ่าน Expo และ Apple/Google จึงบอกแค่ชื่อ Agent กับจำนวนรายการที่รอ ไม่ใส่คำสั่ง ถ้าจะอนุมัติต้องเปิดแอป เพราะการอนุมัติต้องเซ็นด้วยกุญแจของ Controller รอบของ Schedule ที่มีเรื่องจะบอกก็เหมือนกัน push บอกแค่ว่า Agent ตัวไหนมีเรื่องจะบอก ต้องเปิดแอปถึงจะอ่านได้ วันที่มี E2E ให้ push พกข้อความที่เข้ารหัสแล้ว และให้แอปถอดรหัสบนเครื่องก่อนแสดง (บน iOS ใช้ Notification Service Extension) แบบที่ Signal ทำ ถึงตอนนั้นจะเห็นข้อความเต็มบนหน้าจอล็อกได้โดยที่ Apple กับ Google อ่านไม่ได้
- ก่อนจะมี E2E คนที่เข้าถึง Hub ได้ยังเห็นเนื้อในตอนที่ข้อความวิ่งผ่าน ข้อนี้รับได้เฉพาะช่วง v0.1 ที่มีแค่เจ้าของระบบใช้คนเดียว E2E ต้องเสร็จก่อนจะเปิดให้คนอื่นใช้ และต้องรองรับการเข้ารหัสให้ทุก Controller กับทุก Runtime ใน Workspace รวมถึงเครื่องที่เพิ่มเข้ามาทีหลังด้วย Linking
- หัวซองมีรายชื่อ Member ที่ควรได้รับ ซึ่ง Runtime เลือกจาก Grant ที่ตัวเองถือ Hub ส่งต่อตามรายชื่อนี้โดยไม่ต้องรู้ Grant (ADR 0034)
- Hub เก็บคำสั่งถอนกุญแจ ใบรับรองจาก Linking และการเลื่อนขั้น Owner ที่เซ็นแล้วไว้เป็น metadata แล้วส่งให้ Runtime ตอนต่อเข้ามา (ADR 0031) ของพวกนี้ไม่ใช่เนื้อหา Hub จึงยังไม่มีคิวของข้อความ
- credential ของ Connector ส่งแบบ sealed box ด้วยกุญแจของ Machine แบบเดียวกับ key ของ Provider Hub ส่งต่อได้แต่อ่านไม่ได้ และไม่เป็นที่รับ redirect ของ OAuth (ADR 0039)
- Hub ไม่มีคิว ถ้า Machine ปลายทางออฟไลน์ Hub จะตอบกลับ Controller ผู้ส่งทันที แล้วแอปแจ้งผู้ใช้ ส่วน Delegation ไม่ผ่าน Hub แล้วตั้งแต่ Project อยู่บน Machine เดียว (ADR 0026)
