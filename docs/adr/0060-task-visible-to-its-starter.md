# Task ที่เริ่มในแอปเปิดดูได้เฉพาะคนเริ่ม เพื่อให้แอปไม่รก ไม่ใช่เพื่อเก็บความลับ

เดิม Use เปิดดูได้ทุก Task ของ Agent (ADR 0010, 0031) พอมีหลายคนใช้ Agent เดียวกัน แอปจะรกเกินจำเป็น เราคิดถึง Agent เหมือนเพื่อนร่วมงาน (เจ้าของตัดสิน 2026-11-01) คือถามเขาได้ว่าคนอื่นให้ทำอะไรอยู่ แต่ไม่มีหน้าจอให้นั่งอ่านแชตของกันทั้งหมด Task ที่ Member เริ่มคุยกับ Agent ในแอปจึงเปิดดูได้เฉพาะคนเริ่ม จนกว่าคนเริ่มจะเปิดให้คนที่มี Use เห็น ซึ่งย้อนกลับไม่ได้ ค่าเริ่มต้นเป็นแบบนี้เพราะพลาดแล้วแก้ได้ ถ้าลืมเปิดก็กดเปิดทีหลัง แต่ถ้าเริ่มจากเปิดแล้วคนเห็นไปแล้ว ย้อนไม่ได้

เรื่องนี้ไม่ใช่ความลับ และแอปต้องไม่ใช้คำว่าส่วนตัว แต่ใช้คำว่า "แชตของฉัน" เพราะเจ้าของ Machine เข้าถึงข้อมูลบนเครื่องได้ (ADR 0032) คนที่มี Manage แก้คำสั่งของ Agent ได้ และ Workdir กับ Memory ใช้ร่วมกันทุก Task (ADR 0011, 0036) เรื่องที่ต้องการแยกจริงให้ใช้ Agent อีกตัว ซึ่งสร้างให้ทีหลังได้

Agent ค้น Task ของคนอื่นได้ตอนคุยผ่าน Controller เว้นแต่คนที่มี Manage ปิดไว้ แอปต้องแสดงในแชตว่า Agent อาจเล่าเรื่องนี้ให้คนอื่นที่ใช้ Agent ตัวนี้ฟังได้หรือไม่ ระหว่างตอบแชตของ Channel Agent ค้นได้แค่ Task ของแชตนั้น เว้นแต่คนที่มี Manage เปิดไว้ (ADR 0028) ทั้งสองค่าตั้งด้วยคำสั่งที่เซ็น และตรึงตอนเริ่มแต่ละ Task แบบเดียวกับ Memory ตอนคุยเรื่องอ่อนไหวตอนค่าปิดอยู่ การเปิดทีหลังจึงไม่ทำให้เรื่องเก่าถูกค้นเจอ ระบบบังคับที่ tool ค้นหา ไม่ได้ขอให้ LLM ไม่เล่า

Agent ยังทำงานแก้ไฟล์ทีละ Turn นอก Project เหมือนเพื่อนร่วมงานหนึ่งคน (ADR 0011) คนที่ต้องรอเห็นว่า "ไม่ว่าง มีงานของ Nok" แต่ไม่เห็นเนื้อหา และเลือกถามด้วย Ask (ADR 0046) หรือต่อคิวได้ Turn ใน Task ที่ยังไม่เปิดให้เห็น กด Stop ได้เฉพาะคนเริ่มกับคนที่มี Manage (ADR 0017)

Approval ส่งหาคนที่มี Approve เหมือนเดิม (ADR 0044) การ์ดแสดงคำสั่งกับเหตุผลจาก Agent และมีปุ่มดูบทสนทนา เพราะเหตุผลนั้น Agent เป็นคนเขียน ถ้าโดนหลอกอยู่เหตุผลก็หลอกตามได้ ถ้าเปิดดู แอปบันทึกไว้ใน Task ว่าใครเปิด

Task ของ Project ไม่อยู่ในกฎนี้ ยังเห็นได้ตามสิทธิ์ใน Project (ADR 0046) Task ของ Channel และ Schedule ก็ใช้กฎเดิมของตัวเอง (ADR 0027, 0028)

## Considered Options

- **Use เห็นทุก Task เหมือนเดิม**: ไม่ต้องสร้างอะไร แต่แอปรก
- **ห้องส่วนตัวที่คนอื่นถามไม่ได้แบบ Grok**: Grok รัน shared Bot บน cloud และแยกคอมตามคนได้ แต่ Veeloe รันบนเครื่องของ Owner และ Workdir ใช้ร่วมกัน จึงเป็นสัญญาที่รักษาไม่ได้
- **แยก Workdir ต่อ Task แล้วทำงานพร้อมกัน**: ไม่ต้องรอคิว และไฟล์ไม่ปนกัน แต่ Agent เหมือนระบบที่แยกร่างได้มากกว่าเพื่อนร่วมงาน ไฟล์ไม่ต่อเนื่อง และต้องคอยย้ายงาน ถ้าอยากทำงานพร้อมกันให้สร้าง Agent เพิ่ม
- **สั่ง Agent ไม่ให้เล่าเนื้อหาละเอียด**: ดูปลอดภัยกว่า แต่เป็นแค่คำขอที่ LLM อาจไม่ทำตาม (ADR 0046)
- **เลือกทุกครั้งที่เริ่มคุย**: ตั้งใจได้ชัด แต่เพิ่มขั้นตอน และคนจะกดผ่าน
- **คนอนุมัติเห็นแค่คำสั่งและเหตุผล**: หน้าจอเรียบที่สุด แต่ตัดสินใจจากข้อความที่ Agent เขียนเอง

## Consequences

- ทีมไม่เห็นงานของกันโดยอัตโนมัติ ถ้าอยากให้เห็นต้องกดเปิด หรือคุยใน Project
- ทีมรู้ว่าใครกำลังใช้ Agent อยู่ แม้ไม่เห็นเนื้อหา
- Task เก่าที่เริ่มตอนค่าเปิดอยู่ยังถูกค้นเจอหลังปิดค่า ยังไม่มีกลไกซ่อนย้อนหลัง
- `veeloe backup` ยังรวมทุก Task บนเครื่อง (ADR 0051)
- ถ้า Agent จดเรื่องจากแชตลง Memory เรื่องนั้นจะติดไปทุก Task (ADR 0036)
