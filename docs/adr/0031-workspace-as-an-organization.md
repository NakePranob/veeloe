# Workspace ใช้เป็นองค์กรได้: มี Owner หลายคน เชิญจากที่ไกลได้ และถอนกุญแจได้

องค์กรหนึ่งมีหลาย Machine หลาย Agent และหลาย Member ADR 0010 แจกสิทธิ์ต่อ Agent ไว้แล้ว แต่ ADR 0013 ยังมี Owner คนเดียว เชิญคนได้แค่ต่อหน้าด้วย Linking และไม่มีการถอนกุญแจเลย ถ้า Owner ลาออก ทำมือถือหาย หรือกุญแจหลุด ทั้ง Workspace จะเชิญคน แจก Grant หรือ Pair เครื่องใหม่ไม่ได้ และต้องไป Pair Machine ใหม่ทีละเครื่อง

Workspace จึงมี Owner ได้หลายคน Owner เลื่อน Member คนอื่นเป็น Owner ด้วยคำสั่งที่เซ็น และ Runtime เชื่อ Owner คนใหม่เพราะมีลายเซ็นต่อกันมาจากกุญแจของ Owner ที่ Runtime เชื่ออยู่แล้ว ซึ่งเป็นหลักเดียวกับ Linking Owner ปลด Owner คนอื่นได้ แต่ Owner คนสุดท้ายออกจาก Workspace ไม่ได้ ต้องเลื่อนคนอื่นขึ้นมาก่อน v0.1 ยังมี Owner คนเดียว แต่ข้อมูลเก็บ Owner เป็นรายชื่อตั้งแต่แรก เหมือนที่ ADR 0010 ทำกับ Member เฉพาะ Owner ทำ Pairing และสร้าง Agent ได้ เพราะ Pairing เพิ่ม Machine ที่ต้องจ่ายเงิน (ADR 0001) และการสร้าง Agent ก็เกือบเท่ากับเข้าถึงไฟล์ของเครื่องนั้น เพราะตอนที่คุยกับ Agent ตรงๆ Agent อ่านได้ทุกไฟล์ที่ไม่ใช่ไฟล์ลับ (ADR 0008) Owner สร้างเสร็จแล้วแจก Manage ให้ Member ที่ดูแล Agent ตัวนั้นต่อ

Member ใหม่เข้ามาด้วย Invitation Owner สร้างลิงก์ที่ใช้ได้ครั้งเดียวและหมดอายุใน 24 ชั่วโมง แล้วส่งให้ทางไหนก็ได้ แอปของคนที่ถูกเชิญสร้างกุญแจของตัวเองแล้วส่งคำขอเข้า Workspace ทั้งสองเครื่องแสดงรหัสสั้นที่คำนวณจากกุญแจของคนที่ถูกเชิญ เช่น emoji 4 ตัวแบบ safety number ของ Signal ทั้งสองฝั่งเทียบกันทางอื่น เช่นโทรคุยกัน ถ้าตรงกัน Owner จึงเซ็นรับรองกุญแจ ถ้า Hub สลับกุญแจระหว่างทาง (ADR 0006) รหัสจะไม่ตรงกัน แอปที่เปิดจากลิงก์ Invitation เข้า Workspace ที่มีอยู่แล้ว ไม่ได้สร้าง Workspace ใหม่ ส่วน Linking ใช้แค่กับเครื่องใหม่ของ Member คนเดิมเหมือนเดิม

กุญแจของ Controller ถอนได้โดยเจ้าของเองจากเครื่องอื่นของตัวเอง หรือโดย Owner การลบ Member คือการถอนกุญแจทุกเครื่องและ Grant ทุกตัวของคนนั้น คำสั่งถอนต้องเซ็น Hub ตัดสายของกุญแจนั้นทันที และ Runtime เชื่อคำสั่งถอนเพราะลายเซ็น ไม่ใช่เพราะ Hub บอก ของที่เซ็นทิ้งไว้แล้วทำงานเอง คือ Schedule (ADR 0027) กับ Channel (ADR 0028) หยุดทันทีเมื่อกุญแจที่เซ็นมันถูกถอน ถ้ามือถือโดนขโมยแล้วคนร้ายตั้งอะไรไว้ก่อนเจ้าของรู้ตัว ทั้งหมดจะหยุดตามกัน โดยระบบไม่ต้องเดาว่าอันไหนเจ้าของตั้ง แอปบนเครื่องอื่นของเจ้าของแสดงรายการที่หยุดไปให้เลือกเซ็นใหม่ และก่อนลบ Member แอปบอก Owner ว่าคนนั้นมี Schedule และ Channel อะไรบ้าง ให้ Owner เลือกเซ็นใหม่เป็นชื่อตัวเองได้ Turn ที่ทำในนามของ Member ที่ถูกลบโดน Stop งานในคิวถูกทิ้ง และสาย Delegation ขาดที่ทอดถัดไปเพราะ ADR 0010 ตรวจ Use ทุกครั้งที่ส่งต่อ

Use ดูได้ทุก Task ของ Agent ตัวนั้น ไม่ว่าใครเป็นคนเริ่ม เพราะ Agent ใช้ Workdir เดียวกับทุก Task ไฟล์ที่ทำให้คนหนึ่งยังอยู่ให้อีกคนขอดูได้ การซ่อน Task จึงทำให้เข้าใจผิดว่าเป็นความลับ และคนที่ตอบ Approval ก็ต้องเห็นว่าคุยอะไรกันมา Inbox ยังแสดงเฉพาะ Task ที่ตัวเองเริ่มหรือที่รอตัวเองตอบ ถ้าอยากคุยเป็นส่วนตัว ให้ Owner สร้าง Agent อีกตัวให้คนนั้นใช้คนเดียว คนคนหนึ่งเป็น Member ได้หลาย Workspace โดยใช้กุญแจแยกกันในแต่ละที่ และไม่มีตัวตนกลางที่โยงข้าม Workspace ฐานข้อมูลบน Controller (ADR 0021) จึงแยกตาม Workspace ตั้งแต่แรก

## Considered Options

- **Owner คนเดียวกับชุดกู้คืนที่พิมพ์เก็บไว้ แบบ emergency kit ของ 1Password**: กุญแจที่ทำได้ทุกอย่างมีดอกเดียว แต่แก้ได้แค่เรื่องเครื่องหาย แก้เรื่อง Owner ลาออกหรือกุญแจหลุดไม่ได้ เพิ่มให้ Workspace ที่มี Owner หลายคนทีหลังได้
- **เชิญได้แค่ต่อหน้าด้วย Linking**: ปลอดภัยที่สุดและไม่ต้องสร้างอะไรเพิ่ม แต่ใช้ไม่ได้กับทีมที่ทำงานคนละที่
- **ถอนกุญแจเครื่องเดียวแล้วไม่หยุดอะไร หยุดเฉพาะตอนลบ Member**: ทำมือถือหายแล้ว Schedule ยังรันต่อเอง แต่ถ้าโดนขโมย สิ่งที่คนร้ายตั้งไว้จะทำงานในนามของเจ้าของต่อจนกว่าเจ้าของจะไล่หาเจอ
- **Grant ระดับ Machine ให้ Member สร้าง Agent บนเครื่องที่ระบุได้เอง**: หัวหน้าทีมไม่ต้องรอ Owner แต่เป็นสิทธิ์อีกชั้นที่ต้องออกแบบ แสดง และตรวจทุกที่ ทั้งที่ยังไม่มีองค์กรจริงมาใช้ เพิ่มทีหลังได้แบบ additive
- **Use เห็นแค่ Task ที่ตัวเองเริ่ม**: บทสนทนาไม่ถูกคนอื่นเห็น แต่ Runtime ต้องคัดว่าจะส่ง event ให้ Controller ของใคร ขณะที่ไฟล์ใน Workdir ยังเปิดดูได้เหมือนเดิม จึงเป็นความเป็นส่วนตัวแค่ครึ่งเดียว
- **กุญแจเดียวเป็นตัวตนของคนนั้นในทุก Workspace**: Link เครื่องใหม่ครั้งเดียวใช้ได้ทุกที่ แต่เท่ากับสร้างบัญชีกลางขึ้นมา กุญแจหลุดดอกเดียวเสียทุก Workspace และ Hub รู้ว่าคนคนนี้อยู่องค์กรไหนบ้าง

## Consequences

- ยิ่งมี Owner หลายคน ยิ่งมีกุญแจที่ทำได้ทุกอย่างหลายดอก
- ถ้า Owner ทำ Controller หายหมดทุกเครื่อง Owner คนอื่นเชิญกลับเข้ามาด้วย Invitation ได้ ไม่ต้องไป Pair Machine ใหม่ ยกเว้นเป็น Owner คนเดียว ซึ่งยังเป็นแบบ ADR 0013
- ทำมือถือหายแล้ว Schedule กับ Channel ที่เซ็นจากเครื่องนั้นหยุดจนกว่าจะเซ็นใหม่จากเครื่องอื่น
- ยังไม่ได้ตัดสินว่า Machine ที่ปิดอยู่ตอนมีการเลื่อนขั้น Owner, Linking หรือถอนกุญแจ จะได้ลายเซ็นเหล่านั้นทางไหน ในเมื่อ Hub ไม่มีคิว (ADR 0005) และ Hub ที่โดนเจาะอาจกักคำสั่งถอนไว้ไม่ส่ง
- ยังไม่ได้ตัดสินว่า Hub ต้องรู้ Grant หรือไม่ เพื่อส่ง push และเนื้อหาให้เฉพาะคนที่มีสิทธิ์ ก่อนมี E2E Hub ส่งให้ทุก Controller ใน Workspace (ADR 0005, 0013)
- Invitation กับ Owner หลายคนไม่อยู่ใน v0.1 และเพิ่มทีหลังได้แบบ additive (ADR 0023) ส่วนการถอนกุญแจยังไม่ได้ตัดสินว่าต้องอยู่ใน v0.1 หรือไม่ ทั้งที่ v0.1 Link เครื่องที่สองได้แล้ว
